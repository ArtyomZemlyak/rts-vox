# 04 — Детерминизм

Определение, которое мы держим: **одинаковый сид + одинаковый набор модов +
одинаковая последовательность команд → бит-в-бит одинаковое состояние на любом
тике, на любой машине, при любом уровне оптимизации.**

Это нужно для трёх вещей сразу: lockstep-мультиплеера (заложен на будущее),
реплеев, и — практически важнее всего сейчас — для того, чтобы у агента был
машиночитаемый оракул «работает / не работает».

## Правила

Нарушение любого из них — баг, а не стилистика.

**1. Никаких float в симуляции.** Тип `Fx` (i64, Q32.32) из крейта `fx`.
Умножение через i128, деление через сдвиг. Float допустим только в `render`.

Проверяется механически: линт запрещает `f32`/`f64` в `sim-core`, `worldgen`,
`voxel`, `nav`, `modding`.

**2. Своя математика.** `sqrt` — целочисленный алгоритм Ньютона. Синус/косинус —
таблица фиксированного размера с линейной интерполяцией в `Fx`. Никаких
`libm`, никаких интринсиков. Расхождение трансцендентных функций между
компиляторами и CPU — классическая причина десинка.

**3. Стабильный порядок итерации.** `HashMap`/`HashSet` запрещены в путях,
которые итерируются. Разрешено: плотные массивы с индексами (основной способ),
`BTreeMap`/`BTreeSet` там, где нужен упорядоченный поиск. Порядок обхода
юнитов — по индексу в SoA-массиве, а не по чему-либо ещё.

Отдельно про Lua: в Lua порядок `pairs()` не гарантирован между запусками.
Мод-API не предоставляет модам конструкций, где это может проявиться, —
детали в `08-modding.md`.

**4. RNG только явный.** `fx::rng::Rng`, засеянный от сида матча и позиции
в детерминированной последовательности. `rand::thread_rng`, `SystemTime`,
адреса указателей как источник энтропии — запрещены.

**5. Порядок систем фиксирован явно.** Список фаз тика в `03-architecture.md`.
Не расписание фреймворка, не параллелизм по сигнатурам, не порядок регистрации.
Внутри фазы параллелизм допустим только там, где результат не зависит от
порядка завершения задач (например, независимый ремешинг чанков), и это
доказывается тестом, а не рассуждением.

**6. Изменение любого из перечисленного ломает golden-файлы.** Это ожидаемо.
Регенерация golden-файлов — осознанное действие с отдельным коммитом
(`/regen-golden`), никогда не побочный эффект другой правки.

## Что можно не делать детерминированным

Явно и намеренно: рендер, интерполяция, камера, UI, звук, частицы, unsynced-
обломки (ADR-005), unsynced-скрипты модов. Всё это живёт за границей и может
расходиться сколько угодно.

## Тесты

Четыре класса, все headless, все в `cargo test`.

**Golden / replay.** Для набора фиксированных сидов хранится хеш состояния на
контрольных тиках. Дёшево и ловит почти всё.

```
seed=42,  tick=1000  -> hash 0x...
seed=42,  tick=10000 -> hash 0x...
seed=777, tick=1000  -> hash 0x...
```

Плюс записанные реплеи под конкретные сценарии: `dig-through-ridge`,
`collapse-bridge`, `500-units-crossfire`. Реплей = сид + список команд с
номерами тиков; воспроизведение обязано дать тот же хеш.

**Property (`proptest`).** Инварианты, которые обязаны держаться при любом
входе:

- юнит никогда не оказывается внутри непроходимого вокселя;
- сумма ресурсов игрока неотрицательна;
- путь либо найден, либо цель явно помечена недостижимой — третьего нет;
- после разрушения cost field согласован с воксельной сеткой;
- число динамических тел не превышает лимит (ADR-005).

**Симуляционные прогоны.** Два бота, 10k тиков. Проверяется: игра завершается
или доходит до лимита без зависаний; хеши двух независимых прогонов с одним
сидом совпадают; экономика не уходит в вырождение. Это же место, где ловится
провал «тесты зелёные, а играть невозможно» — сюда добавляются геймплейные
метрики (темп, длительность боёв, доля времени в простое), а не только
«не упало».

**Кросс-платформенный прогон.** Хеш `seed=42, tick=10000` считается на Windows
и на Linux в CI и сравнивается. Это единственный тест, который реально
доказывает переносимость детерминизма; всё остальное доказывает лишь
воспроизводимость на одной машине.

## Диагностика десинка

Когда хеши разошлись, нужно знать где, а не только что.

- Хеш считается **по фазам**, не только в конце тика. Расхождение локализуется
  до фазы за один прогон.
- Внутри фазы — хеш по подсистемам (юниты / воксели / навигация / экономика).
- `sim-cli --replay X --verify --trace-from N` печатает пофазные хеши начиная
  с тика N, чтобы можно было сравнить два прогона диффом.

Это стоит написать до того, как понадобится. Отладка десинка без пофазных
хешей — это дни бинарного поиска по коду; с ними — минуты.

## Почему это дороже, чем кажется, и всё равно окупается

Fixed-point математика, запрет на привычные структуры и своя тригонометрия —
это примерно неделя работы и постоянное трение. Взамен: каждая регрессия
ловится одним числом, агент проверяет себя без человека и без GPU, реплеи
работают бесплатно, мультиплеер остаётся возможным.

Модель, на которую опираемся, — Factorio: детерминированный lockstep с
десятками тысяч модов, движковый seeded RNG, требование стабильного порядка
итерации, запрет внешних библиотек в модах. Это работает в проде уже больше
десяти лет.
