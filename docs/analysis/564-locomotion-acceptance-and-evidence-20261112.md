# 564 — Программа приёмки движения, контактов и двуногих

Дата: 12.11.2026. Дополнение к [563](563-cross-system-locomotion-review-20261112.md).
Это не список уже зелёных проверок, а различие между имеющимися доказательствами,
обязательными новыми тестами и критериями готовности реализации.

## 1. Общие требования готовности

Любое изменение принимается одновременно по четырём осям:

1. **Геометрия:** нет запрещённого проникновения, фантомной опоры и пропущенного
   фактического препятствия.
2. **Поведение:** приказ исполняется, нет вечного затора, потери посадки, скольжения
   stance или телепорта.
3. **Детерминизм:** одинаковые состояние и решения после restore, долевого поиска
   и изменения числа воркеров.
4. **Стоимость:** среднее, p50/p95/p99/max тика, логическая работа, память и
   задержка первого ответа, а не только средний FPS или один удобный стенд.

Если оптимизация заявлена как не меняющая результат, прежний `save`/hash должен
совпадать побитово. Если изменена механика, новый контракт и его последствия
должны быть описаны отдельно, а не спрятаны за словом «ускорение».

## 3. Обязательная матрица сценариев

| Сценарий | Что проверять | Текущий статус |
|---|---|---|
| Ровный пол и приказ | Первый намеренный шаг, разгон, прибытие | Частично доказано |
| Плавный уклон | Нормаль корпуса, высота и допустимый профиль | Есть локальные проверки |
| Канава короче span | Проезд без ложного `steep`, общий coarse/motor | Motor исправлен; общий профиль отсутствует |
| Канава шире span | Запрет/объезд, нет ложного моста | Нужна единая матрица |
| Мелкий обломок +1/+2/+5/+8 | Профильная проходимость, отсутствие автоматической стены | Есть выбранные проверки |
| Неполная форма `shape=19` | Пустые ячейки не держат тело | Фантомные столбцы воспроизведены, исправления нет |
| `chunk: Some` 5³ | Настоящие поверхности и запрет | Секция исключена из `Rubble` |
| Кратер и его кромка | Объезд заранее, отказ опасного входа, выход из него | Частично доказано |
| Свежая яма под маршрутом | Dirty только рядом, сохранение конечного приказа | Есть реализация и тесты |
| Встречный корпус | Полный SAT, допустимая касательная, исходный ID | Есть групповые проверки |
| Большой шаг/толчок | Промежуточные позы, отсутствие туннеля | Нет доказательства полного sweep |
| Вход из пересечения | `overlap` нельзя входить; выход уменьшает проникновение | Часть правил есть, общего proof нет |
| `DropDown` | Спуск, падение, скорость приземления, урон | Нет активного общего контракта |
| Крыша + туннель | Две опоры в одной колонке | Активный `nav::vehicle` не покрывает |
| Поворот двуногого | Сторона, досягаемость, отсутствие скрещивания | Есть регрессии |
| Потеря/сминание ноги | Поддержка, наклон, посадка, отсутствие силы у потерянной | Есть регрессии, нужен новый `SupportSample` |
| Ручной полёт | Воздушный sweep, препятствие, отказ работы | Отдельный контур, не наземный motor |
| `fraction==1` рендера | Использование `seg_frames`, нет повторного IK | Предложение, не реализация |
| `0<fraction<1` рендера | Длина звеньев и непрерывность | Требуется отдельный тест |
| Восстановление | Непрерывный прогон и restore дают одинаковые байты | Есть по подсистемам, нужно по новым кэшам |
| 1/2/4/8 workers | Совпадение состояния и порядка принятия | Требуется по каждому изменению |

## 4. Обязательные численные инварианты

### 4.1 Геометрия и допуск

- Пустая ячейка не получает `SupportSurface`.
- `Obstruction` не создаёт положительную опору.
- Проверенная посадка достижима по длине ноги; `Contact.pos.y` не подменяет floor.
- Первый отказ SAT и исходный ID совпадают с полным перебором.
- Большой корпус не теряется из-за центра вне запроса.
- Старые overlap позволяют только уменьшать проникновение, а не увеличивать его.
- `DropDown` не разрешает скрытое прохождение сквозь запрещённую посадку.

### 4.2 Двуногие

- В опоре мировая точка стопы сохраняется; существующий предел Commander —
  не более 0,15 мировой единицы за тик в проверке поворота.
- Ошибка `solved_ankle` относительно посадки не превышает существующие 0,5 мировой
  единицы в регрессии Walker 04.
- Нет пересечения фактических объёмов противоположных ног.
- Toe/heel сохраняют стабильный порядок по ноге и локальной части, а не по высоте
  или положению в мире.
- Swing, потерянная и смятая нога не создают силы, которых нет в профиле.
- Новый приказ не телепортирует поднятую стопу через карту.

### 4.3 Детерминизм и кэш

- `Motion::save` и `BlastRange::snapshot` совпадают при одинаковых входах.
- Старый и новый `floor_proof == None` вызывают идентичный точный путь.
- Поиск целиком и долями даёт одинаковый маршрут и логическую стоимость.
- Кэш не разделяет изменяемые `Foot`, `Contact`, arm targets и повреждения.
- После restore вычисления поверхности и support восстанавливаются из текущего
  мира, а не устаревшего прошлого тика.
- Ни один счётчик наблюдения не влияет на хеш или решение.

## 6. Приёмка по этапам

### Этап 0: геометрия обломков

- `shape19` и `chunk5³` проецируются по фактическим ячейкам.
- Кусок на крыше не входит в общий пол.
- Поворот и удаление секции меняют только её старый/новый диапазон.
- Путь и motor не расходятся: нет ни невидимой секции, ни сплошного AABB-пола.

### Этап 1: общий переход

- `Drive`, `StepUp`, `CrossGap`, `DropDown`, вход и выход overlap различаются.
- Coarse/fine/motor принимают одинаковый профиль и одинаковый результат перехода.
- `span` работает не только в motor.
- Sweep ограничен, возобновляем и возвращает первую допустимую позицию.

### Этап 2: индексы и память

Текущий diff Codex уже содержит `LiveHulls` с ID в ячейках, `relocate` после
принятия позиции, отдельным списком крупных корпусов и полным fallback для
поиска. Полного borrowed `NeighborView` пока нет: `Obstacle` копируется для
локального набора. Массовые крупные тела могут снова вернуть широкий список.
Реализация и ограничения — [565](565-live-hull-neighbors-20261112.md).

Выборка на 512 телах совпала с полным фильтром после relocate и изменения размеров.
На convoy 128 все машины прибыли к тику 356; начало на тике 1, конечные
blocked/reverse/searching — 0, hash `0edf3f06e5717e3d` совпал при 1/4 workers.
Motion mean/p99 — 276/649 мкс при workers 1 и 250/506 мкс при 4/4. Это не A/B
против прежнего gather, не полный бой и не FPS.

- Live-index совпадает с полным сканом по всем кандидатам и исходным ID.
- Relocate после каждого принятого шага, никаких устаревших разрешений.
- Страничный front повторяет dense на пустом, локальном и полном фронте.
- Все буферы ограничены, порядок стабилен, нет полного скана по ID после сетки.

### Этап 3: двуногие и кэши

- `normal == UP` не меняет `Contact`; сложная нормаль идёт полным путём.
- `floor_proof` охватывает весь след стопы и всех проб.
- Общий terrain scratch не меняет ответы, но уменьшает страницы и аллокации.
- `SupportSample` не вызывает новых колебаний и совпадает после restore.
- Рендерный кэш не меняет попадания и авторитетную симуляцию.

### Этап 4: traversal и масштаб

- `StepUp` и `CrossGap` исполняются коротким действием с повторной проверкой посадки.
- `ClimbLedge` разрешён только подходящему профилю, а не любому шагоходу.
- `DropDown` отличает управляемый спуск от падения и описывает урон.
- 128/1000/5000 материальных машин, постоянные правки, полный бой и restore
  проходят заданные бюджеты либо явно фиксируют невыполнение.

## 7. Команды проверки

Все Cargo-команды через `scripts/cargo-local.ps1`, offline там, где используются
временные пакеты. Примеры, а не утверждение об их прохождении:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/cargo-local.ps1 test --release -p harness --test architecture --offline
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/cargo-local.ps1 test --release -p sim-core --lib --offline walker_walks_with_long_slow_steps_and_keeps_its_stance_contacts
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/cargo-local.ps1 test --release -p sim-core --lib --offline commander_pivot_keeps_planted_feet_from_sliding_abruptly
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/cargo-local.ps1 test --release -p sim-core --lib --offline commander_can_stop_and_restart_without_foot_teleportation
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/cargo-local.ps1 run --release -p sim-core --bin bench_mobility --offline -- --case yard --ticks 180
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/cargo-local.ps1 run --release -p sim-core --bin bench_crowd --offline -- --case convoy --count 128 --ticks 600 --workers 4 --physics-workers 4 --detail
```

После новых геометрии и переходов нужны специализированные тесты, а не только
увеличение числа общих прогонов. Полный workspace, долгий бой и масштабная
приёмка не должны подменяться выбранными быстрыми сценами.

## 8. Итоговый критерий

Система готова не тогда, когда «танк едет», а когда одна и та же геометрия даёт
совпадающий ответ у пути, motor, подвески и стоп, с доказанным откликом,
отсутствием фантомной опоры и измеренной ценой динамического мира.

Оптимизация принимается после побитового или явно оговорённого поведенческого
эквивалента, а не после красивого ускорения одного теста.
