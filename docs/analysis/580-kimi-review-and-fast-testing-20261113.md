## Что применено

### Ускорение тестирования

1. `Cargo.toml`: отдельный `sim-test`, opt-level=1, incremental, 256 codegen units,
   LTO="off", overflow-checks=true. Release не меняется. Первый опыт opt=2/16
   компилировался 312 с с нуля и 228 с после изменения SIM; поэтому для короткого
   цикла выбран более дешёвый уровень и мелкие единицы codegen. Итоговые замеры
   фиксируются отдельно, а не приписываются первому варианту.
2. `scripts/test-fast.py`/`.ps1`: один build на target, фактический список тестов,
   точные имена, объединение фильтров, reject нулевой выборки/ignored-only, реальные
   counts/exit code/timeout, JSON и отдельные времена. Нет GUI/GPU. CPU ограничен,
   процессы скрыты, исполнение последовательное.
3. `scripts/motion-lab.py`: настоящий bench_gait без ожидания кадров, restore/hash,
   staged snapshots, manifest с SHA и provenance; успешный код выхода без полного
   числа моделей/тиков не считается успехом.
4. `scripts/gait_report.py`: повторный анализ уже записанного CSV, HTML с ползунком,
   SVG ключевых поз, метрики и A/B. Никакой второй симуляции. Формальные контакты
   и пределы CSV подписаны явно; архивный binary/CSV не выдаётся за текущую версию.
5. [Инструкция](../testing-fast.md) и README описывают реальную работающую команду,
   различие быстрой приёмки, release-профиля и конечного 4К-замера.

Уменьшение числа тиков или размера куба не понадобилось. Headless уже существовал;
проблемой был цикл проверок/сборок и отсутствие удобного разбора его артефактов.

Дополнительная находка при проверке: demo тянул render/Bevy/wgpu как обязательную
зависимость только ради bench_cull_world. Поиск всех импортов подтвердил, что
библиотека и обычные сцены рендер не используют. Зависимость сделана optional,
единственный графический benchmark имеет required-features=render-tools.
Это убирает графическую сборку из обычного пути demo/sim-cli; самостоятельный
render и игра сохраняют зависимости. Opt-in команда описана в инструкции.

### Исправления по найденным проблемам

- `demo::range_match::field` теперь исключает целиком не помещающиеся mounds,
  как другие ограниченные объекты. Не меняем форму холма обрезанием его коробки.
  Есть регрессия сохранения внутренних холмов/валидации нескольких размеров.
- Полные ADR-859…874 добавлены в 10-decisions-full.md: реестр больше не должен
  обещать отсутствующее обоснование.
- `battle_ai_tick` исполняет поданный план на живых обезоруженных акторов,
  сохраняя нейтральный fallback без самовольной атаки рабочих. В AiFrame попадает
  тот же набор fallback; поиск принятого решения использует упорядоченные ID.
- Четыре экономических отказа разделены по причинам. Две dock-проверки теперь
  изолируют логистику от вооружённого командира в реальной дальности 1200;
  отдельная armed-threat регрессия сохраняется. Partial refund требует настоящую
  неполную оплату вместо старой магической суммы 350000. Bootstrap проверяет
  накопление до полной цены и действительную печать после точного resupply,
  не требует построить дорогой завод за старые 7,75 с без нужной массы.
  Производственные цены и защитная политика ради зелёных тестов не ослаблялись.

## Что не переносится автоматически

- Полный rigid-body/QP/MPC или независимый глобальный planner каждой стопы.
- Нейросеть, огромный GOAP/MCTS и новый игровой движок как лечение потерянных
  приказов или неверного пола. Текущий Policy уже подходит для будущих внешних опытов.
- D* Lite/flow fields до исправления геометрии и замера повторного использования
  групповых целей. ORCA не заменяет ограничения гусениц/шагоходов.
- Авторитетный LOD по FPS/камере, удаление физики из теста или ускоренная
  имитация отдельной экономикой. Это поменяло бы проверяемое поведение.
- Большой Rerun/glTF pipeline до простого CLI/CSV/JSON/SVG. Blender полезен для
  редкой геометрической/студийной приёмки, но не должен считать другую походку.
- Старые таблицы экономики/каденции и исторические FPS без исходного manifest.

## Дальнейшие реальные приоритеты

1. Один oracle по занятым ячейкам корня/подошвы и источнику пола. Воспроизводимые
   маленькие сценарии удаления опоры, disabled и компактного/связного обломка.
2. SupportValidity и разделение геометрического контакта/нагрузки. Координатор
   переносов с явным результатом невыполнимого окна, затем bounded FootPlan.
3. Общий контракт перехода для motor/fine/coarse: span, направленный спуск,
   recovery, уровни. Не повышать step, чтобы скрыть разные ответы.
4. ИИ: результаты действий, задачи/прогресс/отмена, безопасное финансирование
   дохода/обороны, компактная оценка силы. Сначала реальные сценарии, затем
   устранение N² и кеширование дорожного графа с oracle решений.
5. Реальные 128/1000/5000 материальных юнитов, динамический мир и итоговый 4К.
   Эти тяжёлые проверки — отдельная приёмка масштаба, не ежедневный inner loop.

Усиленная регрессия Move сравнивает восстановленный экземпляр при 1/2 workers.
Искусственно изменённый status.weapon при restore выводится из неповреждённого
тела, поэтому временная тестовая блокировка повторяется на обеих копиях.
Это не объявлялось потерей snapshot или ослаблением gameplay-контракта.

Три headless-опыта прошли: 4+4+6 моделей по 300 тиков, со сравнением hash после
restore каждого последующего тика. Первые времена без сборки: flat 11,600 с,
terrain 14,774 с, tracks 12,697 с. Подготовка тёплого target — 0,45–0,47 с;
первая сборка выбранного sim-test — 199,52 с. Это CPU-маска 5, BelowNormal,
не production benchmark. Опыт opt=1 исполняет тяжёлый AI-набор медленнее opt=2
(131 против 102 с в этих прогонах), поэтому не обещаем универсальный выигрыш
runtime: быстрый профиль выбран для всего цикла сборка+регрессия. При длинном
профилировании по-прежнему используется release.

Анализ уже записанного CSV занимает около 0,03 с. Проверен каждый из 1200
кадров четырёх моделей в браузерной логике с подставленным canvas, SVG разбирается
XML-парсером. Это проверка построения схемы, не native-визуальная приёмка.
Совпали CSV, все 32 staged snapshot и четыре итоговых hash плоского опыта
быстрого профиля с явным архивным release bench_gait (до расширения CSV новым
has_feet). Расширение CSV и stdout metadata не меняет SIM; время/масштаб свежий
binary теперь экспортирует сам, а архив без такого заголовка помечается unknown.

Cargo tree подтверждает отсутствие render/Bevy/wgpu в обычном demo.
Отдельный opt-in `cargo check -p demo --features render-tools --bin bench_cull_world`
прошёл за 4,38 с. Графический инструмент не исчез из проекта.

Финальный `cargo check --workspace --tests --offline` прошёл за 9,90 с.
Настоящий запуск с ошибочным фильтром завершился кодом 1 и записал ошибку
нулевой выборки; последующий --no-build с актуальным stamp выполнил выбранный
тест за 0,40 с вместе с проверкой fingerprint/загрузкой. После добавления stdout
clock/scale и has_feet повторены flat/tracks: manifest/SVG валидны, все сохранённые
состояния flat совпали с прежней трассой. Гусеницам выставляется
contact_metrics_available=false вместо выдуманных координат ног.

Полный workspace test, новый игровой FPS и массовый бой в этой работе не
заявляются. Изменения проверены в исходниках/отдельных диагностических binary;
игровой release blast.exe по ярлыку остаётся сборкой 579. Для доставки изменения
ИИ в эту сборку нужен обычный финальный release build, не каждый тестовый цикл.

## Переносимость и независимая проверка runner

[584](584-locomotion-evidence-and-next-steps-20261113.md) выявил две проблемы первого
запуска на Windows: отсутствие `pwsh` и запрет `cargo-local.ps1` системной политикой.
Теперь `cargo_local_command()` выбирает доступный `pwsh`/`powershell` и передаёт
`-NoProfile -ExecutionPolicy Bypass` только дочернему процессу, не меняя политику
системы. Проверка добавлена: runner 7/7, analyzer 4/4, `testing-fast.md` обновлён.

После исправления movement дал 39 sim-core + 5 nav, вся nav-библиотека — 144/144,
smoke — 33/33, demo scenes — 7/7. `motion-lab --scenario terrain` завершил replay и
построил manifest/HTML/SVG. `--no-build` после завершения сборки прошёл: 1 тест за
5,651 с, build_seconds=0. Проверка во время параллельной сборки корректно отклонила
изменившийся binary hash; принудительно принимать такой кэш нельзя.

HTML открыт в браузере: выбор Spider и tick 299 меняет DOM и метрики. Скриншот canvas
дважды не удалось получить, поэтому это не объявляется полной визуальной приёмкой.
Подробности новых ограничений опоры и Disabled — в 584.

## Новый контроль одиночной модели и свежих snapshots

Добавлены `--kind` и `test_motion_lab.py`: фильтрация юнита, 300 тиков и восемь staged
snapshots проверяются вместе. Неизвестный тип отклоняется до симуляции. Уникальный
`runs/<uuid>` исключает заимствование файлов прежнего прогона; `manifest.run_directory`
сохраняет связь с ними. Три проверки прошли: полный сценарий, неполные snapshots и
недопустимый тип. Вывод fixture изолирован во временной папке, а не перезаписывает
настоящий отчёт. Подробности — [584](584-locomotion-evidence-and-next-steps-20261113.md).
