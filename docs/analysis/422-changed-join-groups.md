# 422 — Слияние только изменившихся куч обломков

1 ноября 2026, ADR-821. Артефакты: `out/optimization-422/`.

## Причина

Полный `debris_merge_groups` повторно проверял все пригодные для слияния
фрагменты. Прежний `join_memo` пропускал работу только при равенстве всей
истории; движение малой доли кусков делало его бесполезным для остальных куч.

Стабильный `FragmentId` позволяет проверить входы каждой кучи независимо.
Если предыдущий полный проход не нашёл переносов, а ID, ключи и геометрия группы
совпали, повторный поиск переносов не нужен. Изменение индекса после compaction
само по себе не инвалидирует группу.

## Реализация

`Memo::changed` возвращает `None`, если предыдущий результат нельзя использовать,
и точный `BTreeSet<Key>` изменившихся ключей иначе. Предыдущие ID индексируются
через query-only `FxLookup`; массив `matched` в исходном порядке выявляет удалённые
фрагменты. Хеш-таблица не итерируется.

В merge попадают все текущие записи изменившихся ключей, включая старых соседей
изменившегося фрагмента. Неизменные кучи пропускаются. Любой фактический перенос
сохраняет `valid=false` и вызывает полный merge следующего тика. Новый, удалённый,
перемещённый, перекрашенный или изменивший форму фрагмент включает соответствующую
работу. Порядок доноров, выбор голов, арифметика `Geometry::join`, Ledger и формат
снимков прежние.

Это не кэш приближённого ответа и не изменение физики. Стоимость построения
индекса изменений учитывается отдельно в `debris_merge_keys`.

## Проверка холодным оракулом

Существующий тест `resting_join_memo_matches_cold_recomputation_after_geometry_and_support_changes`
прошёл. На16 тиках тёплый changed-keys и холодный полный пересчёт совпали по
сериализации и хешу после изменения краски, позиции, нового контакта и потери
опоры. Нужные слияние и пробуждение не были скрыты.
