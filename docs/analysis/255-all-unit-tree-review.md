# 255 — повторная проверка разрушения деревьев всеми юнитами

11.10.2026. Исходный `main`/`origin/main` — `0b6dc66`, fetch не принёс
новых коммитов, рабочее дерево перед проверкой чистое. Запрос: проверить
деревья у всех юнитов, особенно в бою с ИИ. Эта проверка дополняет
[254](254-main-felling-and-coarse-review.md), а не заменяет её замеры FPS.

Следующий runtime-шаг — [256](256-felling-contact-frontier.md): компактное
хранение собственных семян контакта без изменения правил валки. Проверки
всех типов из этого отчёта входят в регрессионный набор оптимизации.

## Что делает общий движок

| Тип | Контакт при движении | Штатное оружие |
| --- | --- | --- |
| Tank | Пятно гусеничного корпуса | Бронебойное по умолчанию; тип боеприпаса настраивается |
| Artillery | Пятно гусеничного корпуса | Навесной фугас |
| ArtilleryT2 | Пятно гусеничного корпуса | Навесная картечь |
| Strider | Занятые воксели настоящих стоп | Пулемёты |
| Spider | Занятые воксели настоящих стоп | Осадный лазер |
| TurretT1 | Самостоятельно не движется | Кинетическое орудие |
| TurretT2 | Самостоятельно не движется | Энергетическое орудие |
| ArtilleryTurretT2 | Самостоятельно не движется | Навесная картечь |
| Base | Закреплена; самостоятельно не движется | Нет |

Все подвижные типы передают `motion.cut` в одну `Matter::felling_phase`.
Сценарий задаёт расстановку и контроллер; отдельной «валки для ИИ» нет.
Податливые материалы берутся из `range-navigation.ron`: листва 4 и
древесина 5. Они не становятся опорой подвески или стопы.

Для шагающих дерево между ногами может остаться целым: пустой прямоугольник
под корпусом контактом не является. Это отличается от гусеничного пятна.
Потерянные ноги и удалённые воксели стопы не создают срезов. Оставшиеся
стопы продолжают работать; курс и перенесённая нога участвуют в геометрии.

После принятого среза связанная крона в радиусе 14 и не ниже среза уходит
через прежнюю очередь валки. Верх высокого дерева за этим радиусом
обслуживает общий структурный обвал. Целое дерево не получает анимацию
опрокидывания: локальная валка даёт физические куски 2×2×2, а обвал может
оторвать оставшуюся связную часть. Это описание текущего поведения,
не утверждение о завершённой визуальной приёмке.

Оружие работает обычными материальными попаданиями. Лазер воспламеняет
древесину и листву; он не обязан моментально превращать их в пустоту или
плавить как металл. База без оружия сама деревья не обстреливает.

## Новое функциональное покрытие

`crates/sim-core/src/range_unit_felling_tests.rs` подключён только в
`cfg(test)` внутри общего battle-модуля:

- Пять подвижных типов × две стороны × доступный/закрытый пул = 20 случаев.
  Растения имеют отдельный ствол и крону. Проверяется реальное снятие
  обоих материалов, а не только наличие `motion.cut`.
- Вражеский приказ приходит через `submit_enemy_ai_plan` и обычный
  scheduled executor; союзный — через `battle_order`. Все прочие машины
  стоят, оружие заблокировано сроком перезарядки, стрельба запрещена
  дополнительным assertion.
- Шесть слотов и navigation workers=4 включают отложенную общую фазу стоп.
  После контакта юнит покидает дерево; сохранение восстанавливается с
  navigation/physics workers=1. Дальнейшие hashes сравниваются потиково.
- Закрытый пул (`max_flying=0` только в fixture) не принимает материал;
  контакты должны сохраниться. После восстановления исходной доступной
  ёмкости они исполняются без повторного прохода машины. Это проверка
  retry, не доказательство прогресса при непрерывной перегрузке.
- Оба шагающих срезают высокий ствол; крона выше радиуса валки должна
  попасть в структурный обвал. Сохранение/восстановление проверяется и
  на этом пути.
- Все четыре стационарных типа отклоняют приказ движения, сохраняют
  горизонтальную позицию и не уничтожают далёкие растения.
- Перебор `RangeUnitKind::ALL` проверяет попадание штатного оружия в
  древесину без движения и наезда; для базы проверяется отсутствие оружия.

Существующий тест стоп в `range_motion.rs` расширен с одного Spider до
Strider/Spider при курсах 0/730. Проверяются пустота между ногами,
отсутствие опоры на кроне, порядок ограниченного префикса 7/0, потеря
одной/всех ног и полное удаление вокселей стоп.

Первые fixture выявили неверные предположения теста: приказ `Move`
разрешает попутный огонь, расширенная крона касается машины раньше
ствола, а центральный промежуток между ногами надо проверять в
координатах корпуса с учётом разных размеров ног Strider/Spider.
Это исправлено запретом перезарядки, накоплением касаний до первого
ствола и проверкой промежутка в локальных координатах. `Hold` сам по
себе запрещает огонь; причиной загрязнения была движущаяся машина.
Была также исправлена область подключения нового тестового модуля
для доступа к приватному состоянию battle. Ошибки fixture не выдаются
за регрессии игрового runtime.

## Ограничения, которые остаются

1. Переполненный пул обломков всё ещё откладывает валку. ADR-688 сохраняет
   **подготовленные** контакты после ухода юнита, но сам не освобождает пул.
   Тест с последующим освобождением ёмкости не закрывает EP-06.
2. Подготовка среза ограничена префиксом claim-квоты. При `left == 0`
   `cut_limit == 0`; неподготовленная часть контакта не попадает в фронт.
   Это общий путь для всех типов, а не отдельный дефект танка или ИИ.
3. Фронт валки останавливается на первом отказе admission. Компактность,
   справедливость, полный capture контакта и устойчивый прогресс под
   непрерывным огнём остаются открытыми в EP-06/WBPERF-026.
4. Ранее потерянные касания из уже запущенной старой симуляции не
   восстанавливаются задним числом. Новый проход может создать новый контакт.

Ни пределы, ни радиус, ни частота симуляции, ни правила материи не изменены.
Новых сценарных исключений, runtime-полей, сохранений, стоков и зависимости
нет. Новые проверки сами по себе не ускоряют насыщенный бой. Замеры 254
остаются последней квалификацией производительности; новая оконная,
Linux, 30-минутная и 5000-unit приёмка здесь не заявляется.
