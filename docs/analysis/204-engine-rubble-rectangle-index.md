# Точные запросы навигации по карте обломков

Дата: 07.10.2026. После [пакета 203](203-engine-ground-continuations.md) движение занимает около 5,2 мс среднего headless tick, карта обломков — 1,4 мс. `nav::vehicle::Rubble::touches/upper_in` проверяют наличие и максимальную высоту обломков в прямоугольнике. Прежняя реализация отбирает X strip и перебирает строки X, включая далёкие столбцы по Z. Это остаток общей навигации, а не политика конкретной армии. Область [плана](200-engine-performance-plan.md): производные пространственные индексы EP-07 и стоимость terrain proofs EP-08.

## Канонические столбцы и производный индекс

Каноническое представление остаётся отсортированным массивом `([x,z], top)`. Point lookup, iteration, equality и prints используют его. Новый массив узлов хранит непрерывные ranges этого массива, точные AABB и maximum top. Построение линейно, листья содержат не более 32 столбцов; карты до 512 столбцов сохраняют простой поиск без индекса. Эти размеры выбирают служебное разбиение и не являются игровыми квотами.

Узел вне query box исключается. Полностью содержащийся в нём узел даёт точный maximum; частично пересекающийся спускается к детям, а пограничный лист проверяет реальные столбцы. В maximum query узел с top не выше найденного также не меняет ответ. Membership отдельно проверяет наличие: столбец с top=0 присутствует. Ни консервативная высота дальнего heap, ни его bbox не подменяют точный ответ.

`from_sorted` строит индекс один раз после существующего gather. Insert/replace/remove немедленно перестраивают его; collection сохраняет прежнее правило «последнее входное значение побеждает» и строит индекс после заполнения. Clone копирует согласованный индекс. Equality сравнивает только канонические столбцы. Индекс не входит в authoritative state, save или hash; restore создаёт его из актуальной карты тем же общим refresh path.

Память и build — линейны по числу столбцов, глубина — логарифмическая. Стоимость произвольного rectangle зависит от посещённых узлов и пограничных листьев; независимость от размера любого плотного локального контакта не обещается. Ручной insert/remove теперь включает полный rebuild; обычный игровой путь использует пакетный `from_sorted`. Между ticks нет переиспользования geometry или старых высот. Изменённый грунт и опоры видны по прежнему расписанию.

## Проверки точности и остаточной работы

Новый oracle сравнивает presence/maximum с полным перебором до и после замены maximum, удаления, клонирования, обратного collection с повторными ключами и переходов через порог маленькой карты. Проверены нулевая высота, отрицательные координаты, границы i32 и пустой прямоугольник. Существующие пробы pose, goal refusal, живых edits и соседей сохраняются.

Отдельная проба на 4096/65 536/262 144 столбцах требует реальной локальной высоты 7 при далёких heaps высотой 99 в той же X strip. Query читает не более 64 реальных столбцов во всех трёх размерах; он не вправе принять дальнюю высоту или проходить всю спящую историю. Наблюдатель leaf reads в обычном query пустой и не является физическим счётчиком.

## Измерение запросов и построения

`bench_rubble_queries` выполняет 2048 точных queries на раунд, 4 warm и 20 measured rounds; build измеряется отдельно, включая индекс, после копирования входного массива. Before executable создан до изменения общего kernel. Clocks/black_box находятся только в bench.

| Столбцы | Прежние queries, мс | Новые queries, мс | Новый build, мс | Build + queries дешевле |
|---:|---:|---:|---:|---:|
| 8192 | 0,416 | 0,146 | 0,016 | 60,9% |
| 65 536 | 0,699 | 0,213 | 0,115 | 53,1% |
| 262 144 | 1,182 | 0,223 | 0,356 | 50,9% |

Checksums совпали во всех четырёх размерах, включая маленькую карту без индекса. На больших картах query work дешевле на 64,9–81,1%; это выигрыш этого пакета запросов, а не обещанный FPS. Micro timing не включает копирование входа и освобождение карты. Полный battle tick включает создание/замену/освобождение индекса каждый tick; его цена проверяется отдельно.
