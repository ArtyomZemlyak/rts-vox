# 320 — Точный пакетный захват сопротивления взрывов

Дата:16.10.2026. Before — main `ece58e0`, после ground-read
[319](319-coarse-ground-column-reads.md). Задача — capture-порция
[OPT316-02b](316-optimization-delivery-plan.md), решение ADR-746.

## Причина и изменение

В319 ground read ускорен, а худший тик World2400 переместился на2078:
149,763 мс всего,109,200 мс capture сопротивления. Его ground loop всё
ещё вычислял материал по одному занятому вокселю через material_cached.
Курсор ускорял поиск чанка, но нетронутый грунт повторял дорогую подготовку
высоты/дорог/растительности на каждой высоте одной X/Z колонки.

Новый путь использует существующий точный `World.column` и возможность
`Generator::batches_columns`. Edge1–4 и обычные scalar генераторы сохраняют
прежнее чтение occupancy rows. Для edge5–16 batch-генератора каждый X/Z
готовится один раз на колонку. Точный column ceiling отсекает пустой верх;
внутренний AIR не участвует в max, как раньше. Буфер16 материалов на worker
стековый, без domain cache или нового состояния SIM.

Для каждого занятого вокселя вычисляется прежний `material_work(mat,c)`
минус его собственный dent через saturating_sub. Только затем берётся
max. Integer max ассоциативен и не зависит от порядка чтения, поэтому
новый обход колонками возвращает прежнее поле. Повреждения не усредняются;
тонкие стены и неоднородные материалы не теряются.

Первая clipped точка отдельно проверяет насыщение максимума материалов:
если он уже достигнут, генератор колонок вообще не нужен. Дальнейшее
чтение заканчивается на том же доказанном максимуме. Это сохраняет быстрый
путь сплошной прочной преграды. Сопротивление корпусов вычисляется отдельно
прежним кодом с frozen poses, live armour/сегментами, собственными dents
и unit maximum. Максимум грунта не подменяет максимум корпуса.

Граница logical slice, captured prefix, сферическая область, bedrock,
контактные квоты, энергия, apply и момент готовности волны прежние.
Сценарии и параметры оружия не меняются. Уменьшение физического масштаба
не используется для оптимизации. Observer families и snapshot/hash прежние.

| before-a |14,264|63,689|144,829|0,530|103,737|

Пик capture сократился примерно в4,1 раза, его средняя доля в шаге —
примерно на45%. Среднее всего шага улучшилось лишь примерно на1,6%:
обычные движение, завалы и обломки этим патчем не ускоряются. P99 целого
шага снизился примерно на20%; общий max — со145–147 до105–107 мс.

Во всех четырёх runs совпали **все нетайминговые CSV-поля на каждом тике**
и финальный hash `b2e979637e44fb57`. Момент разрушения, нагрузка, очереди
валки/обрушения и обломки сохранены.

Новый худший тик after-a —2227:105,240 мс, из них18,897 capture,
33,603 frontier/read и23,931 применения волны. Это составной пик, а не

ordered apply и возможность точного перекрытия независимой readonly
подготовки разных волн; это отдельный эксперимент с прежними квотами,
снимком и порядком commit, не изменение реализованного здесь алгоритма.

## Проверки

Serial oracle сохраняет прежний reader. Проверка захвата порциями расширена
на coarse edges5/9/16 и выполняется на1/2/4/8 workers, включая нулевую
квоту, границу parallel dispatch, живые изменения земли/броневых dents,
движение/поворот башни после заморозки позы и потерю сегмента. После каждой
порции сравниваются сериализованное состояние, completion и точное
списание логической квоты.

Независимый full-voxel oracle на границах мира расширен до edge1/2/3/4/
5/8/9/12/16. Он проверяет каждую resistance cell, неоднородные материалы,
AIR, dents, частичные клетки и bedrock. Прежние проверки thin armour,
frozen poses, save/load, энергии и итогового кратера остаются в наборе.

Ignored probe `measure_coarse_column_capture` сравнивает старый и новый
parallel ground reader в одном release binary, на одном постоянном пуле4.
Генератор — настоящий RangeTerrain; мир640×192×640, T3 в[320,24,320],
две ground dents, без юнитов. Это stand подготовки, не весь бой/взрыв.
Constructor и serialization вне таймера; один прогрев и7 замеров на
вариант/квоту. После каждого замера saved bytes сравниваются с эталоном.
Median7 и max7 не выдаются за оценку редкого p99.

Адресные проверки:2 capture tests и1 independent edge oracle прошли;
ignored probe запущен отдельно и прошёл. Результат его первой серии:
