# Зависшая рамка выбора: GPU-регрессия — 16.10.2026

База main:77006b1. Пользователь повторно сообщил о прямоугольнике,
остающемся после группового выделения. Исправление119 было неполным:
прозрачная очистка UI-камеры уже существовала, однако её обходил MSAA writeback.

## Воспроизведение и причина

Прежний тест проверял только Node.display. Новый ignored GPU-тест
рендерит 3D-камеру и UI-камеру в общий Image target и читает реальные пиксели.
HUD остаётся на экране; рамка появляется при удержании ЛКМ, затем кнопка
отпускается. Восемь дополнительных кадров исключают обычную задержку
readback. На исходном коде тест дважды обнаружил856 пикселей рамки после
отпускания: Display::None сам по себе не исправляет старое содержимое target.

У UI-камеры не был задан Msaa, поэтому Bevy0.19.1 выбирал Sample4.
MsaaWriteback::Auto включается для последующих камер одного output target.
writeback вызывает ViewTarget::post_process_write, который помечает
destination уже очищенным, и переносит старое изображение в MSAA resolve.
Следующие main/UI-проходы загружают его вместо прозрачной очистки.
Рамка скрыта в ECS, но её пиксели продолжают попадать в композицию.

Первичные источники — локальные исходники зафиксированной Bevy0.19.1:
bevy_render/src/view/mod.rs(post_process_write, prepare_view_targets),
bevy_post_process/src/msaa_writeback.rs(prepare_msaa_writeback_pipelines,
msaa_writeback), bevy_render/src/texture/texture_attachment.rs.

## Исправление

UI-camera bundle создаётся одной функцией panel::ui_camera; её используют
реальный полигон и GPU-тест. Заданы Msaa::Off и MsaaWriteback::Off.
Прозрачная очистка intermediate, premultiplied alpha и сохранение нижнего
output прежние. Шейдерное сглаживание UI-границ остаётся; лишний MSAA
writeback не нужен для HUD. Производственный readback не добавлен.

Дополнительно рамка скрывается при отсутствии однозначного окна/курсора
или фокуса. Обработчик ввода отменяет drag и предыдущую позицию курсора
при потере фокуса даже с застрявшим pressed=true. Отряд сохраняется;
возврат фокуса без нового нажатия не возобновляет старый drag.

## Проверки и пределы

- GPU regression: до исправления fail856, после pass. Проверены640×360
  и3840×1949, изменение размера target, движение края рамки без следа,
  отпускание, потеря/возврат фокуса и сохранение обычного HUD.
- Проверка input выбирает двух союзников, исключает врага, проверяет
  отсутствие обоих концов drag после release и focus loss, сохранение группы
  и отсутствие возобновления жеста при оставшейся зажатой кнопке.
- Общий blast suite:185 passed,1 failed,7 ignored. Отказ input fixture
  вызван отсутствовавшим UiSnapshot после прежнего изменения panel::actions;
  fixture дополнена ресурсом; отдельный повтор прошёл1/1. Это не объявляется
  чистым полным прогоном. Два ранее ignored физических прохождения миссий
  и весь workspace suite здесь не квалифицируются.

GPU-тест выполняется явно:
`cargo test --release -p render --bin blast selection_outline_pixels_disappear_after_release -- --ignored --test-threads=1`.
Тест использует настоящий GPU и Image target, без оконного backend;
ручное перетаскивание в нативном окне и события Alt-Tab ОС не воспроизводились.
Фокус и кнопки задаются ECS-входом. Число пикселей проверяется после
нескольких кадров, не по единственному запоздавшему снимку.
FPS этой правки не измерялся; логика SIM и баланс оружия не менялись.

совпадает с frozen executable: SHA256
