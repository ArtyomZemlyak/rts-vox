# Точные интервалы процедурных колонок

20.10.2026. База main c2385f8, ADR-764. Единая очередь —
[316](316-optimization-delivery-plan.md), предыдущее измерение —
[346](346-adaptive-body-components.md). Артефакты: out/terrain-opt-347/.

## Причина и решение

После346 наиболее тяжёлый стратегический удар тратил около47мс на
первоначальный capture сопротивления и73мс на read_ground. В обеих фазах
крупные клетки читают точные World.column, чтобы разделять XZ-подготовку
генератора между высотами. Но сам RangeTerrain готовил природные холмы,
деревья и камни для колонки подготовленного участка, даже если at() затем
полностью заменял их грунтом/поверхностью/воздухом участка. Также поиск
приоритетного authored блока повторялся для каждой высоты.

В общем RangeTerrain::column_of сначала выбирается уже существующая
владеющая ветвь геометрии. Для участка сохраняются его высота, рампы,
дорожная поверхность и все authored blocks/основания; неиспользуемая
природная ветвь не вычисляется. Вне участка работает прежний читатель.

RangeTerrain::column заполняет постоянные точные интервалы:
грунт ниже поверхности, отдельная ячейка поверхности, воздух выше.
Затем пересечения блоков с запрошенным срезом накладываются от низкого
приоритета к высокому. Это сохраняет first-match semantics:
основания выше layout-блоков, поздние блоки выше ранних, AIR также
заменяет материал. При более двух перекрытиях остаётся прежний
finite-top/first-match reader. Два верхних блока могут совместно скрывать
все382 нижних: полная перерисовка каждого слоя ухудшила бы этот случай.
Fallback сохраняет прежнее чтение только до конечной верхней границы,
но также не подготавливает заменённую природную ветвь.
Высокие u16 material IDs не обрезаются. Неполные
срезы, пустой запрос, границы высот, дорога и рампы сохраняют тот же ответ.

Изменён общий процедурный источник всех полигонов/ИИ/операций. Веток
по типу оружия, номеру сценария или конкретному юниту нет. World.column
сохраняет committed слой изменённых чанков. Материал выдаётся для каждого
вокселя: сопротивление не усредняется, тонкое укрытие не пропускается.
Не менялись RON, мощность/радиус, очередь/квоты, частота30Гц, IDs,
энергия/материя и snapshot. Постоянный кэш и новая mod API не вводятся.

## Следующие участки

OPT316-02b остаётся частичным. Чтение грунта на515 по-прежнему около48мс,
а оплачиваемые claims на513 —26мс. Следующие кандидаты: точные сводки
материалов/спанов для исключения повторных XZ-запросов и bulk claims
без лишних промежуточных объектов, с прежними IDs/ledger/порядком.
Межтиковый индекс опор OPT316-04a остаётся главным кандидатом длительного
боя. Срез не закрывает33мс, очереди/валку, ремешинг, синхронную границу
SIM/render, серии ядерных ударов или общую FPS-приёмку.
