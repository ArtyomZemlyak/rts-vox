# Ускорение освещения и грунта точной адресацией вокселей — 13.10.2026

Продолжение [274](274-engine-profile-coverage.md). База — main `798c46d`.
Изменение относится к общему GPU-рендеру, включая бой с ИИ. Симуляция,
сценарии, разрушения, квоты, плотность дыма и разрешение не меняются.

## Уточнение причины

Метка `gas_raymarch` в анализаторе объединяет gas-base и gas-region.
Это не только объёмный дым: сюда входит освещение поверхностей взрывом
и проверка препятствий на пути света. Для локализации выполнены отдельные
диагностические прогоны по 60 секунд, world-battle/AI-vs-AI, 3840×1949,
physics4/navigation8/Rayon4/Compute4, Vulkan RTX 5090, AutoNoVsync.

| Вариант диагностики | Gas scopes на наблюдавшуюся GPU-публикацию, мс |
|---|---:|
| Исходный рендер | 9,521 |
| Без объёмного изображения облака | 9,168 |
| Без тени облака на поверхности | 9,629 |
| Без регионального освещения/следов на поверхности | 2,340 |
| Без четырёх проверок препятствий для освещения поверхности | 1,959 |

Отключения — только диагностика, в итоговом коде их нет. Это не точное
процентное разложение: меняются число кадров и состав GPU-публикаций,
нет перестановки запусков. Но основной найденный кандидат — дорогой
поиск препятствий для освещения, а не выборка цвета объёмного дыма.

Frozen baseline `out/audit-20261013/normal-blast.exe`, SHA256
`301D81302FB83B27A50ADC85C6DABDC6A33165A50A220B48341B202CC3ABE226`.
Override WGSL и их SHA256 находятся в `out/gas-20261013/<variant>/experiment.json`;
обычный manifest сам по себе не доказывает содержимое `RTS_VOX_SHADER_DIR`.
Каталоги: `reference`, `without-volume`, `without-shadow`, `without-surface`,
`without-visibility`; профиль — подкаталог `profile`. Все пять достигли
тика 1800 и hash `53897fe8c1e09b0e`, выдержали темп 30 Гц.
Диагностический FPS не используется для приёмки.

## Принятое изменение

Локальная воксельная карта хранится в кольцевом буфере: ячейка мира `q`
расположена по адресу `q % dims`. Сдвиг окна не требует переноса старых
ячеек. Но прежний шейдер повторял три динамических целочисленных остатка
на шагах каждого луча, если хотя бы одна координата выходила за `dims`.

CPU один раз при подготовке кадра вычисляет `wrapped_origin = origin % dims`.
После уже существующей проверки принадлежности окна GPU вычисляет:

```text
relative = q - origin + wrapped_origin
address = select(relative, relative - dims, relative >= dims)
```

Каждая компонента `q-origin` лежит в `[0,dims)`, как и `wrapped_origin`.
Их сумма меньше `2*dims`, поэтому одного вычитания достаточно. Это
точно тот же адрес. Окно строится внутри неотрицательных координат мира
через `TerrainWindow::around`. Ячейки вне окна отсекаются до адресации.

В существующий uniform добавлено 16 байт, общих для CPU и обоих WGSL
объявлений. Региональные uniforms получают тот же остаток. Новых
ресурсов, проходов, GPU-readback или кэша, который надо инвалидировать,
нет. Сам обход луча, пределы, материалы, тонкие стены, тени юнитов,
освещение и алгоритм разрушений сохраняются.

## Отклонённые варианты

- Кэш коэффициентов цвета дыма: отложен после диагностики, указавшей
  на другую основную стоимость. Patch — `rejected-colour-cache`.
- Any-hit вместо ближайшего препятствия, сначала область начала луча:
  GPU-оракул подтвердил ответы, но native gas вырос до 13,440 мс,
  за 60 секунд выполнено 1766 тиков вместо 1800. Вариант отклонён.
- Any-hit с простым local-first тоже не выдержал темп: 1733 тика,
  gas 14,009 мс на наблюдавшуюся публикацию.
  Patch и тест сохранены в `rejected-any-hit`, исходный обход восстановлен.

Причина проигрыша any-hit на уровне машинного кода GPU не установлена.
Меньшее число логических запросов само по себе не гарантирует ускорения.

## Проверка корректности

- Настоящий Vulkan compute сравнивает новую адресацию с независимым `%`:
  163 840 адресов, четыре размера окна, пять начал, включая невыравненные,
  нулевые и многократно обёрнутые; проверены обе крайние ячейки окна.
- Прежний GPU-тест стен, удаления и сдвига окна сравнивает ускоренный
  обход с повоксельным эталоном, который сохраняет `%`. Замена в тексте
  эталона проверяется явно и не зависит от CRLF/LF.
- GPU suite: 16 passed. Render lib: 138 passed, 2 ignored.
  Ни в одной изменённой строке нет кода авторитетной симуляции.

## Измерения

Первичная GPU-проверка `wrap-gpu`: 60 секунд, 1800 тиков, прежний hash,
валидный контекст 3840×1949 и темп 30 Гц. Gas 9,521 → 8,357 мс,
terrain 3,704 → 3,273 мс. Это диагностическое наблюдение одной пары,
не гарантированный процент ускорения всего кадра.

Обычная ABBA-приёмка: четыре последовательных запуска по 60 секунд,
те же настройки и 3840×1949, observers Core/GPU/Timeline/Tasks выключены.
Никаких параллельных сборок, тестов или захвата изображений. Новая сборка
использует встроенные шейдеры; `RTS_VOX_SHADER_DIR` очищен.

Средние двух запусков: 56,127 → 62,676 FPS (**+11,7%**), интервал
17,817 → 15,955 мс (**−10,4%**). Обе пары прошли проверки сопоставимости
и обычной FPS-приёмки анализатора. Во всех запусках 1800 тиков, 30 Гц,
hash `53897fe8c1e09b0e`. Средняя стоимость CPU-тика почти прежняя:
12,85–12,92 мс. Устойчивое снижение хвоста/максимума не доказано:
пики около 76–78 мс остались. Цель 165 FPS не достигнута.

Это повторяемый выигрыш на данном workload и RTX 5090, не гарантия
для любого оружия, камеры или минимальной целевой видеокарты.
Длительность 60 секунд не покрывает все события 120-секундного боя
из 274; сравнивать их FPS напрямую нельзя.

для камеры — `-CameraTour` и 90 секунд, не смешивая её с неподвижной сценой.

## Что осталось тяжёлым

Адресация — только часть стоимости. Даже после изменения группа
gas-region/base занимает около 8,36 мс на наблюдавшуюся публикацию.
Следующий GPU-кандидат — повторный поиск препятствий к источникам света;
простые any-hit варианты уже измерены и отклонены. Требуется точное
сокращение повторной работы с проверками перекрытий и движущихся юнитов,
а не уменьшение качества или выключение теней.

CPU motion/debris/rubble и пики взрывных тиков остаются приоритетами
из 274. Этот шаг почти не меняет их время и не закрывает долг валки,
масштаб 5000 машин, every-tick или native-165. Границы GPU-публикаций
из ADR-703 сохраняются: времена scopes не являются полным временем
GPU-кадра и не привязываются к конкретному CPU hitch.
