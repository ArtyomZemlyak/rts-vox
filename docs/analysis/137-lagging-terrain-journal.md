# Уплотнение журнала terrain при отстающем рендере — ADR-543

03.10.2026, исходный main `1435826`. Продолжение [ADR-542](136-render-worker-calls-and-workload.md):
дорогой actual extraction позднего боя, WBPERF-007/008.

## Подтверждённая причина

`begin_frame` очищал `terrain_dirty` только при точном совпадении текущей
revision с GPU acknowledgement. Пока рендер отставал и производитель
продолжал менять землю/маски юнитов, Vec удерживал все прежние записи,
включая повторные и пересекающиеся. Extraction клонировал, сортировал
и объединял всю историю заново. Число выходных patches скрывало её размер.

Для проверки render trace schema 3 добавляет к фактическому `gas_extract`
исходные `dirty_ranges` и wall подфаз range copy/sort/merge, pack words,
clone прочих inputs. Дополнительные clocks работают только с подробной
render-трассой. Подфазы включены в extraction, не прибавляются к нему.
Parser читает schema 1/2/3, проверяет scope/неотрицательность/сумму фаз,
различает контракты и показывает отдельную таблицу.

В контрольном 120-секундном бою, source row 7353 / tick 3296:
**1529715 исходных диапазонов → 37335 patches**; actual extraction
22,9627 мс, из них range 22,4658 мс, pack 0,4824 мс, clone 0,0119 мс.
Это устанавливает конкретный дорогой алгоритм и накопление его входов;
не объясняет все остальные Bevy prepare jobs или редкие фризы.

## Исправление

При задержанном acknowledgement `begin_frame` объединяет уже обработанный
масками префикс журнала. Покрытые адреса слов сохраняются точно, включая
пересечения/смежные ranges. GPU должен получить тот же union текущих
значений; непризнанные загруженными изменения не удаляются.

Необработанный масками хвост остаётся в прежнем порядке. После сокращения
префикса mask cursor перемещается к новой границе, поэтому хвост попадает
в `advance_gpu`, а старые записи не проигрываются повторно. Отдельный cursor
позволяет пропустить уже уплотнённый префикс без новой работы. Сортировка
малых журналов до 1024 consumed entries не добавляется. Точное совпадение
revision/ack по-прежнему очищает журнал и оба cursor.

Это ограничивает повторы обработанной истории размером её реального
покрытия плюс новые записи. Непотреблённый хвост не имеет нового общего
лимита и не отбрасывается; независимый журнал по revisions/reuse payload
остаётся дальнейшей работой. Изменяемый terrain не разделяется с render
world: прежний запрет на Arc copy-on-write полного ~157 MB сохранён.
Физика, authoritative sim, материя, частоты, качество и шейдеры прежние;
новых потоков и зависимостей задач нет.

Стоимость обслуживания измеряется отдельно при включённом профиле:
число compactions, total/peak main-thread wall сохраняются в атомиках и
печатаются после замера. Analyzer показывает их как часть Update, а не
добавочное время кадра. Старые записи без этого поля остаются unknown.

## Проверки и CPU-контроль

Regression tests имитируют задержанный GPU: 64 кадра повторных правок,
проверка union по независимому набору адресов и всех текущих значений,
отсутствие sharing полного terrain, очистка после ack. Отдельный тест
сохраняет неподготовленный хвост при уплотнении 2048 повторов и проверяет
границу mask consumption/отсутствие повторного чтения.

Manual release benchmark включает обслуживание журнала, `advance` и
extraction/drop, 240 кадров по 4096 ranges, одна и та же отстающая revision:

| Trial | Прежняя логика, мс | С уплотнением, мс |
|---|---:|---:|
| 0 | 903,669 | 48,701 |
| 1 | 910,490 | 47,233 |
| 2 | 899,070 | 47,278 |

Старый путь сохраняет 983040 entries, новый — 8192 в конце. Это контроль
полной CPU-стоимости на синтетической нагрузке, не обещание FPS всей игры.

128 library + 101 blast + 81 Python + 23 PowerShell = **333 проверки**,
без отказов. Четыре manual tests обычно ignored (два lib, два blast);
новый journal benchmark дополнительно выполнен отдельно, шесть trials.
Release build/clippy проходят без новых предупреждений. Seed 42 / ticks
1000 / units 5000: прежний hash `66041a9f60189841`.
