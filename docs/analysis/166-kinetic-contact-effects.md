# ADR-572 — эффект бронебойного контакта

Одиночное орудие и все боевые юниты используют один bounded эффект.
До изменения бой создавал только огненный куб edge 1.8 / life 0.16;
одиночный тест — десять небольших искр. Удар плохо читался.

Теперь контакт даёт белую вспышку на 0.10 с, 16 золотых кубических следов,
7 серых вращающихся сколов и 4 прозрачных пылевых блока. Размеры,
скорости и время жизни неоднородны; следы длиной 2–6.5 world units.
Это презентационные частицы, а не дополнительная разрушенная материя.
Общий прежний CAP 1800 не увеличен. Полный пакет 28 частиц освобождает
место за счёт старых визуальных остатков при насыщении.

Веер направлен против последнего отрезка траектории, если контакт
находится рядом с его продолжением. Cached paths ограничены 512,
обнуляются на clear и обновляются после обработки контактов. Новые
мгновенные/неизвестные попадания используют верхнюю полусферу;
владелец не угадывается по соседнему юниту. Нормаль поверхности этим
не вычисляется. Презентационная баллистика использует gravity текущего
кинетического пресета, спрайты не проверяют столкновения с миром.
Реальные обломки и столкновения остаются в прежней симуляции.

Искры имеют направленные cuboid trails; сколы сохраняют размер,
охлаждают цвет и кувыркаются. Пыль прозрачна, с коротким ростом/затуханием.
Отдельные цвета контакта не используют flame_colour, fireball, gas или
поле нагрева. Если попадание уничтожает юнит, прежний эффект гибели
остаётся отдельным событием.

Проверки: реальная стрельба Kinetic без Explosion; два боевых попадания
на полном пуле остаются видимыми, перекрываются и истекают; state_hash
до/после capture одинаков. Worker geometry fixtures включают Flash,
Spark, Chip, Dust и сравнивают позиции/нормали/цвета/индексы/asset usage
при 1/2/4/8 workers и обоих режимах. Headless render --bin blast проходит.
Исходные 13 WIP сохранены отдельно и исключены из коммита; никакой новый
CPU/GPU FPS gain этим визуальным этапом не заявляется.
Логи и native build manifest — out/fix572. Native capture проверяется
по engine screenshots, без стороннего управления окнами.

Первый native capture выявил старый оранжевый свет на стене и грунте:
одиночное Kinetic попадание создавало пустой холодный газовый регион,
который всё равно включал generic blast light/soot в composite. Для
Kinetic этот регион больше не создаётся. В сцене без raymarched layout
прежний PBR BlastLight получает короткий светлый pulse с быстрым спадом
вместо долгого фугасного. Battle Kinetic уже не создавал atmosphere;
теперь оба режима используют только общий контактный эффект.

Полный headless blast suite: 125 passed, 0 failed, 3 прежних ignored.
После корректировки газового света повторный fire suite: 25 passed,
0 failed, 1 прежний ignored; это пересекающиеся проверки, их не суммируем.
Итоговый native capture имеет отдельный каталог visual-final;
первые visual/*.png сохраняются как доказательство найденного дефекта,
не как финальный результат. Capture offline, UI-счётчик FPS на снимке
не является замером realtime производительности.

Финальный native capture: exit 0, 7 PNG; IMPACT tick=57. На 04-impact
и 05-discharge отсутствует прежняя оранжевая засветка; видны короткая
светлая вспышка, направленные искры и серая пыль. Screenshot capture
не является realtime benchmark. Installed target/release/blast.exe
и frozen native-final.exe совпадают по SHA-256:
