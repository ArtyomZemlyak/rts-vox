# 467 — Параллельная очистка Settled stripes

3 ноября 2026, ADR-828. Артефакты: `out/optimization-467/`.

## Причина

Поздний профиль ADR-827 показывал 1,961 мс `settled_clear` на 3000 тиков и 5,041 мс
в более длинном аудите. Восемь владельцев stripe очищались последовательно и для cell
lists, и для query words, хотя их buffers независимы и уже заполняются параллельно.

## ADR-828

`SettledCells::clear_parallel` и `SettledQueries::clear_parallel` используют существующие
восемь stripe owners через Rayon при `fragments.len() >= 1024`. Малые входы сохраняют
прежний scalar clear. Очистка по-прежнему полная: allocations остаются для следующего
builder, логические entries удаляются, `len` сбрасывается.

Никакого persistent state, нового cache key или изменения contact builder нет. Порядок
последующего заполнения, stable IDs, контакты, Fx, snapshot и hash не меняются.

## Проверки

- 200 тиков: все 36 нетайминговых CSV-полей совпали.
- Две ordinary ABBA серии по1600: все36 полей каждого тика совпали, mismatches=0.
- Replay snapshot300→600 на physics1/4/8: `695327e0588d053c` во всех режимах.

заявление об идеальном четырёхкратном масштабировании clear.
