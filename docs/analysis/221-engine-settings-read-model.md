# Настройки через модель чтения общего движка

Дата: 08.10.2026. Продолжение EP-02b после [217](217-engine-panel-read-model.md),
контрольная сборка — [220](220-engine-fragment-identity-transforms.md).

## Причина и изменение

`knobs::refresh` получал `Res<Scene>` и отдельно читал физические параметры
для каждой строки. Когда в составе нет шагохода, каждое поле его шасси
вызывало разбор всего встроенного `data/sim.ron`. Отсутствие шагохода —
обычное состояние данных, поэтому исправление не привязано к сценарию.

Общий `blast::read_model::Parameters` экспортирует owned конфигурацию
оружия, параметры отдельного орудия, фиксированную таблицу шасси по видам,
параметры обломков и необязательной трассы. Для вида берётся первый слот
ростера, в том числе погибший: это прежняя семантика настроек, а не выбор
живой цели. Нет ссылок на мир, тел, маршрутов, геометрии или очередей.
Конфигурация оружия и шасси состоят из полей фиксированного размера.
Сбор первых шасси проходит ростер один раз: время зависит от числа юнитов,
хотя размер таблицы ограничен числом видов. Это не обещание постоянного
времени при произвольном количестве юнитов.

Материалы запрашиваются по явным ID. Экспорт не сканирует разреженный
реестр целиком; отсутствующие ID пропускаются, повторные устраняются,
оставшиеся упорядочиваются по ID. Память списка переиспользуется. Размер
и работа ограничены запросом потребителя; произвольный внешней длины
iterator не получает скрытого фиксированного потолка. Product schema
задаёт конечный набор запросов независимо от карты и числа мод-материалов.

Publisher запрашивает Parameters только при открытых настройках и наличии
строк значений. При закрытии или исчезновении потребителя снимок освобождается.
Обновление выполняется и на прежнем тике; это сохраняет изменения на паузе.
`knobs::refresh` читает только публикацию и render-owned параметры картинки;
при несовпадении generation/tick с View показывает отсутствие физического
значения. Вводимое число остаётся локальным буфером пользователя. Система
обновления настроек включена в цепочку после publisher.

Встроенные defaults шасси кешируются один раз через `OnceLock` в render.
Это неизменяемый результат разбора `include_str!`, не новое глобальное
состояние симуляции. Чтение настроек обработчиками ввода остаётся свежим
прямым чтением мира и также пользуется этим кешем. Writer не принимает
решение по потенциально устаревшему UI-снимку.

## Приёмка

До замеров записан `out/engine-fixes-20261008/settings-read-model/acceptance.json`:
совпадение всех нетайминговых потиковых полей и hash с 220; late replay;
на 60 юнитах mean Parameters export ≤50 мкс, p99 ≤200 мкс; корректность
всех вкладок и отсутствие Scene у refresh; отсутствие новых архитектурных
диагностик; три ordinary native пары по 120 секунд с медианой FPS не ниже
97% контроля и медианой p99 не выше 103%. Микрозамер defaults сам по себе
не считается доказательством роста FPS боя.

## Проверки

Полный `cargo test --release --locked --offline -p sim-core -p nav`:
**894 passed, 0 failed, 6 ignored**. Включены два новых теста Parameters:
owned-публикация не меняет snapshot; изменения на том же tick видны;
первый погибший слот не заменяется следующим живым; reset очищает отсутствующие
виды, трассу и материалы; повторные и неизвестные ID обрабатываются корректно.

Полный `cargo test --release --locked --offline -p render`:
**292 passed, 0 failed, 6 ignored**, из них blast — **145 passed, 4 ignored**.
Три новые проверки сравнивают каждое поле с прежним прямым чтением при
наличии и отсутствии шагохода/трассы; проверяют публикацию только открытому
потребителю, изменения на паузе и смену поколения; обновляют все семь
вкладок без Scene, сохраняя ввод/маркер override и отбрасывая старые числа.
Отдельный ignored test служит только ручным замером defaults.

Architecture: **5 passed, 4 прежних failed**, **46→46** уникальных сообщений
после нормализации номеров строк, добавленных и удалённых нет. Остаются
прямые render writers, floating point, hash containers и часы в путях,
которые проверка считает симуляционными. Этот пакет не закрывает эти отказы.

## Цена defaults и объём данных

Ignored `measure_absent_walker_defaults` исполняется отдельно после всех
сборок/тестов. В одном executable сравниваются явное воспроизведение
прежнего полного разбора RON и новый прогретый `stock_chassis`, с black_box
на входах/результате. Четыре последовательности old/new/new/old, в каждой
2000 наборов по 16 полей; checksum всех четырёх — 2216000.

Прежний путь: **0,434286 / 0,433003 мс на набор**. Новый прогретый цикл:
**0,069 / 0,053 мкс на набор**. Это только получение встроенных чисел:
первый однократный разбор, экспорт мира, форматирование текста, Bevy и GPU
в эти интервалы не входят. Нельзя переносить коэффициент микрозамера
на FPS боя, особенно если шагоход есть или вкладка закрыта.

Product schema делает 18 запросов по ID и получает 8 уникальных материалов.
Logical payload Parameters — **2000 bytes**; из них фиксированная часть
1776 bytes и 224 bytes материалов. Retained capacity списка — **896 bytes**,
то есть фиксированная часть с выделенным буфером — 2672 bytes без overhead
аллокатора. Дубли временно занимают буфер до dedup; эта память переиспользуется
при открытой панели и освобождается при закрытии. Число fragments на размер
публикации не влияет; память всего процесса этим замером не измеряется.

## Полный бой и восстановление

Четыре последовательных headless запуска: frozen 220 control, новый путь,
новый путь с шестью View+Parameters exports после каждого тика, новый путь
с восстановлением 3300→3600. В каждом 60 юнитов, 3600 тиков, physics/navigation
8/8, damage trace и tick CSV. Сборки, тесты и тяжёлый анализ не выполняются
параллельно замерам.

Во всех совпадают **25 нетайминговых потиковых полей**, shots/damage,
alive [26,21], базы [100,100], peak_rounds=30, hash **`5dd0c782d2b2f557`**.
Snapshot на 3300-м тике — 134186763 bytes плюс layout 59377 bytes.
Restore до 3600-го тика воспроизводит исходное состояние.

Mean физического тика по порядку запусков: **13,260 / 13,253 / 13,197 /
13,263 мс**. Экспорты измеряются после закрытия интервала физического step;
эту небольшую разницу нельзя приписывать ускорению симуляции.

21600 Parameters exports: mean по шести окнам 600 тиков — **0,206 / 0,218 /
0,218 / 0,224 / 0,223 / 0,226 мкс**, p99 **0,6–0,7 мкс**, общий max
**14,4 мкс**. Заранее записанный gate mean/p99 пройден. Этот стенд запрашивает
10 разных ID 0…9: payload **2056 bytes**, retained materials **448 bytes**;
он измеряет ядро экспорта, без разбора UI-ключей/форматирования/отрисовки.
Product schema с повторными запросами измерена отдельно выше. Шесть повторов
подряд используют горячий кеш; это не latency целого кадра или гарантия
для 5000 юнитов. Старые retained фрагменты в export не посещаются.

## Границы и следующая работа

Это миграция чтения настроек, а не всего UI-ввода. `knobs::actions/apply`,
workbench и остальные product writers ещё обращаются к авторитетному миру;
geometry/terrain/occupancy также требуют собственных экспортов. Владелец
симуляции остаётся синхронным. Данные сценариев, алгоритмы боя, физика,
зависимости, save/hash и бюджет продвижения очередей не меняются.

Следующий срез EP-02 должен закрывать оставшиеся writers и geometry readers
с явными поколениями, размером, стоимостью копирования и освобождения.
Независимые работы capacity/progress и исторических обходов сохраняют
приоритет. Этот пакет не закрывает EP-02/03, миллионные очереди или 165 FPS.
