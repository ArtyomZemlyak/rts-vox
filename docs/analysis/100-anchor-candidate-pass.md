# Один проход по кандидатам опор

25.09.2026, ADR-407, P-45. База — `35b7c97`.

## Причина

После уплотнения контактов графа поиск опор оставался самой дорогой
CPU-фазой длинной поездки по километровому полигону. К концу маршрута
известно 189 747 чанков, 379 654 компоненты и 133 519 чанков с
компонентами без непосредственной опоры. `resolve` дважды просматривал
плотный индекс всех потенциальных чанков и повторно извлекал из узла
те же метки, включая редкие метки выше 63.

## Изменение

Первый проход по индексу теперь одновременно снимает предварительную
заякоренность и собирает список `(чанк, метка, глобальный номер)`.
Второй проход идёт по этому списку, сохраняя прежний порядок чанков и
меток. Буфер переиспользует ёмкость между тиками. Он производный,
не входит в снимок и пересобирается после обновления граней; его
ёмкость учитывается в `graph_bytes()`. Правила поиска, порядок
отделения и лимиты работы не меняются.

## Замер

Два старых и два новых релизных прогона на одной машине:

```powershell
.\target\release\bench_range.exe --range data/range-km.ron --move 2200,336 --ticks 6500
```

| Метрика | До | После |
| --- | ---: | ---: |
| p50 поиска опор | 3,567–3,571 мс | 2,985–3,004 мс |
| p99 поиска опор | 8,021–8,127 мс | 6,789–7,063 мс |
| p99 полного CPU-тика | 10,783–10,852 мс | 9,802–9,851 мс |
| Снятые клетки | 128 349 | 128 349 |
| Круги четырёх патрулей | `0,5,1,5` | `0,5,1,5` |
| Итоговый хеш | `bb4a604c28e62856` | `bb4a604c28e62856` |

В одном новом прогоне максимум поиска вырос до 33,045 мс против
21,624–22,439 мс в двух исходных; повторный новый прогон дал
18,107 мс. Это хвост с заметным разбросом, а не доказательство
улучшения худшего кадра. Стабильные 120 FPS не достигнуты. Стенд
измеряет CPU-тик без рендера, GPU и переноса видимого окна.

Сырые журналы и исходный бинарник — `out/backlog/adr-407`.

Дополнительно две пары 600-тиковых прогонов с одним энергетическим
выстрелом по той же карте дали одинаковые 46 645 снятых клеток и хеш
`c6373dfde61c255c`. p99 поиска опор в боевом опыте
1,393–1,836 → 1,085–1,150 мс, а p99 всего CPU-тика
6,146–6,581 → 6,058–6,308 мс: интервалы второго показателя
перекрываются, и ускорение полного боевого тика не утверждается.

Прошли 132 теста `voxel` и полный `cargo test --workspace`, включая
эталонные хеши, сохранения и секторные сценарии. Линтер
`clippy --workspace --all-targets -D warnings`, форматирование и
релизная сборка нативного `blast` прошли. Контрольный
`sim-cli --seed 42 --ticks 1000 --dump-hash` сохранил хеш
`12bd9cb0d53498f2`.
