# Компактный список действий пробуждения обломков

Дата: 07.10.2026. Продолжение [проверки 206](206-engine-roof-support-queries.md) и узкая часть EP-07 [общего плана](200-engine-performance-plan.md). Roof index из 206 отклонён и не возвращается в рабочий код. Новый кандидат сокращает временные результаты и пустой последовательный проход фазы wake, сохраняя прежние физические запросы и admission.

Изменение принято: в четырёх последовательных AI runs средние двух контролей против двух новых прогонов дают **wake −13,7%, debris −3,2%, полный tick −1,0%**. Физическое состояние, workload и поздний replay совпадают. Сценарии остаются данными; изменение находится в общей фазе `Bursts::step_fragments_reserved`.

## Наблюдение и гипотеза

В контроле 205 на последнем tick 39 495 фрагментов, из них 35 774 parked. Wake сохраняет `(push, unsupported)` для каждого фрагмента, затем проходит весь массив с mutable доступом, хотя ответы `(None, false)` не меняют ни тело, ни reservations. В окне 3301–3600 весь wake занимает около 0,699 мс на tick; это callback wall interval запросов, соединения результатов и последовательного применения, а не exclusive CPU time.

Гипотеза — сократить цену временного массива и пустых commits: собирать только ответы с push или unsupported, сохраняя исходный индекс, порядок запросов и повторную проверку room перед применением. Ожидаемая метрика — стоимость wake и debris в полном AI battle; oracle — прежний полный список ответов и полное физическое состояние. Ускорение нельзя получать изменением квот, сроков поддержки или состава боя.

## Общая фаза

`fragment_wake_queries` читает неизменяемый список начала фазы. Для каждого фрагмента вызывается прежний predicate. Действие сохраняется только при `push.is_some() || unsupported`; `Some(V3::ZERO)` также остаётся действием. При 1024+ фрагментах каждый batch из 256 элементов собирает собственный компактный список. Indexed collection соединяет batches по их номеру и сохраняет исходные slots внутри каждого batch. Для маленького списка используется последовательный обход.

Последовательное применение получает исходный индекс тела. Flying/working room, parked boundary, terrain claims и thermal reserve проверяются как раньше перед применением каждого действия. Кандидат, которому не хватило места после предыдущего действия, не обходит эту проверку. Пустой ответ не расходовал место и не менял состояние; его отсутствие не меняет результат следующего действия. Source slots не уплотняются и не переставляются.

Построение Settled, сроки due, contact predicates и индекс первого корпуса из 205 не меняются. Перебор исторического массива для predicates сохраняется; этот шаг не закрывает active/sleep migration. Физические budgets, сохранение, hash, материальный ledger и сценарии прежние. Нет отдельного режима физики для ИИ или конкретной карты.

Временная память пропорциональна числу actions плюс числу batches. В плотном случае все ответы могут быть действиями, поэтому экономия не гарантирована: явный индекс и промежуточные batch lists имеют собственную цену. Полный battle gate учитывает allocations, соединение и освобождение этих списков.

## Проверка порядка и реальной работы

Новый oracle сравнивает компактный список с полным для 0/1/1023/1024/1100/39 495 элементов при 1/4/8 workers: все пустые ответы, редкие смешанные actions и действие для каждого элемента. IDs намеренно идут в обратном порядке относительно slots. Счётчик требует вызова predicate ровно для каждого фрагмента; порядок ответов совпадает с исходными индексами, включая границы batches и нулевой push. Для пустой фазы итоговый список не содержит ни одной записи для commit.

Полный differential kernel сравнивает optimized/legacy collectors вместе с прежними индексированным/скалярным contact paths. 1100 реальных фрагментов, 80 корпусов, две перекрывающиеся поверхности с противоположными толчками, pending terrain claim и сначала заполненный резерв. Двадцать шагов при 1/4 workers сверяют snapshots, полный ledger/free containers, wrecks и материальный баланс. Требуются реальное пробуждение после освобождения вместимости, подтверждение claim и восстановление одного пути из сохранения посередине.

## Оставшаяся работа

EP-07/WBPERF-005/011 остаются частичными. Полные predicate scan, построение Settled, rubble gather, translation/substeps и обслуживание накопленной истории сохраняются; новый collector сам по себе не освобождает физическую вместимость. Следующий шаг — отделить цену этих обходов и подготовить производные active/sleep sets с устойчивыми slots и прежним ordered admission. Не повторять отклонённый roof index без доказанного полного выигрыша.

EP-02a/02b/03 и EP-04b/c сохраняют приоритет: общий командный протокол, согласованное состояние для чтения, отдельный владелец симуляции и конечный прогресс физических очередей. Frame/tick coupling, длинные очереди валки/обрушения и большой полноценный игровой roster не закрыты этим исправлением.
