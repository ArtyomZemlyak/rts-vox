# Поиск опоры на корпусах: отклонённый прототип

Дата: 07.10.2026. Продолжение [пакета 205](205-engine-debris-hull-index.md), узкая часть EP-07 [общего плана](200-engine-performance-plan.md). Общая физика исключает обломки на крышах из опор земли и карты rubble. Два потребителя повторяли поиск по всему списку корпусов: подготовка `Settled` и классификация `Bursts::rubble_observed`. Проверена возможность использовать фазовое пространственное дерево для этих запросов.

**Результат: не принято.** Все варианты ускорили только разреженный query стенд, но не полный текущий бой с ИИ. Даже адаптивный вариант дал tick +0,44% и debris +1,56%. Весь рабочий код восстановлен к принятому 205 по всем 361 inputs; новая API и benchmark source удалены из рабочего дерева. Ниже описан сохранённый прототип и его проверка, а не включённая оптимизация. Сценарии и политика ИИ не менялись.

## Что проверял прототип

`HullRoofQueries` заимствует неизменяемый `HullQueries` текущего вызова. Для списков от 128 корпусов отдельный массив хранит минимальную возможную высоту крыши каждого узла. Размещение узлов и построение принятого contact index из 205 сохранены. Roof metadata не увеличивает размер contact node и не вычисляется для маленького списка. В step_fragments используется уже построенное дерево; rubble строит его только для большого списка и переиспользует между классификацией и построением опор.

Дерево отсекает кандидатов по горизонтальным bounds и нижней границе крыши. Верхняя граница Y намеренно не используется: кусок в высокой куче над крышей тоже может быть наездником. Окончательный ответ даёт прежний `Hull::carries`, включая поворот, колонку настоящих вокселей и отверстия. Путь подготовки `Settled` дополнительно сохраняет прежний `footprint_box` guard; raw classifier его не получает. Оба ответа сверяются с соответствующим старым циклом.

До 128 корпусов остаются прямые прежние циклы. Если contact index не построен из-за недопустимых bounds или вычитание координат опасно, запрос также возвращается к скаляру. Порог — выбор алгоритма общего движка по размеру входа, без имени сценария, стороны или типа контроллера; это не изменение игровой квоты и не доказательство оптимального crossover для всех распределений.

Индекс живёт один вызов, не входит в save/hash и не кеширует повреждённую геометрию между фазами. Источник списка, порядок фрагментов, reservations, claims, thermal reserve, pools, translation/substeps, point support и построение rubble columns прежние. Полный gather исторического массива остаётся. Сценарии, ИИ, зависимости и данные не изменены.

## Почему первая версия отклонена

Горизонтальный прототип и версия с минимальной крышей для всех roster sizes ускорили разреженные raw queries, но не прошли общий battle gate. В четырёх прогонах второй версии среднее двух контролей против двух новых: tick 13,249→13,354 мс (+0,79%), debris 2,579→2,602 мс (+0,91%), rubble 1,443→1,472 мс (+2,02%). Workload и физический результат совпали. Ускорение этого microbench не принято за ускорение игры.

В текущем бою максимум 60 корпусов, а `Settled` уже имеет дешёвый guard. Дополнительное построение/обход дерева здесь не окупилось. Итоговая версия отделяет roof metadata и оставляет скалярный roof path маленькому списку. Отрицательные raw и frozen binaries сохранены в `out/engine-fixes-20261007/roof-queries-horizontal/` и `roof-queries-all-rosters/`; они не относятся к итоговой приёмке.

## Проверка результата и работы

Oracle проверяет 0/1/8/15/16/17/64/65/96/128/129/256 корпусов, включая обе стороны порога, перемешанный исходный порядок, повороты, дробные координаты, отверстия, пустые voxel columns и box-only корпуса. Запросы находятся высоко над крышей, низ фрагмента меняется от положения под корпусом до положения над ним. Для raw и guarded paths отдельно проверены крайние i64 coordinates/bottom и возврат к скаляру.

В разреженном стенде на 256/1024 корпусах настоящий ответ последнего исходного корпуса требует не более четырёх leaf checks; запрос ниже минимальной крыши не читает ни одного корпуса листа. Это проверка выполненной работы, а не подмена точного ответа bounds. При плотном перекрытии худший случай остаётся O(H), а стоимость сканирования вокселей отдельного корпуса не ограничена этим числом.

Полный differential kernel расширен до 1100 реальных фрагментов и 256 query hulls. Две перекрывающиеся движущиеся поверхности толкают в разные стороны, остальные корпуса проверяют дальний roster; часть находится за границей маленького мира. Это тест общей физики и read-only queries, не бой 256 полноценных юнитов. Двадцать шагов при 1/4 workers сравнивают indexed/serial snapshots, ledger/free containers, wrecks и материальный баланс, настоящее пробуждение после освобождения резерва, terrain claim и восстановление одного пути. Каждый шаг дополнительно сравнивает всю canonical rubble map двух kernels.

## Узкий замер

`bench_hull_roofs`: 4096 raw queries, 4 warm и 20 measured rounds, разнесённые повёрнутые корпуса с voxel holes, смесь попаданий/промахов и запросов ниже крыши. Build измеряет contact tree и roof view вместе; освобождение исключено из microbench, но включено в battle tick. Before — frozen scalar wrapper, after — итоговая адаптивная версия.

| Корпуса | Прежние queries, мс | Новые queries, мс | Новый build, мс | Build + queries дешевле |
|---:|---:|---:|---:|---:|
| 8 | 0,0769 | 0,0798 | 0,00004 | −3,7% |
| 60 | 0,3695 | 0,3938 | 0,00222 | −6,7% |
| 256 | 1,4946 | 0,1297 | 0,00915 | 90,8% |
| 1024 | 5,6801 | 0,2158 | 0,09863 | 94,6% |

Checksums совпали для всех размеров. На маленьких списках microbench обёртки дороже на 3/24 мкс за 4096 запросов; ускорение этих размеров не заявляется. Это raw query стенд, не профиль guarded Settled и не доказательство выигрыша для любого расположения. Ни 5000 юнитов в игровом runtime, ни native FPS этим не квалифицированы.

## Бой с ИИ и отказ от внедрения

Четыре последовательных release/offline/locked runs: frozen принятый 205, адаптивный прототип, повтор прототипа, повтор контроля. World/AI vs AI, 3600 ticks, physics/navigation workers=8/8; damage trace и tick CSV одинаковые. Сборки и тесты не выполнялись одновременно с замерами; replay отдельно.

Средние двух контролей и двух прототипов: tick **13,273→13,332 мс (+0,44%)**, debris **2,577→2,617 мс (+1,56%)**, rubble **1,443→1,461 мс (+1,29%)**. Settled candidates практически прежние (−0,10%), Settled целиком +3,21%. Два повторения не дают доверительного интервала или доказанной причины роста; они не дают основания объявить ускорение или отсутствие регрессии. По gate плана необъяснённый рост полного времени возвращает прототип на доработку. Снижение количества leaf reads в узком стенде этого требования не отменяет.

Settled показатели — средние 12 логируемых окон по 300 ticks с округлением каждого окна до целой микросекунды; их нельзя выдавать за точные exclusive CPU суммы. Callback wall interval включает ожидания фазы. Пики и позднее окно тоже не улучшились устойчиво.

Во всех четырёх совпали hash `5dd0c782d2b2f557`, alive [26,21], базы [100,100], полные shots/damage и peak_rounds=30. Все 25 нетайминговых CSV fields совпадают на каждом tick, физические damage windows и geometry/ground-only counters одинаковы. Workload не был уменьшен ради результата: ground-only calls 30 372, contact visits 10 645 408; felling 2 915 882 и collapse_queued 2 013 153 на tick 3600 прежние.

## Проверки, паспорт и восстановление рабочего кода

Адаптивный прототип прошёл `cargo test --release --locked --offline -p sim-core -p nav -- --test-threads=4`: **848 passed, 0 failed, 6 ignored** (111 nav, 690 sim-core lib, 3 bin, 44 integration). После этого расширены только test roster counts до 128/129/256; все шесть query/kernel tests дополнительно перезапущены и прошли. `cargo check --locked --offline -p render --bin blast`, source format и `git diff --check` прошли. Четыре прежних architecture failures из 201 не перезапускались; весь workspace зелёным не объявляется.

Отдельный replay прототипа 3300→3600 прошёл: snapshot 134 186 763 bytes, layout 59 377 bytes, hash `5dd0c782d2b2f557`. Корректность и сохранение подтверждены; performance gate не пройден.

Frozen контроль 205: SHA256 `fd79ddc869a0d92c136be6a503f31f728b8a9e0b1e0a8faa4fe52e91ac9c7ea5`. Frozen адаптивный прототип: `0e3fec082c02087bcea26ce86985174d7e7e9a895877118e1994f11884d705e1`. Паспорт относится к архивному прототипу; после отката намеренно не совпадает с текущими исходниками. Полные четыре изменённых source files сохранены как `adaptive-*.rs` рядом с паспортом.

Полный suite после отката не повторялся, поскольку ни один вход принятого 205 не изменён. Его прежняя приёмка — 846 passed, 0 failed, 6 ignored. ## Как продолжать план

Для текущего боя перенос roof scan на дерево не имеет доказанной пользы. Следующий EP-07 шаг должен выделить цену построения/обслуживания Settled и полного historical gather, включая boxes/ranges/query cells, dispatch/join/free, а затем сокращать доказанный источник работы. Не повторять эту миграцию на основании только большого raw query benchmark. Дополнительная проверка большого игрового roster потребуется отдельно от стенда read-only hulls.

Общий active/sleep lifecycle, ordered wake/reservations, освобождение вместимости EP-04b/c, командный протокол EP-02a, состояние для чтения EP-02b и отдельный владелец симуляции EP-03 остаются приоритетами. Ни один этап этим экспериментом не закрыт; принятые оптимизации 201–205 сохранены.
