# Дельта отпечатков завалов — 15.10.2026

База — `941af6f`, свежий `origin/main` совпадает. Это отдельный точный шаг
О3 из [281](281-optimization-proposals-review.md), ADR-708. Он ускоряет
публикацию уже вычисленной карты завалов для навигации в общем движке.
Сценарии, физика, баланс, сроки разрушений и формат сохранения прежние.

## Что изменено

Раньше любое отличие готовой карты запускало FNV по всем её допустимым
столбцам и пересборку дерева отпечатков всех страниц. Теперь линейное
слияние двух отсортированных карт находит изменившиеся столбцы.
Затронутые X-полосы читаются по одному разу; хешируются только грязные
Z-страницы. Порядок байтов каждой страницы идентичен полной сборке.
Старый/новый отпечатки сравниваются, пустая страница удаляется, правки
мира сохраняются в общем наборе инвалидирования поиска. Прежняя
семантика возможной коллизии FNV тоже сохраняется.

После создания/загрузки предыдущей карты ещё нет: первый print полный.
Неизменённая карта сохраняет прежний быстрый путь сравнения. Карта с
одной страницей при первом изменении использует полную сборку. Для
плотной дельты разведка прекращается при изменении не менее
`max(64, ceil(max(old_len,new_len)/16))` допустимых столбцов и более одной
страницы; выполняется полная сборка. Это эвристика стоимости, не квота
игровых изменений и не отсрочка инвалидирования.

Первый прототип без fallback на 65 536 столбцах при полном изменении
публиковал карту за 0,938 против 0,611 мс (+54%). Он не принят.
После адаптации микрозамер `micro-adaptive.log`: изменён первый столбец
той же карты — 0,611 против 0,062 мс; все изменены — 0,670 против
0,634 мс. Это синтетика, 32 измерения после четырёх прогревочных,
чередование порядка A/B; разные числа для одного полного пути показывают
шум короткого замера. Нулевая накладная цена на любой плотной карте не
обещается. Корректность обеих ветвей проверяется независимо от времени.

Воспроизведение синтетики:

```powershell
scripts/cargo-local.ps1 run --release --locked --offline -p nav --bin bench_rubble_print
```

## Профилирование и полный бой

Добавлены `rubble_print_begin/end`, вложенные в прежнюю фазу `rubble`.
В CSV измеряется весь участок публикации: сравнение, поиск дельты,
рабочие структуры, пересчёт, обновление print и замена старой карты.
`rubble_print_us` уже входит в `rubble_us`, складывать их нельзя.
В обычном исполнении observer пуст и часов в SIM нет.

Счётчики `changed_columns`, `dirty_pages`, `hashed_columns`, `full_builds`
диагностические, не сохраняются и не хешируются. Первые два считаются
только для законченной дельты. При раннем fallback частичная разведка
не выдаётся за полную: они нулевые, `full_builds=1`, `hashed_columns`
считает полный проход. Ноль `full_builds` при нуле dirty может означать
неизменённую карту, а не потерянную работу.

Полный reference включается только диагностическим
`--full-rubble-print` в `bench_battle`; обычный движок использует дельту.

## Что остаётся

Полная классификация resting-фрагментов, поиск опор стопок, сбор столбцов,
максимумы и rebuild дерева rectangle queries всё ещё выполняются.
Дельта print не является событийной картой завалов. Для неё нужны dirty
providers, скрытые вклады под максимумом, снятие дальних опор,
merge/reclaim, старые/новые области корпусов и полный oracle, включая
стоимость обслуживания и память. Само сравнение готовых карт линейное.

Полный ограниченный capture валки при `max_claims` и прогресс очереди
остаются следующей архитектурной работой. Этот малый независимый шаг
не исправляет потерю ещё не захваченных растений после ухода танка.
Покрытие столкновений после evict/tumble, EP-03, GPU-кэши с движущимися
препятствиями, group18 ≤100 тиков, пики взрывов, 5000 юнитов и 30-минутный
soak остаются открытыми. Отдельное ускорение публикации не закрывает
бюджет каждого тика/кадра.
