# Производный индекс поиска опор

24.09.2026, ADR-404, P-45. База — `c9ce76a`.

## Причина и изменение

На километровом полигоне при валке растительности граф обрушения
содержит 189 747 известных чанков, 379 654 локальных компоненты и
1 125 810 контактов. Поиск пути к опоре (`collapse_resolve`) на длинном
маршруте занимал около 15 мс на p99 своих вызовов. Граф проверял
133 519 чанков-кандидатов и каждый раз восстанавливал по спискам граней,
какие их компоненты уже имеют непосредственную опору.

Теперь принадлежность чанка множеству кандидатов хранится в плотном
индексе по номеру чанка. Локальные метки без прямой опоры вычисляются
при обновлении контактов: первые 64 представлены битовой маской, а
остальные — списком только у редких чанков с более чем 64 компонентами.
Обход кандидатов и меток остаётся по возрастанию номера. Индексы
производные: снимок мира пишет прежние узлы и после загрузки восстанавливает
кэш; формат сохранения и физические правила не изменились.

Первый опыт с отдельным `Vec` дополнительных меток в **каждом** узле
показал p99 `collapse_resolve` 9,388 мс в одном прогоне, но добавлял бы
24 байта к каждому известному чанку даже без дополнительных меток.
Итоговый вариант держит редкие списки в отдельной упорядоченной карте,
чтобы не переносить этот постоянный расход на потенциально большую карту.
Число 9,388 мс к итоговому варианту не относится.

## Измерение

Команда для всех прогонов:

```powershell
.\target\release\bench_range.exe --range data/range-km.ron --move 2200,336 --ticks 6500
```

Два прогона исходного исполняемого файла и два прогона итогового по тому
же маршруту, без выстрелов. Фазы обрушения выполняются не каждый тик;
их p99 считается только среди вызовов фазы. В таблице диапазоны двух
замеров, миллисекунды.

| Метрика | До | После |
| --- | ---: | ---: |
| p99 поиска опор | 14,977–15,052 | 13,081–14,335 |
| p99 полного CPU-тика | 18,910–18,984 | 17,263–18,226 |
| Снятые клетки | 128 349 | 128 349 |
| Круги четырёх патрулей | `0,5,1,5` | `0,5,1,5` |
| Итоговый хеш | `bb4a604c28e62856` | `bb4a604c28e62856` |

Выигрыш p99 поиска в этих прогонах — примерно 5–13 %, полного
CPU-тика — 4–9 %. Максимумы отдельных тиков не следует оценивать по
такой короткой серии: во втором итоговом прогоне был одиночный пик
50,5 мс в поиске. Рендер и GPU в стенде не измерялись. Бюджет
8,33 мс для 120 FPS пока не выдержан.

Исходный бинарник и сырые логи находятся в `out/backlog/adr-404`.

## Проверки

Тесты сравнивают поиск с полным эталонным обходом, циклический и
устаревший граф, метки за пределами 64-битной маски, а также
восстановление индекса и побитово одинакового снимка после загрузки.
Длинный замер подтверждает прежний хеш, снятые клетки и круги патрулей.
Прошли 131 релизный тест `voxel`, четыре golden-теста и 19 тестов
сохранения `sim-core`, полный `cargo test --workspace`, `clippy` для
`voxel`/`sim-core`, проверка форматирования и релизная сборка `blast`.
Контрольный `sim-cli --seed 42 --ticks 1000 --dump-hash` завершился
хешем `12bd9cb0d53498f2`.
Полный прогон репозитория также выявил прежний ложный отказ архитектурного
теста: он считал запрещённым членский `HashMap` индекса осевших обломков,
который вставляет и проверяет ключи, но не итерирует по ним. Для его точного
объявления добавлено узкое исключение; остальные хеш-контейнеры по-прежнему
отклоняются тестом.
