# Металл: связные панели вместо россыпи осколков

Повторная проверка и исправление пропущенного контактного пути —
[340](340-unit-destruction-review.md). Первоначальный срез339 сам по себе
не включал атомарную сборку в crush_face; она добавлена ADR-757.

19.10.2026. База main29f234c. ADR-756. Локальные артефакты:
out/metal-fracture-339/. Это изменение общей модели фрагментации,
а не настройка отдельного сценария.

## Причина и решение

Повреждённый корпус уже группировал снятые ячейки, но только внутри
малой коробки оружия1..4 вокселя на сторону. Общий small_piece_pct25%
дополнительно делил часть коробок. Для моделей с вокселем100 мм получались
кусочки до40 см; соседние части одной пробитой панели не соединялись
через искусственную границу коробок. Обычный World дополнительно разделял
фрагменты по отделке. Большие отрезанные секции уже существовали, но
выбитый взрывом материал в этот путь не попадал.

Добавлен общий body_fragments: пространственная разбивка и шестисвязный
обход только фактически снятых ячеек. body_fragment_mm1600 хранится
в sim.ron, независимо от грунтовых осколков. Общая модель обслуживает
World::export_body_damage и атомарные повреждения BlastRange, включая
бой с ИИ, баллистические/энергетические попадания и контактное дробление.
Разные юниты, детали, слои башни, роли подсистем и точные рамки не
объединяются. Отверстия сохраняются. Малые одноцветные формы используют
компактную маску; большие или многоцветные — существующий Chunk с исходной
геометрией и отделкой. Дополнительный формат snapshot не вводится.

В BlastRange массы/материя доноров переводятся первому контейнеру.
Средняя скорость равномассовых ячеек сохраняет импульс, потеря энергии
при объединении рассеивается; генерации энергии нет. В обычном World
энергия порции распределяется по объёму, сохраняя прежний конечный бюджет.
Стабильное удаление касается только нового хвоста: старые обломки
не переставляются, не свариваются и не пересобираются. Ноль настройки
оставляет прежний путь для контролируемого сравнения.

## Контролируемый замер

Новый bench_body_fragments пропускает одинаковые512 ячеек брони настоящего
танка через очередь повреждения World, затем отдельно исполняет600 тиков
общей физики обломков над одинаковым плоским полом, без других корпусов
и рендера. Политики0/1600 исполняет один release-бинарник; остальные данные,
снятые ячейки и энергия одинаковы. Rayon4, пять последовательных пар;

На этом входе тел при рождении меньше на91,82%, дальнейшая физика дешевле
в3,54 раза за весь прогон и в6,74 раза за первые120 тиков. Тик повреждения
немного дороже; новый поиск связности имеет цену. Это маленький контрольный
вход, не обещание такого же выигрыша всего движка или FPS. Исходный
перебор ячеек урона сохраняется. В BlastRange остаются временные поячеечные
доноры до атомарного объединения; прямое рождение панели одним контейнером
пока не реализовано.

При ранней проверке стенда найдена неверная единица gravity: API физики
ждёт ускорение за тик, а первая версия передавала значение за секунду.
Эти прогоны isolated-1..5.log и rejected-v1-gravity-bench.exe отвергнуты.
Итоговая сборка перепроверена в delivered-isolated-1..5.log:
gravity/TICKS_PER_SECOND², сводка delivered-physics-summary.json.
Предыдущие final-isolated-1..5.log и measurements-final.json сохранены
как замер той же SIM до финальной сборки рендера. isolated-correct-1..5.log и
prototype-world/reference относятся к версии до исправления phase room;
они сохранены как промежуточные, а не текущие результаты. Приведённая предварительно debug-оценка10x
не является итоговым результатом.

Траектории боя различаются: после изменения формы завалов другие
перемещения, выстрелы и повреждения; живых24/22 против21/23. Поэтому
это не равная по работе пара и не доказательство10%-го ускорения root.
Общая физика обломков здесь не подешевела: её продолжает насыщать грунт,
а секции стоят дороже компактных частиц. Рост числа секций также требует
контроля стоимости мешей в native; одно уменьшение общего количества
объектов недостаточно для вывода о FPS. Every-tick33мс не достигнут.

Остаются существующие консервативные контакты секций по границам, а не
точная повоксельная narrow phase. Новые секции сохраняют исходные вырезы
в геометрии/рендере, но это не обещание точной коллизии всех полостей.
Внутри атомарной порции резервы малых компонент консервативны; на её
завершении объединённые слоты возвращаются перед следующей волной или
кинетической работой той же фазы. Квоты не увеличены.
Грунт, стальные блоки, записанные непосредственно в ландшафт,
уже отрезанные цельные секции, жидкие продукты плавления и радиусы
оружия этой политикой не переписаны. Старые сохранённые обломки не мигрируют;
политика следующего повреждения берётся из текущих общих данных.

## Проверки

Целевые fracture14 прошли,1 диагностическая ignored. Покрыты все10 видов
юнитов и их навесные детали, границы источников, шестисвязность, сохранение
каждой снятой ячейки, массы, материи и конечной кинетической энергии,
неизменность старого settled prefix и побитовый snapshot round-trip крупных
фрагментов. Отдельные тесты проверяют отверстия, касание только ребром/
углом, край координат255 и вложенность коробок для разных масштабов.

Свежий Windows CLI600 при physics1/4/8 иRayon4 даёт одинаковый
01f7e33e10af3d47. Эталон намеренно обновлён совместно с docs/11-roadmap.md:
форма и число физических обломков меняют бой. Формат snapshot прежний.
Это проверка конечного хеша; новая полная сверка всех полей каждого тика
между пулами здесь не заявляется.

Повторный полный release SIM:1017 passed,0 failed,16 ignored.
Integration golden1, sectors6 и snapshot3 прошли. Release NAV129 и modding71
прошли. Финальный render library debug:139 passed,2 ignored; lifecycle5/5.
Архитектурные12 и документальные3 проверки прошли. Финальная release-сборка
полигона завершена; native результаты приведены ниже. План остаётся единым:
[OPT316](316-optimization-delivery-plan.md). Это изменение не закрывает
04/05 и общую кадровую/длительную приёмку.

Первый полный release SIM:1014 passed,3 failed,16 ignored. Два отказа
существующей матрицы cap0/1/3/64 нашли реальную ошибку нового пути:
phase-local room копировался до объединения. Теперь finish_body_batch
возвращает room с точным возвратом объединённых резервов; оба oracle
теста, включая смешанные грунтовые claims и частичное подтверждение,
прошли в debug без изменения своих проверок.

Третий отказ был в setup T1 concurrency fixture: при меньшем числе
обломков stock волна успевала завершиться в тик первых грунтовых правок,
и конкурирующая валка вовсе не запускалась. В этом специальном тесте
использован существующий slow_blasts256 с теми же параметрами у
восстановленной копии. Проверки реального прогресса обоих фронтов,
предела128 flying, материи, snapshot и потикового replay сохраняются.
Stock first-salvo tests не изменены; production скорость взрыва прежняя.

## Рендер крупных фрагментов

Проверка нового представления выявила лишнюю работу: section_to_mesh
клонировал и обходил полный исходный шаблон в обоих слоях даже для
нескольких десятков снятых ячеек. Теперь пустой слой пропускается,
для списка ячеек строится только локальная маска, а обход ограничен
bounds выбранных ячеек. Нормали, фаски,
UV, цвета, тангенты, индексы и исходный порядок граней сохраняются.
Полный render library debug:139 passed,2 ignored; новый oracle test
сравнивает все атрибуты с полным обходом для всех видов и навесных частей.

Работа рендерной очереди учитывает размер секции:1024 единицы за кадр,
64..512 за панель,512 за целый COW-корпус. Прежние две тяжёлые сборки
сохраняются, небольшие панели могут появляться быстрее. Если смена меша
(например, обугливание после гибели) ждёт бюджета, старый меш сохраняется
и следует актуальной физике. Ранее он удалялся перед проверкой бюджета.
Реальный draw-system test с48 секциями проверяет ограниченный приём
более двух малых панелей, сохранение всех сущностей при отложенной
замене, их движение и завершение обугливания. Lifecycle5/5 прошли, включая отдельную проверку цвета обеих сторон.
Первый запуск нового теста обнаружил неполный setup: одиночный
BlastRange::new не содержал units[0] для chunk.template0. Исправлен
fixture с явным источником Tank, production поведение этим не менялось.

После первого ограничения обхода ещё оставалось клонирование полного
шаблона для маленькой секции. В итоговом пути списка ячеек используется
локальный UnitVol по bounds фрагмента и исходный read-only шаблон для
отделки. Проверка соседа ограничена теми же bounds, без повторных
проверок диапазона внутри чтения маски. Полный COW-корпус сохраняет
прежний путь. Публичный body_to_mesh сохраняет полный диапазон.

Окраска панелей полигона теперь использует общий witness::body_tint
с исходным allied/id, а не neutral owner1 материального контейнера.
Правило исходных тел вынесено без смены его цветов. Общий mesher
section_to_mesh сохраняет прежний default tint для обычного World;
полигон передаёт собственную исходную окраску через tinted API.
Финальный bench_section_mesh:93 случая всех видов/навесных деталей,
128 исходных ячеек с отверстиями,12 раундов с отбрасыванием первых двух.
Полные хеши позиций, нормалей, цветов, UV, тангентов и индексов совпали
с замороженной версией до оптимизации. Сумма медиан случаев:
12,3682 →11,3128мс, примерно на8,5% меньше. Корпус Tank:256,6 →194,5мкс,
Strider:273,2 →164,9мкс, Spider:685,4 →188,4мкс, стационарнаяT3:
480,5 →166,1мкс. Некоторые малые детали медленнее; это равновесовая
синтетическая выборка, не частоты реального боя и не общий FPS.
Промежуточная версия только с bounds также сохранена отдельно.
