# 420 — Единая шкала при слиянии геометрии обломков

1 ноября 2026, ADR-820. Артефакты: `out/optimization-411/` и
`out/optimization-412/`.

## Контекст

После среза410 основная работа позднего ИИ-боя по-прежнему связана с обходом
истории фрагментов. В `debris_merge_groups` каждая попытка точного объединения
вызывала `Fx::from_ratio(mm, WORLD_MM)` для общей шкалы и повторно внутри обоих
`origin()`. Это три одинаковых fixed-point деления на попытку.

Сначала был проверен другой вариант: ссылки на уже сохранённую в `join_memo`
геометрию вместо повторного `Geometry::of`. Две пары по1600 тиков дали полный
тик35,870→36,530 мс (+1,84%), позднее окно +1,25%. Локальный выигрыш первой
серии не повторился. Вариант отклонён и в рабочее дерево не переносился.

## Изменение

`Geometry::join` вычисляет шкалу один раз и передаёт её в `origin_at` для обеих
геометрий. Проверка `self.mm == other.mm` предшествует этому пути, поэтому общая
шкала идентична прежним независимым вычислениям. Порядок вычитания, умножения,
деления и округления не изменён. Тестовый `origin()` сохраняет независимый расчёт
через прежнее отношение `mm/WORLD_MM`.

Выбор голов, доноров, границы HEADS, контакты, форма, позиции, материя, Ledger,
квоты и формат снимков не меняются. Зависимостей и новых игровых чисел нет.

## Воспроизведение

```bash
RAYON_NUM_THREADS=4 ./out/optimization-401/baseline/bench_battle-410.exe \
  --world --ai-vs-ai --ticks 1600 --physics-workers 4 --workers 8 \
  --tick-csv out/optimization-412/before-1600-1.csv
RAYON_NUM_THREADS=4 ./out/optimization-401/oracle-source/target/release/bench_battle.exe \
  --world --ai-vs-ai --ticks 1600 --physics-workers 4 --workers 8 \
  --tick-csv out/optimization-412/after-1600-1.csv
```

Полные обходы `Settled`, wake и merge сохраняются. Следующий кандидат —
active/dirty работа по изменившимся фрагментам с полной инвалидацией, а не
дальнейшее дробное сокращение арифметики без повторного профиля.
