## Blender: создание эффекта и экспорт изображений

`scripts/art_lab_effects.py` создаёт отдельную `.blend`-сцену с восемью
стадиями: начальная вспышка, огненный объём, растущая ножка, расширяющаяся
шапка, более прозрачный дым и низкое пылевое кольцо. Геометрия состоит из
кубических элементов; наружные грани собираются в меш без скрытых внутренних
граней. Это контрольный ассет для проверки процесса создания, не законченный
эффект ядерного взрыва основного полигона.

Рендер: Cycles CPU, 4 потока, 256×256, 64 samples, 8 PNG. Приоритет
BelowNormal, affinity на четырёх логических CPU. Сам рендер восьми стадий
занял **3,38 с**; отдельные кадры — примерно **0,19–0,68 с**. Это единичный
офлайн-замер, не цена эффекта в игре. Тяжёлый расчёт жидкости/дыма не запускался.

`scripts/art_lab_effects_pack.py` использует уже имеющийся FFmpeg 7.1:

- декодирует все PNG в RGBA и требует восемь различных кадров;
- проверяет непустое изображение, полностью прозрачный фон и частичную альфу;
- собирает `atlas.png` 1024×512, раскладка 4×2, ячейка 256×256;
- создаёт `atlas.json` с размером/порядком кадров и форматом альфы;
- создаёт `preview.gif` на тёмном фоне, примерно 3 кадра/с, как в исходной
  сцене: одна стадия занимает 8 кадров при 24 кадрах/с.

Последовательность и атлас проверены визуально. Проверки альфы находятся в
`out/art-lab-402/blender-fx/image-checks.json`, параметры и время — в `results.json`.
Исходник — `cubic-blast.blend`; PNG — в `frames/`.

Один такой атлас RGBA8 занимает **2 МиБ** без сжатия и без mipmaps.
PNG на диске и GPU-текстура имеют разную стоимость. Для игры ещё нужны
привязка кадров к времени, правильное смешивание альфы, защита от протекания
соседних кадров при фильтрации и проверка заполнения экрана прозрачными слоями.
Стоимость на игровом GPU не измерялась.

Практический вывод: этот путь полезен для отдельных клубов дыма, вспышек,
вторичной пыли и дальних LOD. У заранее отрендеренного гриба один ракурс;
приближение и движение камеры от первого лица обнаружат плоскую карточку.
Для основного близкого гриба сохраняется потребность в объёмной форме либо
нескольких направлениях/слоях. Атлас пока не подключён в игру.

## Effekseer: установка, редактирование и повторное открытие

`C:/Users/artyo/Tools/rts-vox-art/effekseer-1.80.7/`.
Архив 96 589 737 байт, SHA-256:
`6f059b9cce3a79c5bfe3df9c970cfe62fd72acf130083c7b81832d90f8d1335f`.
Digest совпал с официальным GitHub asset. Реквизиты — `effekseer-install.json`.
PATH и зависимости игры не менялись; редактор не добавлялся в автозапуск.

Проверен штатный CUI `Tool/bin/Effekseer.exe -cui`:

1. Загружен поставляемый `Sample/00_Basic/Laser01.efkefc`.
2. Созданы пересохранённый `.efkefc` и бинарный `.efk`.
3. Пересохранённый проект снова открыт; повторный бинарный экспорт совпал

4. Через публичные `Effekseer.Core.LoadFrom` / `SaveAsXmlDocument` прочитана

5. В копии изменены имена пяти узлов, жизнь первого узла 20 → 30 кадров и

6. Изменённый XML-проект открыт Effekseer, сохранён в `.efkefc`, экспортирован

Файлы изменённого теста: `edited-project.efkproj`, `edited-project.efkefc`,

Воспроизводимый стенд — `scripts/art_lab_effekseer.py` и

### Ошибка, которую нельзя пропустить в автоматической сборке

Отрицательный контроль с **несуществующим входным файлом** тоже вернул
exit code 0 и создал бинарный эффект по умолчанию. Это воспроизведено в
поставленной версии. Значит, только кода возврата недостаточно: вход проверяется
до запуска, выход — по структуре и содержимому. Наш стенд проверяет пять узлов,
заданные значения и повторный бинарный экспорт.

В pinned-исходнике `Program.cs` результат `Core.LoadFrom(input)` не проверяется,
а часть исключений печатается без изменения возвращаемого кода. В `Core.cs`
`LoadFrom` возвращает `false`, если файл не удалось загрузить. Это объясняет
наблюдаемый ложный успех; изменение исходников самого Effekseer не выполнялось.

### GLB эффекта — специальный контейнер

Effekseer экспортировал GLB, но в нём **0 обычных мешей**, данные находятся в
расширении `Effekseer`. Наличие расширения проверено разбором JSON-чанка.
Такой GLB нельзя автоматически принимать за стандартную модель нашего юнита
или готовый эффект для текущего renderer. Для воспроизведения нужен runtime,
понимающий расширение/формат, либо отдельно подготовленный визуальный ассет.
Интеграция нового runtime в Rust/Bevy здесь не делалась.

## GLB → EFKMODEL: потеря геометрии и проверенный обход

В конвертер передана оболочка тестовой машины из 401: один glTF-меш,
**3 material primitives**, **244 треугольника**. Обычный
`EffekseerResourceConverter.exe source.glb -o model.efkmodel` завершился успешно,
но сохранил только **20 вершин / 10 треугольников**, файл 1504 байта.

В исходнике версии 1.80.7 `GLTFLoader.cpp` цикл по `srcMesh.primitives`
каждый раз делает `resize` и записывает `dstMesh.faces` / `dstMesh.vertices`
с начала. Поэтому после цикла остаётся последний primitive одного меша.
Маленький размер файла здесь означал потерю модели.

Проверенный маршрут для этой модели:

```text
исходный VOX
→ Vengi GLB: withmaterials=false, withtexcoords=false,
             withnormals=true, withcolor=true
→ один mesh / один primitive / COLOR_0
→ EffekseerResourceConverter
→ EFKMODEL
```

Результат: **488 вершин, все 244 треугольника**, файл 36 136 байт.
В упакованных вершинах EFKMODEL проверены три цвета:
`(67,204,206,255)`, `(88,108,99,255)`, `(118,130,133,255)` — исходная видимая палитра.
Это структурная проверка геометрии/цветов; показ модели новым runtime не измерялся.
Исходные материалы/UV не объявляются сохранёнными: в этом маршруте используются
цвета вершин. Для текстурированной модели потребуется другой проверенный путь.
Масштаб этого тестового GLB задан в единицах воксельного исходника, как в 401;
при интеграции нужно отдельно согласовать перевод в метры и размер частиц.

## Что осталось и почему

MagicaVoxel, нативные VoxEdit и Blockbench установлены, но полноценные операции
мышью/клавиатурой в их GUI ещё не проверены. Действующий Windows Computer Use
автоматически активирует окно при вводе. Пользователь ранее просил исключить
перехват фокуса, поэтому в этом опыте выбран фоновый режим и задан вопрос,
разрешена ли короткая активация редакторов. Установка, `--help`, загрузка
образца конвертером и проверка веб-версии не заменяют такую GUI-проверку.

У Vengi есть официальный канал команд через named pipe / MCP, но в штатной
нативной сборке окно создаётся показанным; скрытое окно также влияет на цикл
энергосбережения. Принудительные патчи бинарника/самодельная инъекция ввода
ради объявления проверки успешной не делались. Для GUI останется короткий
сценарий: открыть наш VOX, изменить копию, сохранить, экспортировать OBJ/VOX,
сверить число клеток, палитру и импорт.

Для Effekseer отдельным следующим GUI-шагом остаётся Recorder: проверить
запись PNG/атласа и альфу штатным инструментом. Его наличие в документации
не объявляется успешно испытанным экспортом в этом отчёте.

## Повторение

Из корня проекта, с ограничением вызывающего процесса четырьмя CPU и
BelowNormal, как в 401:

```powershell
$blender = 'C:/Users/artyo/Tools/rts-vox-art/blender-5.2.3/blender-5.2.3-windows-x64/blender.exe'
& $blender --background --factory-startup --threads 4 --python-exit-code 1 --python scripts/art_lab_effects.py -- --out out/art-lab-402/blender-fx
python scripts/art_lab_effects_pack.py
python scripts/art_lab_effekseer.py
```

Последний стенд использует исходные ассеты 401, установленные portable Vengi /
Effekseer и PowerShell 7 (`pwsh` в PATH). FFmpeg берётся из существующего
`cache/video-tools/imageio_ffmpeg/binaries/ffmpeg-win-x86_64-v7.1.exe`.
Повтор не требует пересборки игры. PNG/GIF/BLEND и журналы лежат в
`out/art-lab-402/`, каталог игнорируется Git.
