# ADR-594 — повтор грунта без подготовки всех юнитов

Дата: 2026-10-06. Контекст: P-87, повторное ожидание старых Canister waves.

## Что измерено до изменения

ADR-593 убрал повторные полные пересчёты вместимости, но CPU tick почти
не изменился. Новые диагностические счётчики наблюдают builds,
units prepared, world resumes и builds avoided. Подготовленная единица
означает один HitFrames и один enclosing bounds для юнита, не количество
его сегментов, клеток или отдельных матричных операций. Счётчики не
входят в hash/snapshot и не выбирают работу; load сбрасывает AdmissionProfile.

Штатный world60,1800 тиков,8 navigation workers,8 Rayon workers:
20451 подготовка геометрии,1227060 подготовленных юнитов,17190 входов
с первым pending contact уже на мировом акторе. Каждый из этих повторов
заново готовил все60 юнитов до обращения к грунту. CPU battle_wave_step:
mean/p95/p99/max = 323/536/650/1816 мкс на вызов.
Итоговый hash с одной диагностикой1f697f865e6f8aa6, как у ADR-593.

## Изменение

При pending world actor и body_cursor=0 единственный текущий ground contact
выполняется до подготовки HitFrames/bounds. Общая ground_contact содержит
прежнюю операцию: живой материал и surface work, энергия, claim admission,
условный dig, dents/changed/queued. Deferred оставляет точный actor/subcell
cursor и неподтверждённую очередь, без оплаты. Успех продвигает один
actor; лишь последняя подклетка снимает первый pending hit. Если работа
осталась, строится обычная геометрия из frozen poses и живого тела.
Незавершённый локальный body cursor всегда использует обычный проход.
Ни новая порция advance_contacts, ни дополнительная работа фронта не
выдаются. Нет новой очереди, формата сохранения, физического лимита
или изменения силы оружия. Грунт при каждом повторе читается заново.

Проверочное step_contacts::<false> исполняет прежний порядок подготовки
перед всеми контактами; в production используется только <true>.
Операция грунта общая, поэтому проверка сравнивает порядок/курсоры и
не поддерживает вторую копию правил оплаты/урона. Замороженный before
дополнительно проверяет полное состояние настоящего боя до рефакторинга.

## Протокол и ограничения

Локальные frozen manifests, CSV и логи: out/fix594/. Рабочая сборка
сохраняет унаследованные WIP; before/after держат их одинаковыми.
Экспорт staged index квалифицирует только принадлежащую этому этапу
правку. Внешняя toolchain/SDK и весь dependency closure не аттестуются.

```powershell
$env:RAYON_NUM_THREADS = '8'
./scripts/cargo-local.ps1 run --release -p sim-core --bin bench_battle -- --world --ai-vs-ai --ticks 1800 --workers 8 --damage-trace --fire-trace --wave-trace --trace --focus-unit 40 --focus-every 150
```

Замеры — CPU headless, не GPU/native FPS и не камерный тест. Физический
пул продолжает задерживать ground admission; этот этап сокращает цену
ожидания, не завершает хвосты раньше. P-87 и165FPS остаются открытыми.

Новые проверки сохраняют требования реального ground claim, body damage
и остановки на локальном body cursor. Стенд сначала делает валидные
обычные размещения, затем тестовый компактный объём около грунта.
Он совмещён с world sample centres для старого point sampling. Первые
пробные стенды не доходили до проверок алгоритма из-за запрета размещения
в грунте и несовпадения центров точечного образца; production проверки
размещения и критерии реального попадания не ослаблены.


Пять новых проверок release прошли (resume-tests-final.log):
- Deferred грунта без подготовки юнитов, edge1/2/4 и point/local режимы,
  точный последний subcell, движение/наведение во время ожидания,
  возобновление после открытия вместимости и реальное повреждение тела;
- живой грунт: нулевой/малый импульс, недостаток энергии, дубликат claim,
  annihilation с pending claim, исчезнувшая клетка, работа без Matter;
- успешный повтор с продолжением оставшихся подклеток того же контакта;
- настоящее заполнение пула на body_cursor>0, повтор и завершение тела;
- сохранение/загрузка ожидающего world contact с теми же frozen poses.

Сравниваются state_hash, полные bytes range snapshot и контактов волны,
позы, surface_changed, body/ground admission и balanced Ledger. Счётчики
геометрии отдельно проверяют отсутствие подготовки только на безопасном
повторе; успешный partial contact и локальный курсор тела сохраняют её.
