# Прямой контакт с подтверждённой опорой

25.09.2026, ADR-411, P-45. База — `a769fbd`.

## Причина и изменение

Разбор графа опор при каждом активном тике перебирает метки без прямого
заземления. У большинства таких компонент уже есть сосед, путь которого
к коренной породе подтверждён. Прежний код и для них запускал общий
обход: очищал буфер, добавлял начальный узел, выставлял временную метку
и проходил цикл поиска.

Теперь перед запуском обхода проверяются непосредственные связи
начального узла. Если среди них есть подтверждённый сосед, узел сразу
считается поддержанным. Для остальных остаётся прежний обход со всеми
правилами для циклов и неподдержанных отделений. Кандидаты по-прежнему
идут в стабильном порядке; проверка не меняет мир, формат снимка или
правила разрушения. Пересборка нумерации также сохраняет длину рабочего
массива достижимости: `resolve` инициализирует все его элементы перед
чтением, поэтому предварительное обнуление было лишним.

## Замер

Два прогона базового и два нового release-бинарника на одной машине:

```powershell
.\target\release\bench_range.exe --range data/range-km.ron --move 2200,336 --ticks 6500
```

| Метрика | До | После |
| --- | ---: | ---: |
| p50 поиска опор, мс | 2,676–2,682 | 2,285–2,297 |
| p99 поиска опор, мс | 6,205–6,255 | 5,151–5,244 |
| p99 полного CPU-тика, мс | 9,252–9,322 | 8,410–8,426 |
| Снятые клетки | 128 349 | 128 349 |
| Круги патрулей | `0,5,1,5` | `0,5,1,5` |
| Итоговый хеш | `bb4a604c28e62856` | `bb4a604c28e62856` |

В 600-тиковом прогоне с энергетическим выстрелом p99 поиска опор
938 → 774 мкс; число снятых клеток 46 645 и хеш `c6373dfde61c255c`
сохранились. Общий p99 боевого CPU-тика в одной паре почти не изменился
(5,932 → 5,971 мс): его ограничивают иные стадии.

Это CPU-стенд без рендера и GPU. Общий p99 длинной поездки всё ещё
слегка выше 8,33 мс, а гарантия 120 FPS на всех кадрах не достигнута.
Бинарник базы и сырые журналы — `out/backlog/adr-411`.

## Проверки

Проверка поиска опор против полного эталонного обхода охватывает циклы,
устаревшие чанки, срезы и запекание. Длинный и боевой прогоны сохранили
хеши, число разрушенных клеток и маршруты. Полная проверка workspace,
clippy, форматирование, релизная сборка окна и контрольный хеш
симуляции выполнены при фиксации изменения.
