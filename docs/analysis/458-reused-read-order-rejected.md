# 458 — Reuse read-order capacity: отклонено

3 ноября 2026. Артефакты: `out/optimization-458/` и
`out/optimization-443/after-458.*`.

## Гипотеза

`read_contacts_inner` выделял `order` и, при resumes, `first/rest` на каждый вызов.
Derived `read_order/read_rest` сохраняли capacity между вызовами и очищались. Prefix и
stable body-first partition должны были остаться прежними.

## Проверки

- 19 contact-read тестов прошли.
- Во всех ordinary сериях совпали все35 нетайминговых полей.
- Все181 nuclear hash совпали, ledger сбалансирован, hash `ae3798a582873796`.

## Производительность

Ordinary серии оказались нестабильными: первая дала mean34,851→36,144 мс и позднее
окно51,250→51,029 мс. Вторая и третья содержали аномальные общесистемные замедления,
включая сотни миллисекунд в разных фазах и у baseline. Эти серии не используются для
оценки кандидата.

Nuclear оказался решающим:

| Показатель | ADR-827 | Reused read-order |
|---|---:|---:|
|Mean tick|17,548 мс|22,955 мс|
|Худший тик|38,080 мс|54,833 мс|
|Суммарный `read_ground`|173,537 мс|269,511 мс|
|Суммарный claims|559,703 мс|617,228 мс|

`read_ground` вырос на55,28%, mean на30,81%. Локальная capacity-оптимизация отклонена.

## Решение

Прототип полностью удалён, исходный `order/first/rest` восстановлен. Restored release
на200 тиках дал 0 расхождений. Строгий cumulative остаётся в
[454](454-cumulative-827-measurement.md). Этот путь больше не развивается.
