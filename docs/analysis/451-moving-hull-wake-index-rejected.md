# 451 — Moving-hull wake index: отклонено по общей стоимости

2 ноября 2026. Артефакты: `out/optimization-451/`.

## Гипотеза

В позднем бою wake вызывает `HullQueries::hit_moving` почти для всей истории,
хотя support-due составляет лишь часть фрагментов. Вместо per-fragment broadphase
прототип строил отдельный spatial index вокруг движущихся корпусов и обходил только
их кандидатов. Контактный `Settled` и его `want` не изменялись.

В index входили resting и flying non-chunk фрагменты. Overflow и чрезмерно большие
ranges сохраняли старый BVH fallback. Generation marks удаляли повторы ячеек.
Отдельный `contacted` flag сохранял семантику первого hull: climb/floor не разрешает
более позднему корпусу bulldoze-нуть тот же фрагмент.

## Корректность

- `a_moving_hull_bulldozes_a_lying_piece_out_of_its_way` прошёл;
- warm/cold join oracle прошёл;
- после восстановления старых diagnostic counters при отсутствии resting все 35
  нетайминговых CSV-полей каждого тика 1600 совпали;
- endpoint hash `ef96977a5b55489b` совпал.

## Производительность

World AI-vs-AI, 1600 тиков, physics4/navigation8/Rayon4:

| Показатель | ADR-825/826 | Wake index | Изменение |
|---|---:|---:|---:|
|Mean 1600|30,041 мс|30,454 мс|+1,37% (медленнее)|
|Позднее окно1201–1600|42,531 мс|43,202 мс|+1,58%|
|`debris`, полный бой|12,626 мс|12,991 мс|+2,89%|

В поздних окнах дополнительный `Settled` builder и candidate inversion не уменьшили
суммарную фазу wake. Например, на 1501–1600 wake составил 5,366 против 5,214 мс,
а `Settled` — 11,162 против 10,651 мс. Движущиеся корпуса охватывают слишком большую
часть мира: второй candidate builder не окупает более узкий обход.

## Решение

Прототип отклонён и полностью удалён. ADR-825/826 восстановлены; restored release
на 200 тиках дал 0 расхождений по всем 35 полям. Суммарные принятые метрики остаются
в [444](444-cumulative-825-measurement.md). Следующий анализ направлен в rubble и
другие крупные фазы, а не в ещё один вариант wake spatial index.
