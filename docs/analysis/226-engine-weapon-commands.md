# Настройки оружия через общий движок и восстановление боя

Дата: 08.10.2026. Продолжение EP-02a/02b после [225](225-engine-density-commands.md).
Контроль — frozen 225. Критерии заданы до изменения кода в
`out/engine-fixes-20261008/weapon-commands/acceptance.json`.

## Исправляемый дефект

Ползунки, пресеты и мощность меняли ExplosionConfig через прямой reconfigure.
Общий командный вход и переносимый checkpoint не знали об этом изменении.
Physical snapshot полагался на конфигурацию, переданную вызывающим кодом:
другой пресет при загрузке мог изменить дальнейшую физику. Сохранить только
текущую конфигурацию недостаточно: конструктор использует исходные значения
для мира, лимита правок и первоначальной конфигурации акторов.

Четыре максимума UI также превышали уже действующие пределы загрузчика:
material energy 4 млрд вместо 1 млрд, armour multiplier 100000 вместо 10000,
heat radius 64 вместо 32 и wave work 65536 вместо 8192. В частности,
pending kinetic loader уже отвергал multiplier выше 10000. Теперь UI
ограничивает ввод поддерживаемыми значениями; пределы движка не расширены.

## Решение и границы

`Command::ConfigureWeapon { config }` принимает полную типизированную
целочисленную конфигурацию. Это соответствует существующей логике UI:
любая строка собирает пресет, множитель мощности и все overrides вместе.
Названий сценариев и UI-пресетов в executor нет. Старый reconfigure стал
совместимой оболочкой над тем же обработчиком. Применение ограничено
проверкой фиксированного числа полей и копированием значения; обхода мира,
I/O и разбора RON внутри команды нет.

ExplosionConfig::validate вынесен из from_ron без изменения поддерживаемых
границ. Стойкость мишеней принадлежит layout и нормализуется до проверки,
как раньше. Ошибочный ввод отвергается целиком, равный возвращает Unchanged.
Applied сохраняет признак владения конфигурацией, который переживает reset.
Один вызов executor создаёт один результат в доступном battle capture.

Snapshot58 содержит initial и current config перед layout. Конструктор
восстанавливает исходный мир, затем устанавливается текущая конфигурация.
Внешний аргумент config для этой версии не определяет состояние. Явный
material format 0/56/57 сохраняет независимость истории плотности; прежние
опциональные настройки обломков/ходовой и физические хвосты продолжаются.
Миры без применённой ConfigureWeapon сохраняют старые байты/hash, включая
прежний контракт внешней конфигурации для legacy save. Одного rejected/no-op
ввода недостаточно для перехода на v58. Старые executable не читают v58.

Portable checkpoint v1 использует tag5, нулевой reserved target и тот же
явный little-endian codec полной конфигурации. Неизвестные enum/option tags,
ненулевой reserved target и обрезанные данные отвергаются. Структурно
корректная pending команда с недопустимым игровым значением загружается:
она должна получить Rejected при исполнении, как до сохранения. Applied
snapshot дополнительно проверяет игровые границы initial/current.

Семантика уже начатого выстрела не заменена новой. Полёт и волна продолжают
читать live config в прежних местах; параметры отложенного кинетического
урона остаются захваченными при попадании. Настройки этого орудия не меняют
таблицы оружия AI-акторов. Изменение config.edits_per_tick не перестраивает
начальный лимит World. Поэтому сохраняются обе конфигурации, а не только
текущие числа панели. Общий lifecycle и унификация gun/actor path остаются
отдельными задачами; этот пакет не объявляет их завершёнными.

## Проверки и измерения

Новые проверки охватывают Applied/Unchanged/Rejected без частичной мутации,
layout-owned стойкость, сохранение reset, initial/live limits с layout и без
него, все сочетания material prefix/motion/debris, enum/option tags и каждую
точку обрезания config codec. Отдельные физические проверки сохраняют мир
во время полёта и активной волны, сравнивают отложенный кинетический урон
с исполнением без искусственного ограничения вместимости и продолжают
240-тиковый бой с pending, повторным, невалидным вводом и reset.

Существующий тест полёта огнемёта требовал равенства hash при разном
shell_speed. После включения config в авторитетное состояние это неверное
ожидание. Тест теперь сравнивает полный физический результат после
выравнивания config в конце полёта и отдельно требует равное продолжение
восстановленного мира с изменённой скоростью. Первый лог сохранён в
`headless-tests-first.log`. Проверки физического урона не ослаблены,
золотые файлы не обновлялись. Ошибка нового стенда capture вне battle mode
также исправлена до окончательной квалификации.

UI-проверки проходят через настоящие actions: все 13 строк, четыре
исправленные числовые границы, reset, семь пресетов и четыре мощности.
Paused rebuild создаёт мир с уже собранной effective config; повторного
применения weapon overrides на следующем кадре не требуется.

Release sim-core/nav/modding: **984 pass, 0 fail, 6 ignored**. Blast UI:
**157 уникальных pass, 4 ignored**. Полный UI-прогон дал 156 pass и один
отказ нового стенда: ButtonInput::clear оставлял Enter нажатым и повторное
press не создавало событие. После замены на reset(Enter) отдельно повторён
этот тест: 1 pass, 0 fail. Оба лога сохранены, qualifier требует совпадения
единственного исходного отказа и успешного повторного теста, не суммирует
дубли. Игровой код при исправлении стенда не менялся.
Architecture: прежние **5 pass / 4 fail, 46 нормализованных диагностик**,
без добавлений/удалений. Открыты render writes, floats, hash containers,
clock; перенос одного writer не закрывает эти проверки целиком.

Цена value-команды измерена через size_of собранных типов на x64. Старые
объявления взяты из замороженных исходников 225; raw — footprint.rs/.ll.

| Тип | Было, байт | Стало, байт |
|---|---:|---:|
| Command | 40 | 200 |
| Envelope | 72 | 232 |
| Receipt | 96 | 256 |
| Capture Record | 64 | 224 |

ExplosionConfig занимает 200 байт. При 1024 удерживаемых результатах это
256 KiB вместо 96 KiB payload, плюс неизменные служебные структуры.
Размер всех вариантов Command вырос, включая обычный приказ. Поля config
лежат внутри enum, без отдельной heap allocation под них; вместимость
очереди ограничена Limits. Этот
компромисс требует явного учёта при дальнейшем production journal/owner,
а не предположения, что value переносится бесплатно. Обычный stock бой
и захват команд — разные нагрузки; native gate ниже проверяет обычный бой.

Три последовательных stock боя по 3600 тиков, 60 юнитов, 8 physics /
8 navigation workers: frozen 225, кандидат и кандидат с late restore
3300→3600. Совпали **все 25 нетайминговых полей каждого тика**, shots/damage,
alive [26,21], базы [100,100], peak_rounds=30 и hash **`5dd0c782d2b2f557`**.
Mean step: **13,641 / 13,562 / 13,351 мс** соответственно. Разница первого
кандидата с контролем −0,58% не доказывает устойчивого ускорения. Эти бои
проверяют прежний путь без новых настроек; исполнение и restore новых
команд проверены отдельно перечисленными выше физическими тестами.

## Игровое окно

Заранее задана одна ordinary пара по 120 секунд, control → кандидат,
1600×900, AutoNoVsync, 8 physics / 8 navigation / 4 compute workers.
Настройки закрыты, GPU/core trace выключен. Сборка и тесты завершены до
замеров. Допуск: FPS ≥97% контроля, p99 ≤103%, обязательны valid/eligible,
3600 тиков и прежний hash. Одна пара служит проверкой регрессии и не
доказывает ускорение. `--require-valid` и итоговая qualification подтвердили
оба запуска и соответствие executable паспортам.

| Метрика | Frozen 225 | Кандидат 226 |
|---|---:|---:|
| Mean FPS | 71,8 | 72,7 |
| p95 кадра, мс | 30,964 | 30,608 |
| p99 кадра, мс | 33,337 | 33,154 |
| Max кадра, мс | 49,848 | 51,037 |
| Simulation realtime ratio | 0,9996 | 0,9996 |

Допуск 3% пройден: FPS +1,25%, p99 −0,55%. Оба запуска завершили
3600 ticks/120 s с hash `5dd0c782d2b2f557`. Max вырос на 1,189 мс.
Одна пара не устанавливает устойчивость разницы или причину редких задержек.
**Ускорение не доказано, 165 FPS не достигнуты.** Исправление закрывает
владение live weapon config и его восстановление, без отдельного алгоритма
для сценария. Rustfmt check и git diff --check пройдены.
