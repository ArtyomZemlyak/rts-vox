## Следующие законченные результаты

1. **Грунт принимает реальные куски.** Bounded точная маска, actual conditional edits,
   резервирование компонентов и согласованный transfer; conservation, энергия,
   no-op/мост-компонент/перекрытия, worker/save/replay. При временно полном pool после
   освобождения работа продвигается. При постоянно полном хранилище нужен доказанный
   путь точного уплотнения/явный supported envelope, а не вечный retry или sink материи.
2. **Независимые обрушения не ждут весь бой.** Точные владельцы изменений и связанные
   конструкции/опоры за границами чанка; готовая область обрушивается, пока в другой
   ещё работает волна. Проверка после confirm не видит устаревшее ожидание, но ownership
   не теряется. Валка получает компактный справедливый фронт и проверку useful progress.
3. **Окно получает согласованное состояние движка.** Оставшиеся terrain/occupancy,
   distant/minimap, pose/geometry/effects readers переводятся на owned export.
   Экспорт измеряется по bytes/copy/free/retained memory, затем sim owner вне кадра,
   reset/cancel/save/shutdown и recovery. Долговременный journal развивается отдельно;
   его отсутствие не повод откладывать все readers и физические исправления.
4. **Уменьшается стоимость живой работы.** Active/support/rubble/motion/nav кандидаты
   принимаются по актуальному профилю, целому tick и command-to-visible. Один быстрый
   сортировочный kernel или lookup не закрывает historical walks и общее время кадра.
   Для ИИ — сначала исполнимые цели и повторные отказы, затем тактические усложнения.
5. **Появляется новая итоговая приёмка.** Ordinary native paired runs без capture/
   диагностической нагрузки, тот же состав/качество/30 Hz/physical result, все попытки
   сохранены. Отдельно — 30 минут боя, 20 reset/restart, memory categories/transient peaks,
   input→admit→apply→route→visible, save во время незавершённой работы. Старые FPS и
   headless миллисекунды не заменяют эту приёмку; цель 165 FPS ещё открыта.
6. **Сценарии полностью становятся данными.** Runtime team/owner/objectives, один gun/
   battle физический контракт, список возможностей legacy World и миграция consumers.
   Только затем 64/128/256/512/1000/5000 материальных сущностей на общем kernel;
   10 км — отдельный paged world/coordinate/nav/save этап. Константу cap64 нельзя просто
   увеличить и назвать масштаб доказанным.

P-74/ADR consistency исправляются отдельным проверяемым срезом перед использованием
новых миграций как «зелёного» gate. Точный retry guard уменьшает CPU, не устраняя
нехватку физического представления. GPU-газ/публикация не изменяют авторитетный урон.
Смена ticks admission/collapse намеренно может поменять hash: новый контракт сначала
доказывается независимыми проверками. Чистые оптимизации сохраняют старый результат.
