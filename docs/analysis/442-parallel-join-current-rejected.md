# 442 — Параллельное построение join current: отклонено

2 ноября 2026. Артефакты: `out/optimization-442/`.

## Гипотеза

`Memo::current` строится последовательно по всей истории. Вычисления `Geometry::of`
и полного pile key независимы для каждого фрагмента. Прототип использовал Rayon
`par_iter().enumerate().filter_map().collect()` для больших входов; indexed collect
сохраняет прежний порядок ID и diff.

## Проверки

- Warm/cold после merge и sorted/hash/unsorted тесты прошли.
- Release-сборка прошла.
- Все36 нетайминговых полей каждого тика совпали; hash `ef96977a5b55489b` прежний.

## Измерения

Baseline `out/optimization-439/baseline-825.exe`, SHA-256
`ccfe075969c4c853a2a4b21398f7b6b9bd1aa0511cef9a053dc87beaed0cd991`.
World AI-vs-AI,1600 тиков,physics4/navigation8/Rayon4, порядок «после/до».

| Показатель | Baseline | После | Изменение |
|---|---:|---:|---:|
|Полный mean|31,994 мс|33,095 мс|+3,45%|
|Позднее окно1201–1600|45,872 мс|47,612 мс|+3,79%|
|`debris`|13,794 мс|14,662 мс|+6,29%|
|`merge_keys`, позднее окно|2,888 мс|4,387 мс|+51,91%|

Параллельная диспетчеризация и indexed collect оказались дороже последовательного
cache-friendly прохода. Обратная серия не оправдана отрицательным результатом.

## Решение

Прототип отклонён, runtime возвращён к ADR-825. ADR не создаётся. Не распараллеливать
этап только потому, что элементы независимы: размер задачи и стоимость сборки
результата важнее теоретического parallelism.
