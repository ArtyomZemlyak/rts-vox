# 585 — Быстрый цикл проверки механики

13.11.2026. Продолжение инструментов 580 и замечаний ревью 584.
Изменены запускатели и документация; игровой Rust, данные баланса и release
в этой работе не менялись. Пересборка игры ради изменения Python не требуется.

## Что уже использовалось

Отдельный sim-test без LTO, настоящий движок без окна/ожидания тика,
точные имена из inventory, SHA executable и проверки restore/workers.
CSV/HTML/SVG позволяют смотреть записанную походку без новой симуляции.
Эти средства уже применялись при проверках 581–583. Однако слишком широкие
повторы и преждевременные release-сборки продолжали удлинять рабочий цикл.

## Что добавлено

- `movement-quick`: 21 SIM + 5 nav проверок походки, отзывчивости старта,
  лесного склона, ступеней, нового кратера и упрощённой опорной сетки.
- `--reuse-passed`: Cargo сначала проверяет актуальный executable; затем
  разрешено использовать подтверждённое исполнение неизменных тестов.
  Проверяются SHA executable, окружение сборки, SHA самого запускателя,
  покрытие точных имён и целостность журнала реального исполнения.
- Переиспользование разрешено только для явно перечисленных модулей механики
  SIM и nav/fx. Внешние файлы/документация/preview не кешируются этим способом.
  Результат отмечается `reused_passed`, рядом копируется доказательство.
  Новый фактический запуск сначала отменяет старый pass: сбой/timeout не
  оставляет прежнюю зелёную запись пригодной к переиспользованию.
- Fingerprint дополнен прямыми литеральными include_str/include_bytes:
  например, `docs/07-economy.md` теперь инвалидирует `--no-build`.
  Не утверждается полное покрытие внешнего компилятора и сложных макросов.
- `motion-lab --kind commander` запускает одну проблемную модель с теми же
  300 тиками и проверками сохранения/повтора, без отдельной физики.
- Каждый опыт создаёт собственную папку `runs/<id>`. Проверяется точный набор
  восьми staged snapshots на каждую выбранную модель. Старые снимки в папке
  вывода не могут скрыть незавершённый запуск. После проверки обновляются
  совместимые копии CSV/snapshots в корне папки вывода.

## Проверка

Артефакты: `out/unit585`. Реально выполнены 26 проверок короткого набора;
отдельно выполнен повтор с подтверждённым переиспользованием. Никакие
переиспользованные результаты не прибавляются к числу новых исполнений.

Предварительно измеренный короткий цикл: 17,63 с фактического запуска →
2,10 с подтверждения неизменных результатов. Сборка актуальных тестовых
программ занимала около 0,4–0,5 с на пакет. Это не обещание такого времени
после любой Rust-правки: её компиляция остаётся отдельной ценой.

Свежий одиночный terrain-опыт Commander: 4,61 с всего, 2,98 с SIM;
300 тиков, snapshot на 45, затем побитовая сверка 1/2 workers и остановки.
Hash `5e2e44ea7ac49be7`, 38 отрывов, минимум одна planted-опора, ноль тиков
без неё. Время запуска зависит от текущей нагрузки, не является FPS игры.

Проверки инструментов: 10 runner + 3 motion-lab + 4 gait-report, все пройдены.
Отрицательные случаи включают опечатку модели, старые snapshots вместо
недостающих новых, изменённый executable/runner/окружение, испорченный журнал,
нулевое/частичное/ignored-only исполнение и изменение включённого канона/WGSL.
Документальные проверки: 3/3. `git diff --check` проходит.

## Рабочий порядок

Локальная регрессия → короткий набор → расширенный набор по затронутому
контракту → одна финальная release-сборка. Для изменений соседей/порядка фаз
обязателен serial/deferred и worker parity, короткого набора недостаточно.
Для визуала — записанная трасса и нужные native-кадры. Для производительности
игры — отдельный 4К бой с min/mean/max и перцентилями; он не запускается ради
каждой правки и не заменяется таймингом headless SIM.

Ограничение CPU/BelowNormal и скрытый запуск сохранены. Эти Python-изменения
не требуют открытия игры, захвата фокуса или повторной 9-минутной сборки release.
