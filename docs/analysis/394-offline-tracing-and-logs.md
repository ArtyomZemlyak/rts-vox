# Офлайн таймлайн и журнал тяжёлых кадров

24 октября 2026. Артефакты: out/tracing-394. Игровой Rust-код, сетка,
частота SIM, материалы и настройки данных не меняются.

## Что добавлено

`analyze-range-profile.py --trace` после обычного анализа создаёт:

- `world-battle.trace.json`: Chrome Trace Event JSON для Perfetto;
- `world-battle.slow-frames.jsonl`: все наблюдавшиеся интервалы кадра ≥50 мс;
- `world-battle.trace-export.json`: источник, бинарник, хеш состояния,
  контекст окна, выбранные окна, число событий, лимит и потери.

`profile-range.ps1 -ExportTrace` вызывает этот экспорт после завершения
всех игровых процессов и OS sampler. Экспорт не добавляет instrumentation
в игру. Опции CorePhases/RenderTimeline сохраняют свои прежние накладные
расходы и диагностический статус. Экспорт не повышает eligibility замера.
Существующий каталог с raw или производными артефактами сохраняется:
повторный capture требует нового Output. Ручной повтор анализа позволяет
пересоздать производные файлы из прежних CSV.

Таймлайн содержит интервалы begin-to-begin, измеренный Update и следующий
промежуток, внешний тик, интервалы границ фаз, детали, реально сохранённые
задачи воркеров, render stages и Bevy tasks при наличии соответствующих
проверенных источников. Счётчики очередей показываются в конце Update.
Слоты/акторы, generation, tick, source row и OS thread сохраняются в args.

Метаданные обозначают дорожки как логические интервалы wall time.
Вложенные задачи одного OS thread размещаются вместе; пересекающиеся
observer scopes получают отдельную дорожку. Это обеспечивает корректную
вложенность Chrome JSON без тысяч дорожек по каждому актору.
Агрегированные physics totals не превращаются в выдуманные интервалы,
незакрытые render spans показываются точкой без выдуманного конца.
Необъявленные CSV рядом с каталогом не подмешиваются в экспорт.
GPU publication samples не имеют общего placement clock и не изображаются
как интервалы GPU или доказанное ожидание видеокарты.

JSONL привязывает длительность кадра к предыдущей строке Update,
сохраняет диапазон тиков, число шагов, core wall, компоненты и текущие
размеры очередей. Последний Update не получает выдуманного следующего
интервала. Bevy delta, который может запаздывать через pipeline, для
отбора тяжёлых кадров не используется. Вложенные компоненты не суммируются.

По умолчанию экспортируются окна вокруг 12 самых тяжёлых интервалов,
с контекстом ±250 мс. Окна сливаются, их исходные номера строк сохраняются.
Интервалы, пересекающие окно, сохраняются целиком с исходными временами.
JSONL охватывает весь capture независимо от фокуса таймлайна.
`--trace-all` включает полный таймлайн, `--top` задаёт число тяжёлых кадров,
`--trace-context-ms` задаёт контекст. Лимит500000 относится к данным;
метаданные дорожек не занимают его. `filtered_outside_focus` и
`dropped_events` различают выбор окна и настоящее переполнение лимита.
Бюджетный срез явно помечен truncated; исходная валидность capture
от этого не меняется. JSON пишется через временный файл и атомарную замену.

## Исправление сравнения входов

PowerShell5 и7 по-разному сортировали некоторые имена с пунктуацией.
Из-за этого одинаковые path→SHA256 отклонялись как разные InputHashes.
Runner теперь сортирует пути через StringComparer.Ordinal, независимо
от культуры. Analyzer сравнивает записи по Path без изменения исходного
списка. Дубликаты, неверные SHA/Exists и отсутствующие записи отклоняются;
смена пути, хеша, признака наличия и неизвестных полей остаётся различием.
Регистр и разделители пути не нормализуются как предположительные alias.

Старая первая пара393 fps-before/fps-after после исправления корректно
проходит сравнение: eligible=true, fps_acceptance_eligible=true. Это
исправление представления метаданных, не новый FPS и не смена входов.
Исходный отказ сохранён в out/optimization-393/first-pair-rejected.analysis.json;
повторная проверка — out/tracing-394/verification.json.

## Проверки и реальный прогон

oracle, экспорт времён, вложенных/пересекающихся scopes, фокус/полный режим,
переполнение бюджета, открытый render span, незаявленные CSV, наследуемые
часы, неверные параметры и нарушенные пары меток. Тесты используют отдельный
TEMP внутри workspace; системный sandbox TEMP недоступен этому процессу.
PowerShell suite прошёл в Windows PowerShell5 и PowerShell7, включая
ordinal sorting для ru-RU/en-US/tr-TR и синтаксис runner.

Реальный native capture:60 с,1200 тиков, AI vs AI,62 исходных актора,
Vulkan RTX5090, запрошены3840×2160/Maximized, клиент3840×1949,

не соответствовал новому exe. Он не удалялся и проверка не ослаблялась.

Валидность evidence=true, realtime=true, reasons=[], state_hash
`d2cae11030043979`, RenderContext неизменен. Этот диагностический прогон
не является допустимым замером FPS; общая производительность игры здесь

## Запуск

Для уже проверенного бинарника этого среза, из корня проекта:

```powershell
$env:WGPU_BACKEND = 'vulkan'
& ./scripts/profile-range.ps1 -Seconds 60 -Scenarios world-battle -SkipBuild -BinaryPath out/optimization-393/after-game.exe -Output out/performance/trace-next -SavedTuning -NavigationWorkers 8 -PhysicsWorkers 4 -RayonWorkers 4 -ComputeWorkers 4 -WindowWidth 3840 -WindowHeight 2160 -Maximized -CorePhases -RenderTimeline -ExportTrace
```

Output должен быть новым каталогом. Для новой версии игры сначала
подготавливается её отдельный бинарник и доказательства сборки через
`build-range-variant.ps1`, затем указывается соответствующий BinaryPath.

Экспорт уже записанного прогона без запуска игры:

```powershell
python scripts/analyze-range-profile.py out/tracing-394/native-diagnostic --trace --require-valid
```

Весь capture: добавить `--trace-all`; более широкий фокус:
`--top 20 --trace-context-ms 500`. Лимит: `--trace-event-limit 1000000`.
Для runner лимит задаёт `-TraceEventLimit 1000000`.

Открыть https://ui.perfetto.dev и выбрать Open trace file → локальный
world-battle.trace.json. В этом срезе данные никуда не загружались.
Поддержка формата и ограничение вложенности:
[официальная документация Perfetto](https://perfetto.dev/docs/getting-started/other-formats).
Это инструмент визуализации записанных событий; стеки OS/драйвера
и причины ожиданий требуют отдельного системного профайлера.
