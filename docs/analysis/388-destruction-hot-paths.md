# Точные сокращения работы разрушений и публикации рельефа

24 октября 2026. Продолжение профилирования387, ADR-804.
Размер вокселя, SIM20 Гц, давление, урон, квоты и игровые данные сохранены.

## Что изменено

Полностью удержанная глубиной почва проверяется и в малых ячейках волны.
Почва с отверстиями получает точное доказательство по живым упакованным
индексам. Генератор подтверждает только нетронутые части; полностью
материализованный объём обходится без процедурной справки.
Проверка работает с4/8/16 битами на индекс, частичными словами и краями
чанков; старые чужие записи палитры и материал вне запроса не мешают.
Неподтверждённая область сохраняет подробный путь. При применении
контакта нагрузка проверяется снова; геометрия тел не исключается.

Публикация правок в видимый объём больше не просматривает все тела для
каждой клетки. Временный direct-mapped кэш64 областей32³ хранит полный
ключ и кандидатов в исходном порядке. Коллизия перестраивает корзину.
Прежние точный габарит и u.solid выполняются для каждого кандидата.
Это размер технической корзины, не изменение размера куба мира.

Снятые клетки одного тела разделяют кадры корпуса и башни. Для пакетов
от32 клеток осевые слагаемые точного Frame::world вычисляются по одному
разу на координату оси. Последовательность сложений, fixed-point
деление, вращение и округление те же. Малые пакеты обходятся без таблиц.

В горячем material_kinds вместо очистки1024 слов на каждую ячейку
обычные ID собираются в одном u64. Первый большой ID переносит уже
собранные младшие виды в прежний полный набор без повторного чтения
префикса. Холодная функция не встраивается: её8КиБ scratch не попадает
на обычный путь. Состав видов, их порядок и проверка стоимости прежние.

Пакетное чтение колонок также распространено на ячейки2–4. Их буфер
занимает16 u16 вместо4096 u16 большого пути. Генератор готовит X/Z
один раз для нескольких Y; изменённые данные берутся теми же точными
строками чанков. Независимый dense oracle расширен на размеры2/3/4,
дырки, высокие ID и границы мира/чанков. Инструментированный генератор
для2³ подтвердил4 подготовки колонок вместо8 скалярных запросов.

Пустоты под перекрытиями/кронами отсеиваются по точной живой карте
занятости после прежней проверки потолков. Сохраняется прежняя форма
пустой маски и посещение контакта; материалы не генерируются.
Отдельный тест подтверждает ноль material/column-запросов в пустоте
под крышей и правильный результат сразу после добавления в неё вокселя.

## Уточнение стоимости чтения

В исходном core capture tick911 содержал743 material-пакета:
14,621 мс суммарных material spans,2,683 мс упаковки и0,664 мс proofs
внутри19,187 мс read_ground. В raw core CSV сохраняется только самый
длинный scope семейства на поток/этап:0,170 мс одного material span
нельзя принимать за полную стоимость чтения. Полные счётчики находятся
в world-battle.physics.csv. Эти диагностические вложенные интервалы
не складываются с родительским read_ground повторно.

## Отвергнутый вариант пакетов

Попытка увеличить целевой объём read-ahead с16384 до65536 вокселей
и объём задания с512 до4096 сохраняла точные результаты, но не дала
нужного сокращения пика. В изолированном полном грунте с ребром9
медиана148,8→206,7 мкс; другие случаи улучшались. Обычный capture
fps-dispatch дал93,9 FPS,1% low19,9 и худший кадр110,335 мс против
105,804 мс промежуточной версии до этого опыта. Это по одному capture
с шумом времени, однако воспроизводимой пользы для главного рывка нет.
В итоговой сборке исходные размеры пакетов и заданий восстановлены.
