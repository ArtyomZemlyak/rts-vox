# 323. Независимые запросы опор к замороженному индексу

Дата: 2026-10-18. Продолжение [322](322-rubble-column-spans.md),
активная очередь — [316](316-optimization-delivery-plan.md), OPT316-04.

## Что меняется

После построения `Settled` карта завалов последовательно проверяла каждый
кандидат `stacked` методом `supports`. Эти запросы не изменяют ни таблицу,
ни куски, ни мир: каждый ищет существующую верхнюю грань под одним куском.
Последовательная зависимость между ними отсутствует. В базовом повторе
World6000 окно2401..6000 тратит на этот parent1,027 мс/тик.

Большой список запросов разбивается на indexed пачки по256 исходных
индексов. Пачки читают один замороженный `Settled`; внутри запроса прежний
порядок клеток и контактных источников. Объединение списков поддержанных
кусков идёт по порядку пачек. Параллельная ветка выбирается при не менее1024
запросов и более одного потока уже существующего пула. Малые наборы и один
поток оставляют прежний последовательный фильтр без временного списка.

Параллельный путь выделяет временные списки успешных source IDs по пачкам;
их суммарная память линейна числу запросов. Dispatch, аллокации, ожидание
и объединение входят в parent query и end-to-end замеры. Нового
долгоживущего геометрического индекса нет; снижение RSS/VRAM этим срезом
не заявляется.

Это параллельное чтение одной фазы, не межтиковый индекс и не кэш ответов.
Построение membership и проверка текущих world/hulls выполняются полностью.
Приземление, wake, push, evict и изменение мира сюда не переносятся.
Квоты, геометрия поддержки, толщина плиты, данные оружия и формат snapshot
сохраняются. OPT316-04a/04b этим не закрываются.

observer приведён ниже. Диагностика хвоста — `tail-diagnostic.json`.

`--profile-rubble`, с новыми именами CSV/log. Артефакты `ordinary-*` отделены
от диагностических `before/after-a/b`.

полный drain валки, худший тик≤33 мс, native165 FPS, редкие секундные
фризы и длительный memory/VRAM soak остаются отдельными задачами плана.
