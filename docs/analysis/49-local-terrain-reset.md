# Локальная правка геометрии и сброс повреждённого мира

23.09.2026, P-49 / ADR-351. Продолжение [замеров действий](48-range-interactions.md).
Release, та же машина и километровая карта 10000×192×10000. Ручной стенд
`bench_range_interactions`, журналы `out/interactions/one-block-before.log`,
`one-block-after.log`, `heavy-damage-before.log`, `heavy-damage-ceiling.log`.
Отдельный стенд сброса — `bench_range_reset`.

Редактирование материала первого блока пересчитывало все авторские блоки
полигона, даже в удалённых секторах. Теперь упорядоченные списки блоков и
пандусов сравниваются по общему началу и концу; восстанавливаются области
только изменённой середины. Это сохраняет порядок наложения при вставке,
удалении и перестановке. Зоны и расчистка обрабатываются как прежде.

Сброс после повреждений пересчитывал полную высоту каждой затронутой
колонки, даже если правка была только в нижнем чанке. Теперь полный
пересчёт остаётся для изменённой авторской геометрии, а боевой урон
восстанавливает лишь реально материализованные слои Y. Верх колонок
считается по восстановленным битам; нетронутые слои выше последнего
повреждённого слоя сохраняют прежний верх. Очереди, урон и обломки при
сбросе по-прежнему исчезают.

| Действие | До, мс | После, мс |
|---|---:|---:|
| Изменить материал одного блока | 199,0 | 10,9 |
| Вернуть материал | 200,3 | 12,7 |
| Сбросить 100 повреждённых чанков в прогретом стенде рендера | 47,5 | 23,5 |

Для последней строки стенд снимает по одному вокселю в 100 разных чанках
боевого участка, затем сбрасывает опыт. Время подготовки повреждений —
около 19 мс и в таблицу сброса не входит. Это контролируемая нагрузка
на восстановление, а не замер целого взрыва. Промежуточный вариант со
сканированием потолка от самой верхней строки дал 24,4 мс; ограничение
сканирования последним восстановленным слоем дало 23,5 мс. Обычный
сброс без повреждений остаётся около 10 мс в том же стенде.

Отдельный процесс `bench_range_reset` на той же карте и тех же 100 чанках
дал **50,8–51,3 мс** на полный сброс в трёх повторах. Только
`World::restore_pristine` в нём занял 12,1 мс; остальное приходится на
построение нового опыта. Разные стенды расходятся по абсолютному времени,
поэтому парное ускорение в таблице не следует переносить на любой
запуск. Для нового отдельного стенда нет замера версии до изменения.

Нативный `actions` после изменений (`out/interactions/native-local-edits`):
7377 кадров за 20 секунд, среднее 368,8 FPS, p99 5,375 мс, максимум
24,182 мс, **17 кадров выше 8,33 мс**. Сценарий дошёл до 1843 правок
повреждения в бою, сбросил их, загрузил дальнее окно `[8344, 0, 8280]`
и вернулся. Показатели плавают между прогонами и не доказывают
улучшение максимума относительно ADR-350; эффект локальных правок
проверяет отдельный CPU-стенд.

Проверки: точное совпадение битов, материала, потолков и последующих
тиков с новым миром при изменении блока и вставке в середину списка;
сброс правок на трёх разных слоях; 334 теста `sim-core`, 125 `voxel`,
113 библиотечных и 29 исполняемых тестов `render`, интеграционные
golden/save/economy/sectors, Clippy без предупреждений.

**Остаток P-49:** холодный запуск всё ещё 7–8 секунд; сброс 100 чанков
23–51 мс в разных стендах, крупная новая авторская зона может занять сотни миллисекунд,
рендер имеет отдельный пик подготовки GPU. Бой останавливается на время
подготовки дальнего окна. Порог 120 FPS для каждого кадра не достигнут.

Воспроизведение:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/cargo-local.ps1 test --release -p render --bin blast bench_range_interactions -- --ignored --nocapture
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/cargo-local.ps1 run --release -p sim-core --bin bench_range_reset
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/profile-range.ps1 -Scenarios actions -Seconds 20 -Output out/interactions/native-local-edits
```
