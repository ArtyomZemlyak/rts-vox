# 497 — Settled cells с вертикальными масками

3 ноября 2026. Артефакты: `out/optimization-497/`.

## Причина

[Профиль494](494-current-3000-profile.md) показал 5,033 мс cell construction в
основном debris `Settled`; [профиль496](496-rubble-3000-profile.md) показал
6,022 мс support build во втором `Settled` внутри rubble. Каждая опора раньше
создавала отдельную hash-ноду на каждую Y-ячейку.

## Прототип

Ключ hash map стал `(x, z, vertical_word)`. Нода содержит `source`, прежний link и
`u64 mask` фактически запрошенных Y из `want.column`. При `get([x,y,z])` iterator
выбирает ноду того же vertical word и пропускает только источники с нужным битом.
Разреженные высоты, отрицательные слова, wide links и canonical source order
сохраняются. Это не superset, persistent state, sorting или изменение queries.

Существующий test oracle разворачивает ноды обратно в полные 3D cell lists и
сравнивает их, включая workers1/2/4/8 и negative/word boundaries. Прежние ошибки
компиляции `fragment_join_memo` unit tests остаются неизменными и описаны в
[495](495-sorted-settled-cells.md).

## Проверка 200 тиков

Все36 нетайминговых полей совпали с fat-LTO ADR-836. Ранняя серия:
mean10,524→10,298 мс, `debris`1,841→1,830 мс, `rubble`0,543→0,523 мс.
Это не итоговый процент; решение принималось по полным1600-тиковым AB/BA.

до3,474 мс: фильтрация масок при контактах стоила дороже экономии на nodes.

## Решение

Прототип **отклонён и откачён**. Исходные per-Y linked nodes и тесты восстановлены.
Restored release повторно дал нулевые расхождения по всем36 полям на200 тиках.
ADR, replay и native-замер не нужны при отрицательном headless результате.
Ранний небольшой выигрыш не подтвердился полным боем.
