## Причина и изменение

В исходном эпизоде пик tick515 занимал150–152мс. Давление уже не могло
оплатить большую часть грунта, но движок продолжал обходить его материал
и каждый отказавший кубик. Именованные scopes дали около76мс read_ground
и72мс apply. При этом отказы ничего не меняют в мире: их логический эффект —
счётчики интерьера/неизменяемой рамки, одно посещение клетки и прежний cursor.

1. Отказы считаются из точной occupancy-маски через popcount интервалов
   строк её пересечения с интерьером мира. Остальное относится к рамке;
   верх мира не превращён в новую рамку. Префикс ранее обработанных битов
   исключён. Нет приближённой плотности или удаления счётчиков.
2. Для сильного контакта с фактической энергией грунта ниже минимальной цены
   любого зарегистрированного материала read-ahead читает только occupancy
   через World.solid_bits. Значения материалов в таком случае не нужны.
   Временный тег UNPRICED не сериализуется. При использовании живой остаток
   проверяется снова; если условие не подтверждено, работает полный fallback.
3. Давление ниже необходимой работы, доступная энергия, оплачиваемые claims,
   dents/деформация и аннигиляция сохраняют прежние пути. Неоплачиваемый
   контакт и раньше не тратил voxel work; его посещение по-прежнему тратится.
4. В обычном применении порядковый номер материала идёт последовательным
   счётчиком вместе с битами маски. Широкая маска не пересчитывает prefix rank
   для каждого кубика; при resume он вычисляется один раз.
5. Column-reader крупных клеток не вычисляет материал выше точного ceiling
   committed occupancy. Нулевая плоскость между Z-строками не оставляет
   значения соседней колонки. Канонический X/Y/Z порядок сохранён.

Это ускорение существующих операций, без изменения схемы snapshot,
оплачиваемой энергии, выброса материи или контактов. Полная карта,
следующие волны и навигация получают те же изменения в те же тики.

## Проверенные и отвергнутые варианты

Один ranked iterator и ceiling почти не сдвинули пик: первый диагностический
вариант148,168мс против149–152мс. Прототип occupancy-only по оценочному
исчерпанию бюджета уменьшил read до11,641мс, но поднял apply до247,374мс,
весь tick515 —261,977мс. Отложенные claims ещё не заплатили, так что оценка
не означает фактического исчерпания. Материалы приходилось читать снова
последовательно. В итоговом условии используется фактическая энергия;
оценка по-прежнему может выбирать bounded batch, но не разрешает пропуск.
Сохранён отдельный тест, не позволяющий вернуть эту регрессию.
Ранние after1/bulk1/first-variant/rejected-estimate — диагностические
артефакты; итоговые замеры имеют метки final2..4.
