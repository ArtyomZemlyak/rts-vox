# Таблицы ID обломков в рендере — ADR-536

03.10.2026. Продолжение [129](129-phase-ring-stall-capture.md),
WBPERF-002/013/027. Основа main `b39c815`.

## Принятое изменение

Постоянные render-слоты и история поз устранили пересоздание деревьев,
но обе таблицы использовали std HashMap с RandomState/SipHash. Рендер
запрашивает их по внутреннему u64 ID для каждого обломка на каждом кадре;
история заполняется перед каждым физическим шагом. В бою это десятки
тысяч повторных lookup. Эти таблицы не содержат внешние строковые ключи
и не задают порядок физических результатов.

Обе заменены на существующий `bevy::platform::collections::HashMap`.
В закреплённом Bevy 0.19.1 он использует FixedHasher/foldhash. Новые
зависимости, собственный хешер, обрезание ID и плотная индексация не нужны.
История по-прежнему переиспользует buckets; render-слоты сохраняют entities.
Порядок рисунка берётся из физического списка, поиск — по полному ID.
Обход retain удаляет независимые старые entities и раньше не имел
стабильного порядка. Все куски, геометрия, эффекты, интерполяция, reset,
reuse ID, пробуждение и физика сохранены. Симуляционные таблицы не менялись.

## Проверки

7 тестов обломков прошли, затем полный blast suite: **94 passed, 2 ignored**.
Включены реальные lifecycle/reuse/despawn, история до тика и reset,
полёт/приземление/пауза, неизменившийся Transform, изменение позы и mesh,
точные occupancy/GPU-shadow cells. Release build и clippy успешны;
остались прежние type_complexity warnings. Рабочее дерево содержит
отдельные ранее подготовленные изменения; они не входят в ADR-536,
включая тест/исправление геометрии насыщенной кучи.

## Все шесть обычных нативных прогонов

Стоковый world-battle AI-vs-AI, 60 секунд, 1600×900, RTX 5090 Vulkan,
physics/navigation 8/8, target 165 FPS. Без CorePhases, trigger и GPU
timestamp. Последовательность: before1, after1, after2, before2, before3,
after3. Во время замеров не было сборок/тестов/изменений исходников.
Ручной render context и focus true оставались одинаковыми.

Все три первоначальные пары не прошли строгий gate: первая из-за
1801/1800 и хеша, вторая/третья также из-за потери темпа одной стороны.
CLI сравнений завершился с кодом 2. Эти результаты не являются тремя
успешными A/B-парами и не удалены из отчёта.

После исходного разбора дополнительно проверена **полная матрица 3×3**
уже сохранённых запусков; новых повторов для замены плохих не делали.
Прошли ровно два сочетания: before2→after1 и before2→after3. У всех трёх
этих запусков 1800 шагов, хеш `4d209d19c248cf15`, 1× и одинаковый context.
Это один сопоставимый контроль, использованный дважды, а не два
независимых контрольных повтора. Исходные JSON с неуспешными заранее
назначенными парами сохранены; матрица записана отдельным файлом.

В этих сочетаниях fragments-группа дешевле на **29,7% и 29,2%**,
FPS выше на 5,5% и 3,6%. Core до 12,356 мс, после 12,355/12,465 мс:
ускорение симуляции не заявляется. Группа включает историю и обновление
картинки обломков; она не является собственным временем одной draw-функции.
Измерения поддерживают сокращение повторных render lookups. Стабильность
хвоста, устранение фризов и 165 FPS ими не подтверждены.

Обе замороженные рабочие сборки включают одинаковые отдельные локальные
правки вне этого ADR; это не сравнение чистых Git-коммитов. SHA256:

  `194404b8304c5b44557e69c55dba66763c18593f62fad0d09a601ffff9757773`;
- `out/performance/blast-fix536-after.exe` (after и текущий release):
  `a4ee4c9cfd799a7a2bb7b85f12908d13e0f4edf99c1dc83741b13e5ae5523a47`.

Остальные хеши: before1 `192d1f6c8b4f0a27`, after2
`3c8e255a9db0f106`, before3 `d53da25e7690e1cb`.

## Фризы и дополнительный soak

В after2 core tick 1325 занял 479,657 мс. Эпизод 1323…1331:
измеренный Update 2585,337 мс, core 2483,861 мс, следующие gaps 149,195 мс,
неперекрывающийся охват 2734,531 мс. В before3 tick 489 — core 616,222 мс;
эпизод 487…495 охватил 2617,092 мс. Причина неизвестна. Ни рендер-таблицы,
ни GPU/lock wait не объявляются причиной по этим wall-числам.

Перед изменением выполнен 180-секундный phase-ring soak той же before
сборкой, порог 50 мс, CpuThreads. 5234 шага, хеш `41bd6c924c1d48b6`.
Темп 0,96891×, p99 40,388 мс, max кадра 77,415 мс. Ни одного core-trigger,
сохранён только тихий хвост 16 тиков. Его самый долгий тик 5232 — 17,869 мс,
motion 6,396 мс, debris 4,666 мс, rubble 1,784 мс. Целостность диагностики
прошла; FPS-приёмка запрещена. Кадр и core — разные интервалы: max кадра
77 мс сам по себе не означает core ≥50 мс. Стойкую позднюю нагрузку
и редкие многосекундные эпизоды надо продолжать разбирать отдельно.

`fix536-stall-soak/` и runner/analysis/test/build/clippy logs сохранены.

ждёт тик. 165 FPS во всех случаях не достигнуты.
