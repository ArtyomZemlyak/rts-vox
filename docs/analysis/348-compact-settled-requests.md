# 348. Компактные задания индекса опор

Дата: 20.10.2026. База: `main 45ca70b`. Единственная очередь —
[316](316-optimization-delivery-plan.md), подготовка OPT316-04.

**Принят только срез временной памяти. Ускорение всего SIM не доказано.**
Задание stripe стало8 вместо28 байт (−71,4% payload/элемент).
Полный rebuild опор, списки источников и физические ответы прежние.
Persistent membership04a и dependency cache04b остаются открыты.

## Что меняется

SettledCells распределяет выбранные источники по восьми владельцам X modulo8.
Раньше каждый запрос копировал source index и обе границы коробки. Одна
коробка могла копироваться восемь раз. Теперь запрос хранит source index
и первую принадлежащую stripe X-клетку; остальные координаты читаются из
того же неизменяемого массива selected, который уже живёт до окончания join.
Новый постоянный кэш и дополнительная копия selected не вводятся.

Порядок partition/source, обратной вставки и обхода Z/X/Y прежний.
Отрицательный X сохраняется целиком, округление/stride не пересчитываются.
Head-only arena, полные wide successors и число кандидатов не меняются.
Ничего не пропускается при нехватке места. Clear очищает логические задания,
а их буферы продолжают переиспользоваться. Snapshot/hash, энергия, материя,
квоты,30Гц и same-tick contacts/navigation прежние. Общий код обслуживает
обломки и карту завалов во всех режимах; RON и сценарии не менялись.

Сокращается backing storage восьми request Vec при одинаковой capacity,
а не весь индекс или RSS игры. Время чтения selected и bounds checks
включено в приведённые end-to-end замеры. Ускорение FPS не заявляется.

Отдельный синтетический fixture:70000 selected slots с пропусками,
381170 заданий, разные границы/отрицательные координаты. Все decoded
задания и capacities совпали. Выделяемый payload Vec14 680 064→4 194 304
байт (14→4МиБ). Медиана только partition при120 чередующихся повторениях
365→297мкс; сюда не входят построение/чтение индекса и вся SIM, поэтому
локальное ускорение не отменяет отрицательный end-to-end CPU-вывод.

## Отвергнутые пробы

Все прототипы ниже удалены из production; их корректный hash сам по себе
не означает успешную оптимизацию. Проверки final нельзя приписывать
отвергнутым представлениям.

- Inline first candidate вместо arena head: два6000-контроля.
  Late cells1,206/1,344→1,495/1,510мс; root12,539/12,930→12,593/12,684.
  Arena короче, но сборка дороже, устойчивого общего выигрыша нет.
- Tuple `(x,y,z)` вместо массива: один6000 probe, root12,654мс,
  late cells1,338мс. Преимущество не доказано; в final отсутствует.
- Tuple с X quotient внутри stripe: один6000 probe, root13,028,
  late cells1,375мс. Преимущество не доказано; в final отсутствует.

Это отрицательные результаты на данной машине, не универсальное утверждение
о стоимости tuple/hash. Компактные задания сохраняют исходный ключ `[x,y,z]`.

## Проверки и артефакты

Локально `out/optimization-348/`: frozen before/probe/final executables,
логи/CSV, rejected patches, compare.py, comparison.json и source fingerprints.
compare.py сверяет6000×36 игровых значений и hash, сохраняет mean/percentiles
всех parent фаз отдельно. Микропроба requests_probe.rs независимо сверяет
полные decoded задания двух представлений и измеряет capacities. Это
синтетическая проверка памяти/partition, не измерение RSS или скорости SIM.

Финальный полный release lib run: **1035 passed,0 failed,17 ignored**,
329,47с. Включены независимые ordered-cell/полные списки источников,
wide links, отрицательные координаты, clear/rebuild, тонкие опоры,
изменения hull/world, sweep/eviction, worker determinism и replay.
Ignored performance experiments не выданы за выполненные проверки.
Release integration golden1 и snapshot3 также прошли: эталонный hash
прежний, восстановленный живой бой продолжается побитово. Архитектурные
12, docs3 и проверка ссылок/якорей прошли. Полный текст ADR-765 добавлен
вместе с записью реестра; первая docs-проверка обнаружила его отсутствие.

Первый полный release run обнаружил три устаревшие проверки после344:
1031 passed,3 failed,17 ignored. Все три падения отдельно воспроизведены
на исходных runtime/test sources main45ca70b в debug, временно убрав
оптимизацию. Это не следствие компактных заданий:

- Счётчик Weapon::COUNT уже включает Nuclear, но тест перечислял только
  прежние восемь видов. Добавлен девятый с прежней проверкой уникальных кодов.
- Стационарных видов теперь шесть, тест валки ожидал пять. Проверки
  неподвижности и отсутствия удалённой валки по всем видам сохранены.
- Legacy order oracle создан до manual-only шахты. Он продолжает
  сравнивать все прежние10 видов; новая шахта имеет отдельный контракт
  nuclear_tests и новый тест отказа от controller orders для обеих сторон,
  с полным равенством snapshot/hash после каждого отказа. Runtime admission
  не меняется, автоматический запуск не разрешается ради legacy oracle.

Уточнение пользователя о пропадающих тенях при неподвижной камере
зафиксировано как открытое в [342](342-unit-shadows.md).
Это не считается исправленным срезом348; визуальное исчезновение требует

## Что делать дальше

В свежем baseline late debris4,56–4,92мс, motion4,00–4,03,
rubble1,93–2,03. Внутри debris на последнем300-тиковом окне settled
занимает около3,45мс. Главная цель04a — убрать полную повторную подготовку
membership при неизменившихся провайдерах, включая цену invalidation и
dense fallback; ещё одна перестановка записи не закрывает эту задачу.

До внедрения требуются фазовые версии и полное покрытие spawn/move/rest/
wake/merge/evict/reclaim/sections/restore. Сравнивать весь индекс/контакты
на каждом фазовом входе с полным builder. Нельзя смешивать снимки motion,
debris и rubble. Срез348 не закрывает04a/04b, валку/очереди03, blast peaks02b,
SIM/render08, память длительного soak или FPS-приёмку09.
