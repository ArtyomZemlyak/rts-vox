# 319 — Точные колонки для чтения грунта крупных взрывов

Дата: 16.10.2026. Before — main `6502e08`, после ограничения read-ahead
в [318](318-bounded-ground-read-ahead.md). Задача — первая порция
[OPT316-02b](316-optimization-delivery-plan.md), решение ADR-745.

## Причина и решение

Native scopes в318 локализовали дорогой тик2081: ground read около116 мс,
body map около1,1 мс, heap/filter почти нулевые. Ограничение выброшенного
хвоста не устранило повторное чтение реально нужного материала.

Прежний `read_cell_into` находил занятые воксели через `solid_bits`, затем
для каждого спрашивал `material_cached`. Курсор ускоряет поиск overlay,
но нетронутый чанк всё равно вызывает `Generator.material` на каждый
воксель. В RangeTerrain он повторно вычисляет дороги, высоту, растительность
и авторские примитивы, хотя часть этих вычислений зависит только от X/Z.
У генератора уже есть точный `column` API с переиспользованием этой работы
по высоте (ADR-114); новый альтернативный генератор не нужен.

Теперь ground cells edge5–16 используют `World.column`, если генератор
объявляет `batches_columns=true`. RangeTerrain имеет такую оптимизацию;
простой генератор по умолчанию сохраняет прежний row-reader. Возможность
описывается в общем Generator API, не определяется номером сценария.
Одна плоскость
16×16 и колонка16 на стеке возвращают прочитанное в прежний X/Y/Z порядок.
В маску и плотный список материалов попадают только непустые воксели.
Малые edge1–4 сохраняют прежнее чтение occupancy rows; полностью доказанный
воздух сохраняет прежний быстрый путь. За краями мира остаётся воздух,
частичные клетки сохраняют локальные индексы.

`World.column` также перестал сначала вычислять генератор под полным
изменённым чанком, чтобы затем выбросить эти значения и заменить overlay.
Теперь он читает overlay сразу; соседние нетронутые участки по высоте
объединяет в один вызов генератора. Это общий API движка, пригодный всем
его читателям, без условий на сценарий или конкретное оружие.

Нет приближённой плотности, сокращения радиуса, изменения энергии, ущерба,
квот или continuation. Контакты корпуса и ground order прежние; snapshot,
hash,30 Гц и observer families не меняются. Capture сопротивления,
применение ущерба и очереди обрушения этим патчем не оптимизируются.

## Проверки и ограничения

Существующий independent scalar oracle contact rows расширен с edge1–4
до1/2/3/4/5/8/9/12/16. Он сравнивает каждый индекс маски и порядок
материалов, включая начальный sentinel, границы мира/чанков и живые
правки. Прежние read-ahead scalar/energy/body проверки также используются.

Новый voxel-тест проверяет результат колонки против отдельных `material`
и считает фактические обращения к генератору. Полностью изменённый span
читает0 процедурных вокселей; колонка высотой99 с изменённым средним
чанком —67 вместо99. Несколько соседних pristine chunks читаются одним
вызовом, а не отдельным на каждый чанк. Прежние проверки columns против
material/cache/snapshot через edits/load/reset входят в полный набор.

Колонка может прочитать и AIR внутри частично заполненной клетки, где
прежний row-reader запрашивал только занятые материалы. Первый безусловный
кандидат ухудшал дешёвый quarter-density стенд edge9 примерно на42%,
edge16 — на50%; поэтому заменён явной возможностью генератора. При false
этот стенд использует прежний row-reader. Производитель генератора должен
объявлять true при реальном переиспользовании дорогой X/Z подготовки;
это выбор упаковки запросов, не изменение материалов. Выигрыши конкретного
боя нельзя объявлять универсальным ускорением каждого генератора.

Дешёвый quarter-density источник проверен повторной ABBA-серией в одном
и том же стенде (пул4,2048 pending, budget65 536; медиана7 повторов в каждом
run). Средние двух run medians до/после:

| Вход | Before, мс | After, мс |
|---|---:|---:|
| Edge9, обычное списание работы |0,20755|0,21845|
| Edge9, энергия исчерпана |0,95075|0,98150|
| Edge16, обычное списание работы |0,18895|0,19245|

Прежняя большая регрессия42–50% снята. Нулевая цена выбора пути не
заявляется: на edge9 остаётся примерно11–31 мкс дополнительного времени

0,900–1,028 мс. Это небольшая стоимость/разброс на локальном стенде,
не доказательство ускорения всех генераторов. На всех64 комбинациях
edges/заполнений/квот/энергии совпали prepared/retained, batches и air counts
