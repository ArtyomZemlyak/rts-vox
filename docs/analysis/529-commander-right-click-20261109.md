# Обычный ПКМ командира ошибочно включал добычу — 09.11.2026

## Причина

`Panel::crawler_mode` сохраняется после переключения выделения. Обработчик
ПКМ использовал его также для командира. В режимах сбора/бурения он выбирал
приказ `Reclaim`/`Dig` вместо `Move`. Дополнительно не срабатывал проход
луча сквозь выбранный корпус к земле: при близком клике за цель принималась
геометрия командира. Дальний клик мог выглядеть как движение к забою.

## Исправление

В `workbench.rs` эффективный режим вычисляется по текущему выделению.
Сохранённый режим краулера действует только на непустую группу краулеров.
Командир и смешанная группа получают обычный контекст движения/атаки.
Одна и та же проверка применяется к выбору земли под корпусом и к созданию
приказа. Ctrl+ПКМ и Ctrl+Shift+ПКМ остаются явными приказами добычи и реклейма
для совместимых юнитов. Автоматическая добыча экономического ИИ не менялась.

## Проверка

Расширен тест настоящего обработчика Bevy input:

- клики сквозь выбранный корпус командира и по дальней земле;
- каждый из сохранённых режимов Move/Reclaim/Drill;
- правильный `Order::Move` и конечная точка движения во всех шести случаях;
- отдельный Ctrl+ПКМ по земле сохраняет `Order::Dig`;
- проверка области применения режима на командире, краулере и смешанной группе.

Существующий тест режимов краулера проверяет обычный ПКМ для всех трёх
режимов. Оба теста прошли в debug и release. Артефакты — `out/commander-rmb-*.log`.
Это проверка ввода без оконного backend, а не новый замер FPS боя.

Release-сборка `render --bin blast` завершена; обновлён
`target/release/blast.exe`, используемый ярлыком «Полигон».
