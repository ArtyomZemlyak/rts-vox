Поиск максимального сопротивления грунта также исследован по исходникам:
чтение прекращается при глобальном максимуме, но обычная почва его не

представителем всей клетки: тонкая сталь, бетон и dents изменят давление.
Новая material-summary API в этом срезе не вводилась. Сначала ускорена
доказанно дорогая часть оплачиваемого commit с точным независимым oracle.

## Изменение общего движка

Сборка металлических панелей общая для обычного World, полигона, боя с ИИ,
взрывного и контактного разрушения. Внешние spatial boxes остаются BTreeMap
в прежнем порядке. Внутри каждой коробки вход хранится массивом и сортируется
по координатам; дубликаты по-прежнему запрещены.

Для компактной области вместо до шести remove-поисков BTreeMap на ячейку
используется плотная таблица индексов. Она содержит не более65536 слотов
и не более восьми слотов на входную ячейку. На x64 это максимум512КиБ
таблицы на одну обрабатываемую коробку, без постоянного кэша. Размер
bounding box может быть256³, но столь большая таблица не выделяется:
разреженные и большие случаи сохраняют дерево. Входные массивы и output
остаются пропорциональны уже ограниченной атомарной порции повреждений.

Сохраняются lexicographic seed и порядок X-/X+/Y-/Y+/Z-/Z+, а затем прежняя
сортировка доноров по индексу. Поэтому прежними остаются порядок компонент,
выживший fragment/container ID, порядок Fx-сумм, скорость, масса, отделка,
геометрия, зарезервированные slots и ledger. Между владельцами, частями,
подсистемами, слоями башни, позами или aligned boxes связи не добавляются.
Это не средняя плотность и не упрощение физики. RON, радиусы, сила оружия,
квоты, частота30Гц и snapshot не менялись. Контактное и грунтовое разрушение
не подменяются очисткой объектов сценария.

Наблюдатель получает только имена этапов. Часы и запись CSV остаются вне
SIM. Три новых интервала не пересекаются между собой, но вложены в apply:
складывать их с apply или root SIM нельзя. Исходный поиск сохранён только
в cfg(test) как независимый oracle.

## Что остаётся

Норматив ≤33мс каждый тик не пройден. Следующие независимые кандидаты02b:
точные локальные сводки сопротивления capture, сокращение чтения ground
при сохранении каждого контакта и bulk оплачиваемые claims без лишних
промежуточных объектов. Последнее требует сохранения порядков, IDs,
энергии и ledger; простое удаление временных объектов этого не доказывает.
Межтиковый индекс опор OPT316-04a остаётся приоритетом длительного боя.
Этот срез не закрывает очереди/полноту валки, движение, ремешинг, GPU,
синхронную границу SIM/render, серийные ядерные удары или общую FPS-приёмку.
