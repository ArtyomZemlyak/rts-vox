# 505 — Source-stable members в render batches

3 ноября 2026. Артефакты: `out/optimization-505/`.

## Причина и прототип

ADR-839 сохраняет группы на месте, но при совпадающей картинке всё равно копирует
каждый `Stamp` через `clone_from_slice`, потому что source indices могли измениться
после compaction. Когда картинка и indices совпадают, эта запись не нужна.

Прототип объединяет проверки в один pass: `same_picture` и `same_sources`.
Members копируются только при `same_picture && !same_sources`; changed pictures
проходят прежний retire. Это устранение записей, а не изменение lifecycle или
publication order.

## Проверки и результат

Lifecycle-тест прошёл. Четыре native capture AB/BA против ADR-839 дали:

| Пара | Mean FPS | p99 кадра | `fragments` p50 | `simulation_core` p50 |
|---|---:|---:|---:|---:|
|1, after→before|34,086→34,308|89,621→88,822 мс|2,939→2,887 мс|23,203→22,771 мс|
|2, before→after|33,995→34,139 (+0,42%)|91,140→89,289 мс|2,885→3,025 мс|22,750→22,890 мс|

Сводно FPS 34,152→34,113 (**−0,11%**), p99 кадра−0,59%, `fragments`
**+3,32%**, `simulation_core` **+1,26%**. Пары разошлись по знаку FPS, а целевые
фазы стали дороже. Стабильного выигрыша нет.

## Решение

Прототип **отклонён и откачён**, ADR-839 восстановлен. Пропуск записей сам по себе
не доказывает ускорение: дополнительная source-проверка и изменённая раскладка кода
не улучшили полный кадр.
