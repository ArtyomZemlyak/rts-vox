# Упакованный индекс чанков без прямой опоры

25.09.2026, ADR-409, P-45. База — `a6164d2`.

## Причина и изменение

На километровой карте поиск опор просматривал плотный байтовый индекс
587 814 возможных чанков при каждом разборе обрушений. К концу длинной
поездки прямой опоры не имели 133 519 чанков. Последовательный массив
был лучше дерева, но всё ещё требовал полного прохода и занимал
587 814 байт.

Индекс теперь хранит один бит на чанк — 73 480 байт при том же размере
карты. Обход просматривает слова и только выставленные в них биты.
Биты добавляются и снимаются вместе с обновлением компонент, удалением
чанка и загрузкой снимка. Порядок чанков остаётся возрастающим,
включая переход между словами. Счётчик кандидатов, поиск пути к опоре,
порядок отделения и формат сохранения не меняются.

## Замер

Два прогона старого и два нового release-бинарника на одной машине:

```powershell
.\target\release\bench_range.exe --range data/range-km.ron --move 2200,336 --ticks 6500
```

| Метрика | До | После |
| --- | ---: | ---: |
| p50 `collapse_resolve`, мс | 2,894–2,896 | 2,701–2,725 |
| p99 `collapse_resolve`, мс | 6,445–6,569 | 6,042–6,072 |
| p99 полного CPU-тика, мс | 9,539–9,558 | 9,166–9,322 |
| Максимум полного CPU-тика, мс | 21,337–21,773 | 20,302–21,640 |
| Снятые клетки | 128 349 | 128 349 |
| Круги патрулей | `0,5,1,5` | `0,5,1,5` |
| Итоговый хеш | `bb4a604c28e62856` | `bb4a604c28e62856` |

В отдельном 600-тиковом боевом прогоне с одним энергетическим выстрелом
p50 поиска опор снизился с 591 до 468 мкс, p99 CPU-тика — с 6,467 до
5,989 мс. При этом максимум тика вырос с 8,797 до 9,350 мс: одного
боевого прогона недостаточно для вывода об улучшении худшего кадра.
Число снятых клеток 46 645 и хеш `c6373dfde61c255c` прежние.

Это CPU-стенд без рендера и GPU. Даже в длинном прогоне p99 CPU-тика
выше бюджета 8,33 мс; 120 FPS во всех сценариях не достигнуты.
Бинарник базы и сырые журналы — `out/backlog/adr-409`.

## Проверки

Тест границ битового слова проверяет появление и исчезновение кандидатов,
удаление чанка, порядок и совпадение результата с полным обходом.
Прошли `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`,
`cargo fmt --all --check` и релизная сборка нативного окна `blast`.
Контрольный `sim-cli --seed 42 --ticks 1000 --dump-hash` сохранил
хеш `12bd9cb0d53498f2`.
