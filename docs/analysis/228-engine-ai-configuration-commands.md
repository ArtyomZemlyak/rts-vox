# Настройки ИИ и отмена планов через общий движок

Дата: 08.10.2026. Продолжение EP-02a/02b после
[227](227-engine-battle-lifecycle-commands.md), ADR-633. Контроль — frozen 227;
критерии заданы до изменения кода в
`out/engine-fixes-20261008/ai-configuration-commands/acceptance.json`.

## Исправляемый разрыв

configure_enemy_ai менял правила, переносил deadline на текущий тик и
удалял pending внешний план вне общего ingress. Перенести только setter
было недостаточно: у owner остались бы Delivered receipt и незавершённый
буфер результата, хотя этот план больше не исполняется. Кроме того,
checkpoint требовал строго возрастающих deadline разных планов. После
смены интервала корректный следующий план может иметь более ранний срок.

`Command::ConfigureEnemyAi { tuning }` переносит полный Tuning из пяти
целочисленных/boolean полей. Бывший метод, CLI `--ai-rules` и существующий
rebuild делегируют общему исполнителю. Разбор RON и файловый ввод остаются
снаружи движка; сценарных условий и новых параметров баланса нет.
Tuning теперь Copy, без изменения данных или границ validate.

Ошибочный ввод возвращает Rejected без изменения мира, pending и deadline.
Равные допустимые значения возвращают Applied: прежний API намеренно
перезапускает цикл даже при повторной настройке. Один вызов создаёт один
результат в bounded capture; старый Result и текст ошибки сохранены.

## Согласованное завершение плана

Owner применяет команду перед физикой, затем завершает свой pending план
как `PlanState::Reconfigured { tick }` до AfterMotion. Новый Rules-ответ
не выдаётся за исполнение старого внешнего плана. Его receipt удерживается
до отдельного acknowledgement, не требует сохранения command receipt и
не освобождает вместимость очереди без подтверждения.

Время отмены находится между доставкой и прежним deadline включительно;
сохранённый мир уже прошёл отменяющий шаг. Следующий план доставляется
после завершения предыдущего. Для Reconfigured допускается более ранний
или равный deadline; для Executed/Cancelled сохраняется прежний порядок
сроков. Проверка допускает независимое подтверждение результатов, включая
удаление отменённой команды при сохранённом результате плана.

Новый цикл при queued reconfiguration использует Rules в текущем шаге;
внешний runner доставляет следующий план уже для нового deadline.
Предварительная доставка внешнего плана до queued launch этим пакетом
не добавлена. Прежний синхронный API вне owner сохраняет свою последовательность.

## Сохранение и диагностическое воспроизведение

Настройки, deadline и pending уже входят в physical snapshot: его формат
не изменяется. Portable checkpoint v1 добавляет command tag8 с нулевым
reserved target и 17 байтами Tuning, plan-state tag3 для Reconfigured.
Boolean строгий, обрезанные/неизвестные структуры отвергаются. Неверные
игровые числа сохраняются как pending ввод и получают Rejected при исполнении.
Старые executable не читают новые tags; старые wire records не перекодированы.

AI preflight учитывает только допустимую ConfigureEnemyAi, назначенную на
текущий тик, в порядке общей очереди. Record устанавливает hook заранее,
replay проверяет frame до изменения мира и отмены плана. Missing/wrong frame
оставляет и очередь, и внешний план целыми. Invalid настройка и команда,
отложенная per-tick лимитом, не создают раннего deadline. Обычный step
не вызывает diagnostic preflight или полный hash.

При повторной проверке обнаружен отдельный дефект 227: предварительная
оценка числа command receipts использовала минимум 60 байт, а lifecycle
StartBattle/FreeControl и ammunition занимают 59. При 16 таких записях
и пустом списке планов остаток составляет 952 байта; проверка требовала 960
и отвергала корректный checkpoint до чтения. Минимум исправлен на 59;
явные caller ceilings, checksum и строгий разбор сохранены.

## Проверки

11 целевых release-тестов прошли до полного прогона. Проверены все поля
и границы tuning, legacy/typed equivalence и однократный capture, повторный
перезапуск, отмена в сам deadline, сохранение плана при invalid настройке,
новые deadlines раньше/равно/позже отменённого и независимый ack.
Codec проверяет reserved target, boolean и все точки обрезания команды;
каждое поле pending настройки влияет на hash. Restore отвергает невозможные
времена отмены и доставки следующего плана.

Физический тест сравнивает 240 тиков direct execution и owner с повторными
portable restore: настройки до запуска и во время боя, перенос лимитом,
невалидный ввод. Требуются реальные выстрелы и повреждение. AI tests
проверяют настройку с обеих сторон команды запуска, final value в одном
тике, spill и missing/wrong frame до мутации. После review добавлен тест
полной очереди из 16 коротких команд с восстановлением до и после исполнения.

Полный release sim-core/nav/modding: **1005 pass, 0 fail, 6 ignored**,
включая все 12 новых проверок. Architecture: прежние **5 pass / 4 fail**,
все **46 нормализованных диагностик** совпали с frozen 227. Открыты
render writes, floats, hash containers и clock; новых нарушений нет.
Rustfmt check и git diff --check пройдены.

Полный blast UI: **159 pass, 0 fail, 4 ignored**. Пройдены существующие
проверки загрузки сценариев, переигрывания, настройки и пересоздания мира.
UI-элементы и данные сценариев в этом пакете не менялись.

## Границы и дальнейшая работа

Rules остаются прежней политикой, команды и AI исполняются в прежних фазах.
Дорогой физический step ещё находится в кадровом цикле. Перенос настройки
не объявляется ускорением боя. Reset/rebuild с передачей владения, epoch
и отменой jobs, ручное орудие и geometry/terrain export остаются следующими
границами перед выделением owner. EP-02/03, прогресс физических очередей
и цель 165 FPS не закрыты.
