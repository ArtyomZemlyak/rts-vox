# 428 — Фильтр одиночных changed-куч: отклонено

1 ноября 2026. Артефакты: `out/optimization-428/`.

## Гипотеза

Куча с одной текущей записью не может дать перенос. Прототип подсчитывал
записи каждого изменившегося ключа и исключал такие ключи из shards и
`Geometry::join`. Полный fallback и группы с несколькими записями не менялись.
Все36 нетайминговых полей1600-тикового боя совпали.

## Производительность

| Показатель | Baseline | После | Изменение |
|---|---:|---:|---:|
|`merge_keys` 1501–1600|2,731 мс|2,972 мс|+8,8%|
|`merge_groups` 1501–1600|7,258 мс|7,625 мс|+5,1%|
|Полный mean|34,985 мс|35,423 мс|+1,25%|
|Поздний тик1201–1600|51,001 мс|52,422 мс|+2,79%|
|`debris` 1201–1600|27,690 мс|28,669 мс|+3,54%|

Подсчёт всех ключей стоит больше пропускаемой работы. Список singleton-куч
не оправдывает новую таблицу и полный проход.

## Решение

Runtime-прототип не переносится в рабочее дерево. ADR не создаётся. Для P0-A
нужно сокращать построение `current` и большие полные обходы, а не добавлять
таблицы ради фильтрации небольшой их части.
