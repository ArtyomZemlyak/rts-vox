# ADR-569: связные резервы повреждения под давлением debris pool

04.10.2026. Продолжение P-76 / ADR-567…568.

## Что исправлено

Резерв по одному месту на временный донор был консервативным сверх
фактической формы: 64 снятые клетки одной связной коробки превращаются
в один физический кусок, но проход останавливался уже после первой,
если свободно только одно место. Теперь атомарный Batch поддерживает
маски лицевых компонент по тем же точным ключам, что конечная группировка:
unit, part, fracture origin/side,16компонентов frame, subsystem role.
Finish/царапины, как прежде, не разрезают связную сталь.

Изолированная клетка занимает одно место; соседняя не занимает нового;
мост между N компонентами возвращает N−1. Дубликат не освобождает резерв
и не переводит вторично материю. Нельзя сварить разные роли, части,
повороты или клетки, соприкасающиеся только углом/ребром. Никакого раннего
flush и перестройки старых куч. Цена, материя, IDs, скорость клетки и
финальное вычисление формы/импульса следуют прежнему пути. При достаточном
месте byte snapshot совпадает со scalar. Когда старый консервативный путь
отказывал, новый может снять больше клеток; совпадение старого исхода
под давлением не является требованием.

После атомарного commit active fragments+claims и flying+claims остаются
в пределах прежних RON caps. Temporary donors могут временно превышать
количество физических кусков, максимум64клетки на итоговую компоненту.
Ledger сохраняет retired slots в free list, поэтому лимит числа записей
load расширен структурно до max_fragments×64 + units×2 +2 с проверкой
encoded bytes до allocation. Это не увеличение live fragment pool и
не изменение формата; целостность Ledger и свободного списка проверяется
прежним валидатором. Консервативные ground/melt резервы не менялись.
