# Отбор корпусов для взрывной волны и измерение FPS

24 октября 2026. Продолжение381. Размер куба, скорости юнитов,
частота SIM20 Гц и бюджеты разрушений сохранены.

`Explosion::read_bodies` переводит границы ещё не отображённого тела
в сетку волны один раз. Проверка множества ячеек теперь сравнивает их
индексы, не строя мировые кубы для каждой пары тело/ячейка. Деление
евклидово; включительная верхняя граница корпуса сохраняет прежнее
пересечение с полуоткрытым кубом. Геометрия каждого контакта не менялась.

Отклонены два предварительных варианта: прямой кеш256 обратных коробок
ускорял некоторые крупные ячейки, но замедлял мелкие и отдельные модели;
перенос постоянного радиуса коробки не дал устойчивого выигрыша в полном
бою (медиана10435→10464 мкс). Они сохранены только в `out/optimization-382`.
В рабочем коде этих вариантов нет.

Профилирование обычного окна измеряет интервалы начала кадров по
монотонным часам. Min/MaxInstantFps — обратные самого длинного/короткого
кадра; высокий максимум не означает удерживаемую частоту.1% low —
1000/среднее время самых медленных ceil(N/100) кадров. Эти три метрики
теперь автоматически входят в `scripts/profile-range.ps1`.

Три последовательные пары headless-боёв: world/ai-vs-ai,62 юнита,
1600 тиков,nav8/physics4/Rayon4, стандартные настройки. Медианы:

| CPU SIM, мс | До | После |
|---|---:|---:|
|Средний тик|10,537|10,551|
|p50|8,991|9,011|
|p95|19,604|19,805|
|p99|50,339|51,391|

Устойчивое ускорение полного боя этим изменением **не подтверждено**:
разница среднего около0,1%, первый новый прогон медленнее остальных.
Уменьшение арифметики в отборе тел не устраняет остальные расходы
разрушений. Это не основание обещать рост FPS или отсутствие рывков.
`summary.json`, `before/after-1..3.csv/log` в `out/optimization-382`.

Все36 нетайминговых полей совпали на каждом из1600 тиков всех трёх
новых прогонов с исходным. Полный конечный hash у всех шести
`5e7626bc850f1c75`, выжившие[20,22]. Oracle границ, instant-blast12,
contact-read14, wave-damage6, wave-resume16, golden1, snapshot3,
architecture12, docs3 прошли; ручные диагностические тесты пропущены.
Форматирование, diff check и тесты инструментов профилирования прошли.
Полный набор прежних SIM-тестов не запускался; прежние отказы из376
не объявляются исправленными. Release blast и bench_battle пересобраны.

Первый замер окна1600×900 дал103,0 FPS; после уточнения пользователя
он не используется как оценка его обычного режима. Его целевой режим —
развёрнутое окно на4K с сохранёнными настройками `out/range-tuning.txt`.
Профилировщик отключает VSync; результаты показывают частоту без
ограничителя, а не гарантированную частоту показа монитором.

Финальная пара оконных прогонов:60 секунд каждый, Vulkan/RTX5090,
nav8/physics4/Rayon4/compute4, saved tuning, `--window3840,2160
--maximized`. Фактический клиентский рендер **3840×1949**, не2160 по
высоте: развёрнутое окно сохраняет системное оформление. Положение
камеры и размер окна не менялись. Оба манифеста признаны пригодными
для сравнения, входные файлы и сохранённые настройки совпали.

Средний FPS отличается на1,4%; одна пара не доказывает устойчивого
ускорения, тем более headless-пары его не подтвердили. Мгновенный
максимум сильно зависит от единичного короткого кадра и не означает
стабильные350–620 FPS. Просадки до93 мс остались. Оба окна отработали
1200 SIM-тиков, отношение SIM/реального времени0,9998; конечный hash
`4bc6cf541a715dab` совпал, stderr пуст. Этот hash отличается от stock
headless из-за другой длительности и saved tuning.

`fps-4k-stats.json`; в каждом каталоге исходный CSV кадров, лог,
