# Публикация разрушений без повторной работы

24 октября 2026, продолжение аудита389, ADR-806.
Артефакты: `out/optimization-390/`. Изменён только render adapter.
Мировой воксель, SIM20Гц, энергия, радиусы, физика и квоты прежние.

## Причина и изменение

В профиле388 худший обычный кадр включал~83мс SIM и~16мс публикации
рельефа вместе с occupancy. В этой работе сокращается публикация;
расчёт авторитетной волны не переносится и не упрощается.

surface_material раньше искал SurfaceWork для каждого материала.
Повреждённые оттенки существуют только у2/3/6: бетон, сталь, камень.
Воздух, почва, растительность и другие ID теперь возвращают прежний
цвет без дерева вмятин. Прежняя функция surface_tint остаётся общей
точкой проверки палитры.

Дальняя колонка раньше повторно вставлялась в BTreeSet для каждой
изменённой высоты и каждого поверхностного уведомления. Временный
фильтр64 строк с64-битной маской отмечает уже посещённые колонки.
Полный ключ X/Z-блока проверяется; коллизия может дать повторную
вставку, но не пропуск. Итоговый набор и порядок его чтения прежние.
Фильтр живёт одну публикацию, без нового постоянного кэша мира.

Материал поверхностного уведомления/снятой клетки тела читается только
после проверки локального окна и тела, закрывающего эту клетку. Правка
мира по-прежнему передаёт уже известный материал. Неизменившееся
упакованное слово не создаёт отдельную dirty/upload-отметку; верхние границы
колонок обновляются до этой проверки и остаются консервативными.
Дальние колонки регистрируются независимо от попадания в локальное окно.

Полная terrain_words уже не разделяется с render world при extraction:
там ранее внедрены owned patches. Новое копирование/разрешение полного
объёма не вводится; этот прежний результат не объявляется новой работой.

## Исправление жизненного цикла

В advance длины removed собираются до шага SIM; производство добавляет
юнит в конце шага. Старый apply_terrain индексировал прежний массив
по новому id и падал. Реальный тест производства воспроизвёл:
`index out of bounds: the len is 4 but the index is 4`.

Для нового слота используется начало0. Все уже существовавшие слоты
сохраняют свои прежние курсоры. После публикации обычная occupancy
добавляет новое тело. Тест сравнивает полную карту с её независимым
перестроением и требует сбалансированную материю.

## Проверки до запуска окна

10 выбранных тестов прошли, один ручной benchmark игнорируется:
точная карта/загрузка, коллизии кеша и границы u32, полная палитра
поверхности, координаты всех видов, производство и retained terrain.
Дополнительно2 проверки настоящей артиллерии и7 streaming прошли.

Новый стенд61443 реальных правок мира и65539 surface notifications
сравнивает весь упакованный объём с write_window, независимо строящим
его по текущему миру/телам/вмятинам. Применение только опубликованных
диапазонов к старому буферу также даёт весь новый буфер. Набор дальних
колонок сравнивается с полным BTreeSet-обходом; повторная публикация
того же состояния не создаёт dirty words. Отдельный oracle фильтра
охватывает коллизии, повторные пакеты и крайние координаты u32.

Это не полный новый прогон SIM: авторитетный код не менялся. Шесть
открытых SIM-отказов аудита389 и проблема crop малых матчей этой
публикацией не исправляются. Исправлен отдельно проверенный render
выход за границу при выпуске нового юнита.

## Изолированный CPU-стенд

before-tests.exe/after-tests.exe — замороженные test executables,
release, LTO=false/codegen-units16. Одна и та же фикстура и benchmark,
два прогрева и девять измерений, копирование исходного буфера вне
таймера. Три пары запусков с чередованием порядка, без компиляции,
игры и других измерений. Оба варианта передают15361 слово.

Медианы трёх запусков4,3433→1,6313мс, примерно−62,4% или в2,66раза
быстрее. Это ускорение публикации на данном стенде с большим количеством повторов,
не множитель FPS и не ускорение самой SIM-волны.

наблюдателей. FPS и сроки публикации оцениваются по ordinary кадрам;
