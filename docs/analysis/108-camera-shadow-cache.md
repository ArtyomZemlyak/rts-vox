# Кэш теневых ячеек при перемещении камеры

26.09.2026. Продолжение P-69/P-45, пункта о задержках при перемещении
камеры по километровому полигону.

## Причина и изменение

При каждом сдвиге подробного окна сбрасывался кэш занятости всех машин.
Заново преобразовывались в мировые координаты вокселы корпуса, башни
и сочленённых сегментов, включая неподвижные и находящиеся вне окна.
Этот расчёт нужен для теней и взаимодействия газа с машинами, но
положение камеры само по себе не меняет геометрию машины.

Теперь кэш машины хранит мировые координаты теневых ячеек отдельно
от адресов в подробном окне. Сдвиг или изменение размера окна заново
отбирает и адресует готовые координаты на границе окна. Машины,
целиком находящиеся внутри обоих окон или вне обоих, сохраняют и
готовые адреса: при прежних размерах тороидального буфера адрес
зависит от мировой координаты, а не от начала окна. Границы кэша
считаются по фактическим теневым ячейкам, включая башню и ноги, только
при первом запросе после смены геометрии. Расчёт не добавляется к
каждому тику движения машин при неподвижной камере.
Движение, поворот башни, изменение поз сегментов и удаление вещества
пересчитывают геометрию.
Вмятина без изменения занятости сохраняет прежний кэш. Сброс сцены
по-прежнему очищает кэши машин и сохраняет список старых теней для удаления.

Физика, материалы, свет, подробность и частота обновления картинки
не меняются. Цена — дополнительный переиспользуемый CPU-вектор из
трёх i32 на теневую ячейку машины. Одинаковые координаты от разных
вокселов удаляются при прежнем объединении занятости; отдельная
сортировка мировых координат при каждом движении не добавляется.

## Проверки

- `cargo test -p render --bin blast`: 53 прошли, один ручной бенчмарк
  пропущен. Новая проверка сравнивает кэш с полным преобразованием
  при сдвигах, выходе из окна, изменении его размеров и возврате после
  повреждения машины вне кадра. Счётчик подтверждает отсутствие
  пересчёта геометрии только из-за камеры.
- Существующие проверки сравнивают весь подробный объём с новой
  сборкой и отдельно применяют только опубликованные GPU-пакеты.
  Они покрывают движение машин, разрушение и заворачивание окна.
- Release-сборка выполнена.
- После отложенного расчёта границ повторены все шесть тестов теневой
  занятости. Архитектурные проверки: девять прошли.
- `check-range-camera.ps1`: 239 кадров отдаления, возврата и бокового
  перемещения, максимум скачка среднего RGB 1,175 при пороге 8.
  Проверка крупных вспышек проходит; субпиксельную рябь она не исключает.
  Окончательная запись: `out/backlog/camera-shadow-cache-verified`.

## Нативный замер

Один и тот же 12-секундный проход зума и близкого бокового перемещения
камеры по `range-km.ron`, без записи PNG и параллельной сборки.
До изменения — `camera-occupancy-before.{csv,log}`, окончательная
версия — `camera-occupancy-lazy.{csv,log}`, файлы в `out/backlog`.

| Метрика | До | После |

| Число кадров | 3524 | 3595 |
| p50 кадра, мс | 2,708 | 2,727 |
| p95 кадра, мс | 8,071 | 8,052 |
| p99 кадра, мс | 13,018 | 11,203 |
| Максимум кадра, мс | 23,056 | 16,964 |
| p99 CPU-представления со стримингом, мс | 5,394 | 3,809 |
| p99 обновления занятости в тике, мс | 3,164 | 3,223 |

Оба прогона исполнили 360 тиков, удалили 28025 ячеек и переместили
окно в `[1032, 0, 0]`. Промежуточный вариант с расчётом границ на
каждой смене позы удорожал тиковую занятость до p99 3,486–3,636 мс;
в окончательном варианте этот расчёт отложен до запроса камеры.
Стоимость действительного движения машин не ускорена; оставшаяся
небольшая разница не выдаётся за улучшение. Это последовательные
замеры конкретного стенда, а не гарантированный FPS любого боя.

## Границы

Кэш ускоряет перемещение камеры, но не отменяет преобразование
действительно движущихся машин. Подготовка полос мира, обновление
GPU-буферов и симуляция остаются отдельными затратами. Достижение
120 FPS во всех боевых сценариях этим изменением не заявляется.
