## Алгоритм и границы

Прежде карта раскладывала все повторяющиеся столбцы двумя стабильными
проходами Z/X, затем сворачивала повторы до максимальной высоты.
Теперь большой плотный gather раскладывается только по X. Временная
запись содержит Z/top в одном u32 вместо полного 12-байтного столбца.
Внутри строки выполняется точный max по Z, а упорядоченная выдача проходит
маски присутствия. Два верхних уровня масок указывают только занятые слова
и блоки: далёкие столбцы не заставляют обходить пустой промежуток.

`top+1` в u32 отличает присутствующий столбец высоты 0 от отсутствующего
и представляет высоту 65535 без переполнения. Все затронутые записи и
маски очищаются при выдаче строки. X/Z-порядок, максимум, point/rectangle
queries и отпечатки страниц остаются прежними. Проверки реальной опоры,
исключение растительности, крыш/бортов и подготовка hulls не изменены.

Порог большого входа прежний: 4096. Суммарная ёмкость двух координатных
осей не превышает N входных записей. Scratch: 4N байт для scatter,
таблица концов X, одна строка top+1 и её маски. Нет сетки размером с
площадь мира, новых постоянных кэшей, delayed invalidation или полей save.
Работа и память O(N); малая или разреженная выборка использует исходный
radix+dedup. Редукция max выполняется последовательно над целыми высотами.

## Отклонённые варианты и kernel

Первый вариант с полными 12-байтными временными записями не принят:
изолированная карта 2,956 против 2,796 мс базы, а полный бой дал rubble
2,109 против 2,086 мс. Его небольшое снижение общего тика 11,914→11,831
объясняется другими фазами и не доказывает пользу изменения.

Второй вариант с упакованной записью и ограничением полного обхода
bitmap тоже не принят: 2,903–2,912 против 2,796 мс. Финальная версия
использует иерархию присутствия вместо полного прохода по пустотам.

Изолированный kernel: 16 прогревов, по 240 измерений, physics/Rayon4,
по два финальных прогона. База 2,796/2,793 мс; финал 2,243/2,189 мс.
Среднее 2,794→2,216 мс (−20,7%). Восстановление, подготовка hulls и
сравнение карты исключены из таймера. Каждый результат полностью
сравнивается с первым, исходный state_hash не меняется; конечные checksum
совпадают между всеми вариантами. Это время отдельного kernel,
не обещание ускорения всего тика или FPS.

## Квалификация

Независимый oracle использует BTreeMap координата→максимум. Проверены
малые входы и пороги 4095/4096/4097, плотные повторы, случайный порядок,
одинаковый Z в разных X, пустые строки, нулевые высоты, top=65535,
весь 16-битный домен координат и повторное объединение готовой карты.
Прежний тест стабильной сортировки сохранён. Проверки полной карты
сравнивают её с прежним алгоритмом при workers1/2/4/8, после копки,
перемещения/изменения корпусов и обломков. Новый алгоритм использует
только временные данные одного вызова и не может удержать старую опору.

Headless: 1458 passed, 13 штатно ignored, 0 failed, без повторного учёта
одних тестов. В том числе sim-core 944, зависимости 450, интеграции 44,
architecture/docs 15, драйвер bench_battle 5. CLI600 на physics1/4/8:
`74f9a6e6513d3711`. Snapshot300→replay600 сохраняет этот хеш, снимок
12 391 986 байт. AI movement: Tank/Strider получают путь и движение на
тике 84, первый выстрел 1171/1245, хеши `a1fc6128ae166eda` /
`27d104e53a7c1f56` прежние. Формальный cargo bench завершён: 0 measured,
954 ignored; измерение производительности — отдельные бои и kernel выше.
`cargo fmt` и `git diff --check` проходят.

Тесты графического клиента, пересборка полигона и нативный профиль
выполняются; результат будет дописан после завершения.
