# 216 — общий снимок состояния для HUD и миникарты

Дата: 08.10.2026. Первый продуктовый срез EP-02b после повторной ревизии
[215](215-engine-performance-review.md). Это перенос реальных читателей
игрового окна на модель чтения, не объявление отдельного потока готовым.

## Изменение

В `sim-core::blast::read_model` введён owned `View`: generation/tick, размер
мира, режим/фаза, состав сторон, здоровье баз, состояния/позы юнитов, эффективное
оружие, дальность и приказ. Одиночная пушка представлена тем же компактным
типом Unit. В снимке нет воксельных томов, очередей материи, навигационных
продолжений или controller. Экспорт не сериализует физический snapshot и
не вычисляет hash мира.

`View::update` переиспользует память списка и заново читает актуальные поля.
Tick не служит единственным ключом инвалидизации: команды, смена оружия,
начало боя, редактирование и reset могут происходить на том же tick. Сокращение
списка удаляет старые slots; generation относится ко всей публикации.
Сохранённая предыдущая публикация не ссылается на изменяемый мир.

В `render/blast` добавлен publisher `UiSnapshot`. После изменений мира он
публикует View и необходимые параметры интерфейса: pause, FPS, power, notice.
Боевой HUD, roster, карточка выбранного юнита, маркеры миникарты и её рамка
камеры используют этот ресурс. Эти системы больше не получают `Res<Scene>`
и не читают `Scene.sim`. Они работают в headless ECS без ресурса сцены.

Ввод с миникарты отделён от публикации её terrain image: ввод остаётся перед
исполнением тика, изображение обновляется после rebuild, маркеры — из новой
публикации. Так reset не соединяет маркеры нового поколения со старой картой.
Как и раньше, terrain image обновляется по generation; динамический terrain
export этим срезом не реализован.

## Почему срез ограничен чтениями

Рабочий `Scene` ещё имеет writers через knobs, workbench, setup, weapon
reconfiguration и одиночную пушку. Перенос только боевых команд в owner при
сохранении этих обходов потребовал бы mutable accessor и не обеспечил бы
границу владения. Этот пакет выполняет доступную часть EP-02b без такой
лазейки. Существующий CommandRuntime может экспортировать тот же View через
`world()`; отдельный тест проверяет pending/receipt и последующую публикацию.
Подключение owner ко всему продуктовому lifecycle остаётся следующей работой.

| Читатель/писатель | После 216 |
|---|---|
| `panel::hud::refresh` | Только UiSnapshot и параметры UI |
| Minimap markers и camera outline | Только UiSnapshot, camera и selection |
| Minimap terrain и input | Ещё Scene/world; input меняет только камеру |
| Старый `panel::refresh`, кнопки actions | Ещё Scene; миграция не завершена |
| moving/occupancy, witness, fragments, bodies, shields/effects, streaming | Нужен полный geometry/terrain read model |
| Move/Attack, setup, knobs, weapon changes, solo gun | Общая граница всех writers ещё не завершена |

Scenario definitions, физические правила, AI cadence/AfterMotion, caps,
число workers и save formats не меняются. View — производные данные
представления и не входит в authoritative save/hash.

## Проверки и цена

Артефакты: `out/engine-fixes-20261008/hud-read-model/`. До правок зафиксированы
388 source/data/build inputs и сохранены исходные версии редактируемых файлов.
Все прежние незакоммиченные изменения сохраняются.

Приёмка задана до измерений: export для 60 units mean ≤50 мкс и p99 ≤200 мкс;
физический hash/workload прежние; HUD работает без Scene и не удерживает старые
slots после reset. FPS оценивается обычными запусками, отдельно от headless
экспорта; структурный переход не выдаётся за CPU/FPS ускорение.

Headless: **890 passed, 0 failed, 6 ignored** — 843 библиотечных проверки
nav/sim-core и 47 bin/integration, включая golden, save/replay и terrains.
Четыре новые проверки модели чтения входят в это число: отсутствие мутации
save, независимость старой публикации, изменения на том же tick, смена
generation/сокращение roster и работа через read-only world CommandRuntime.

Render: **139 уникальных passed, 3 ignored**. Полный запуск сначала дал
138 passed и один отказ нового marker test: он ошибочно использовал
`BlastRange::new` без layout, где список units пуст. После замены фикстуры
на настоящую расстановку все три minimap tests прошли повторно. Отказ и
ретест сохранены в отдельных логах; остальные 138 проверок не перезапускались
без причины. Новый HUD test удаляет источник Scene и проверяет вывод, выбор
и очистку roster по одной публикации. Marker test также работает без Scene.

Architecture: **5 passed, 4 прежних failed**. Сверены все 47 диагностических
строк без нестабильных номеров строк: новых/исчезнувших нарушений нет.
Общего pass этого harness пакет не заявляет. Причины прежних отказов и
ограничения regex-проверок разобраны в 215.

Окончательные native/bench бинарники связаны с **391** входом; до и после
сборки их хеши совпадают. Из прежних 388 входов изменены только пять файлов:
подключение модуля в BlastRange, диагностический bench, игровой schedule,
HUD и minimap. Добавлены read model, её tests и product publisher. Все RON,
зависимости, физические алгоритмы и остальные исходники прежние.

Три последовательных headless боя: frozen 214 control, candidate default,
candidate с шестью экспортами после каждого тика. Каждый — 60 units,
3600 ticks, 8 physics/8 navigation workers. Все **25 нетайминговых потиковых
полей** совпадают; итоговые shots/damage, alive 26/21, базы 100/100 и physical
hash **`5dd0c782d2b2f557`** прежние. Mean tick: **13,400 / 13,376 / 13,379 мс**.
Это сохранение workload, не заявление ускорения. Стоимость export измеряется
вне core tick; обычный native учитывает её в полном кадре.

В диагностическом проходе измерено **21600** публикаций, по шесть на один
tick (повторные no-tick кадры). По 600-tick окнам mean export —
**0,650 / 0,649 / 0,656 / 0,662 / 0,770 / 0,682 мкс**, p99 — **1,6–1,9 мкс**.
Нагрузка позднего разрушенного мира не заставляет экспорт обходить его
накопленную материю. Общий max — **343,2 мкс**; причина единичного хвоста
этим микрозамером не установлена. Пределы mean/p99 пройдены.

Логический payload на 60 юнитах — **4960 bytes** (включая заголовок View),
retained roster — **4800 bytes**, по **80 bytes на юнит** на этой платформе.
Это не общий RSS, не portable wire format и не полный render export.
Повторные вызовы подряд используют горячий кеш; поэтому микрозамер не
подменяет обычные frame measurements и не обещает такой же latency любого
кадра. Нет постоянных копий геометрии и полного world hash.

Native проверяется шестью отдельными 120-секундными запусками `world-battle`:
control-1 / after-1 / after-2 / control-2 / control-3 / after-3. Окно
1600×900, AutoNoVsync, 8 physics / 8 navigation / 4 compute workers,
обычный profile без GPU/core trace. Сборки, тесты и анализ CSV не выполняются
параллельно с измерениями. Контроль — frozen native из ревизии 215,
candidate — окончательная сборка 216. SHA-256:

`qualification.json` связывает тесты, потиковые CSV, экспорт, native manifests

`rustfmt --check` для восьми затронутых исходников и `git diff --check`
проходят. Срез принят как миграция читателей с ограниченной ценой;
EP-02b целиком и общий performance acceptance остаются открытыми.

## Оставшаяся работа

Продолжить EP-02b на оставшихся UI readers и geometry/terrain manifests,
измеряя bytes/export/free на разрушенном мире. Завершить typed product writers,
после синхронной проверки переносить owner. Не включать полный diagnostic
world hash на каждом AI deadline. Независимая цепочка physical capacity,
collapse/felling и historical scans сохраняет приоритет; этот пакет её не
закрывает и не обеспечивает 165 FPS сам по себе.
