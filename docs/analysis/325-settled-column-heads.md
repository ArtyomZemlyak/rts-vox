## Срез общего builder

`SettledCells` используется и физикой обломков, и картой опор. Прежний
builder на каждую посещаемую Y-клетку выполнял хеш-поиск полного `[x,y,z]`,
чтобы получить первую/последнюю запись её связного списка источников.
Несколько клеток одного куска повторяли поиск той же XZ-колонки.

Большая сборка получает для вертикального word0 компактную колонку:
`(x,z) → {mask, start}`. Маска берётся из **нынешнего** `SettledQueries`.
Головы только запрошенных Y-битов хранятся подряд в переиспользуемом Vec.
Адрес головы — start + число младших установленных битов маски.
Один горизонтальный поиск обслуживает все Y-клетки данного source/XZ.

Это word0 **клеток контактного индекса**, Y0..63, а не ограничение
высоты мира или разрушений. Отрицательные и остальные Y, малые входы
и переполнение буфера сохраняют прежнюю таблицу `[x,y,z]`.
Новое представление ограничено32768 логическими головами на stripe;
свыше лимита используются обычные клетки, работа не отбрасывается.
Vec capacities могут превышать логическую длину и сохраняются между
вызовами. Снижение RSS/VRAM этим срезом не заявляется.

## Порядок и точность

Распределение по X modulo8, source order, цикл Z/X/Y и arena node encoding
прежние. В dense голову помещается тот же первый/последний node index,
в список — те же source IDs в том же порядке. Sparse и dense не делят
один заполненный список. Чтение сначала проверяет заполненную голову
колонки и затем исходную клетку fallback.

Повторный additive build не переводит существующие hash-списки в dense:
уже захваченные маски продолжают работать; новые биты идут в старую
таблицу. Clear очищает maps, логические головы и счётчики. Память
переиспользуется, но membership и ответы строятся заново на каждом
обычном фазовом входе. Межтиковое состояние опор не кешируется.

`Settled::hit`, проверка верхней грани, половины единицы поддержки,
тонких плит, world/hull/fragment inputs и swept query reach не меняются.
Материя, квоты, wake/landing, сохранения и хеши сохраняются. Этим
срезом не реализован persistent fragment index из OPT316-04a/04b.

## Проверки и измерительный контракт

Адресный oracle сравнивает полный набор клеток и **полные списки** source
IDs с исходной 3D-таблицей, также читает каждый результат через `get`.
Проверяются1/2/4/8 workers, отрицательные Y и word64, реальный wide-link
путь с тестовым порогом3, сброс и повторное использование поколений.
Большой вход исчерпывает32768 голов каждой stripe и проверяет смешанный
dense/sparse fallback. Отдельный additive build меняет вертикальную
маску без clear: старые списки не теряются и не раздваиваются.

Baseline — frozen `out/optimization-323/after-*`; fingerprints497 runtime
source/data inputs, меняется `burst.rs`. Все тяжёлые операции идут
последовательно. World AIvsAI6000,physics4/nav8/Rayon4. Сравниваются все36
нетайминговых полей каждого тика и итоговый hash. Подробные spans
вложены; inclusive значения не складываются с parent/root.
