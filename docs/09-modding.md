# 09 — Мод-контракт

## Позиция

Открытый исходник **не заменяет** мод-API. Три причины:

- **Форки не композируются.** Десять модов от десяти авторов должны работать
  в одном процессе одновременно. Форк — это ветка, а не мод.
- **Дистрибуция.** Мод обязан ставиться игроком без тулчейна. «Мод на Rust» =
  каждому игроку rustup и десять минут сборки. Это не моддинг, это пересборка.
- **Эмпирика.** Крупнейшие модовые экосистемы принадлежат закрытым играм с
  хорошим API (Factorio, Minecraft, RimWorld). А там, где open source даёт
  живой моддинг — BAR/Zero-K на Recoil, Luanti, Cataclysm — работу делает
  Lua/JSON-API, а не открытость исходника.

Что открытость действительно даёт: отсутствие налога на реверс-инжиниринг,
реальность тотальных конверсий, возможность сообществу расширять сам API,
долгожительство. Это ценно и ортогонально моддингу, а не замена ему.

## Три уровня

**Уровень 1 — данные (RON) плюс `.vox`-модели.** Юниты, материалы вокселей,
оружие, здания, рецепты, биомы, параметры генератора. Порядка 80% того, что
делают моддеры. Не требует ни строчки кода.

После ADR-016 это стало заметно сильнее, чем планировалось: **мод на новый
юнит — это `.vox`-модель плюс раскладка материалов плюс позиция ядра плюс
числа в RON.** Ни поведения, ни кода, ни скриптов. Уровень моддинга From The
Depths и Space Engineers, полученный почти даром, потому что мир, постройки и
юниты — одна система.

**Ванильный контент — такой же пак, как мод** (ADR-115). `data/` грузится
той же функцией, что `mods/*/`, и отдельного пути у ванили не существует.
Иначе «мод работает как ванильный контент» — обещание без проверки:
расходиться они начнут на первом поле, которого загрузчик мода не знает.

**Числа тика — не контент пака** (ADR-140). Урон от падения, периоды,
потолки работы за тик, радиусы и перепад лежат в `data/sim.ron`, один
файл на партию, и грузятся отдельно от паков. Это правила, по которым
идёт lockstep, а не то, что мод добавляет; кто и как получит право их
менять — отдельное решение. Умолчаний у полей нет: пропущенное поле —
ошибка разбора, а не ноль.

**Модели юнитов — `.vox`.** Роль воксела (броня, ядро, двигатель, орудие,
сенсор) задаётся номером цвета, а смысл номерам придаёт RON юнита.
Оси файла переставляются в оси движка **при чтении, в одном месте**.

**Файл мода — недоверенный вход, и читается он как недоверенный.**
В lockstep он грузится у всех клиентов, поэтому парсер не имеет права
ни паниковать, ни выделять память по числу из файла, ни крутить цикл,
длину которого задаёт файл. Путь из данных не выходит за пределы пака.

**Уровень 2 — Luau.** Способности, триггеры, поведение AI, UI. Делится на две
непересекающиеся зоны (ниже).

**Уровень 3 — WASM (`wasmtime`).** Escape hatch: свои генераторы карт, тяжёлый
AI, всё, где нужна и произвольная логика, и скорость. Опционально, после 1 и 2.
Детерминизм WASM гарантирован спецификацией везде, кроме битов NaN, а
`wasmtime` умеет их канонизировать — то есть lockstep-безопасность достижима.

## Synced и unsynced

Разделение скопировано у Spring/Recoil (gadgets против widgets) и является
центральным механизмом всего мод-API.

**Synced-скрипты** выполняются внутри симуляции, в фазах `mod_pre_tick` и
`mod_post_tick` (`02-architecture.md`). Могут менять состояние игры. Обязаны
быть детерминированными. Ограничения жёсткие:

- нет float — только `Fx`-обёртки, предоставленные хостом;
- нет `pairs()` по хеш-таблицам в путях, влияющих на состояние; API отдаёт
  упорядоченные итераторы, а произвольные таблицы модов не участвуют
  в вычислении состояния;
- RNG — только `sim.random()`, засеянный от сида матча;
- нет `os.time`, `os.clock`, I/O, сети, загрузки внешних библиотек;
- нет доступа к рендеру, вводу, UI;
- **нет прямых мутаторов.** Мод не пишет воксели и не начисляет материю
  напрямую: он ставит запросы в те же отложенные очереди, что и ядро. Иначе
  мод-API обходит и `MAX_VOXEL_EDITS_PER_TICK`, и инвариант сохранения
  материи, и правило «дописывание откуда угодно, разрешение в одном месте»
  (`03-determinism.md`, правило 5а). Очередь приказов — та же, через которую
  ходит игрок: `World::push_order` и фаза `ApplyCommands` (ADR-195).

[QUESTION Q-46 blocks:stage-6 by:human]
Как хост технически не даёт моду использовать float? Единственный числовой тип
Lua и Luau — f64, поэтому «нет float — только `Fx`-обёртки» пока лозунг, а не
механизм. Два варианта: узкое исключение к ADR-004 (разрешить `+ - * /` по
IEEE 754, запретить трансцендентные — так делает процитированный прецедент
Factorio, который на детерминизм базовых операций как раз **опирается**), либо
чисто userdata-API, где числа мода вообще не Lua-числа, ценой эргономики.

**Unsynced-скрипты** выполняются в рендер-слое. Могут читать состояние, рисовать
оверлеи, менять UI, реагировать на ввод. Не могут менять состояние игры —
только порождать команды, которые пройдут обычный путь через очередь.
Ограничений на детерминизм нет.

Эти ограничения — не изобретение: это ровно модель Factorio, где движок
запрещает загрузку внешних библиотек именно из-за недетерминированности, даёт
собственный seeded RNG и требует стабильного порядка итерации.

## Мультиплеер, реплеи и моды

Хеш набора модов (имена, версии, хеши содержимого) входит в handshake
lockstep-сессии. Расхождение — отказ подключения, а не десинк на десятой минуте.

**Тот же хеш пишется в заголовок реплея и снапшота.** Реплей с другим набором
модов обязан отказываться проигрываться сразу, а не расходиться по хешу на
тике 4000.

Отчёт о десинке включает список модов, чтобы виновника было видно сразу.

## Индексы палитры и слияние данных

**Индекс материала в палитре задаётся явно в данных и никогда не выводится
из порядка загрузки** (ADR-028). Материал объявляет свой номер сам; два
материала с одним номером — **ошибка загрузки с внятным сообщением**, а не
тихое переназначение.

Чтобы моды не сталкивались номерами, диапазоны разведены: ванильный контент
занимает зарезервированный диапазон, мод объявляет свой в `mod.ron` и обязан
в него уложиться. Пересечение диапазонов — тоже ошибка загрузки.

Это не деталь: палитровые индексы лежат в хранилище вокселей, в снапшотах, в
реплеях и в golden-картах. Если бы нумерация выводилась из порядка загрузки,
установка одного мода перенумеровывала бы существующие материалы и ломала все
сохранения разом. Формат данных — чинить поздно почти невозможно, поэтому
правило принято до первой строки кода.

Отвергнутая альтернатива — хеш от строкового id (`мод:материал`): он снимает
необходимость координировать номера, но делает номер непредсказуемым для
человека и требует таблицы разрешения коллизий, то есть меняет ошибку
загрузки на молчаливое переназначение.

[QUESTION Q-48 blocks:stage-6 by:human default:256]
Сколько всего номеров в палитре и как они поделены между ваниллой и модами.
Палитра u16 (ADR-094), то есть делить надо 65 536 номеров, а не 256.

**Валидация свойств при загрузке — обязательна, границы входят в хеш набора
модов.** Вырожденные значения ломают не баланс, а симуляцию: плотность 0 даёт
бесконечную бесплатную породу либо сток вне перечня; твёрдость 0 означает
снятие воксела за тик каждым юнитом, то есть мгновенное насыщение очереди
правок — DoS на симуляцию у всех клиентов lockstep; отрицательный выход
создаёт материю. Границы клампов обязаны входить в хеш: иначе клиенты с
разными версиями клампов разойдутся.

Плотность и прочность любого материала, кроме воздуха, лежат от 1 до
`MAX_DENSITY` и `MAX_STRENGTH`; у воздуха (номер 0) обе нулевые. Замена
материала на ходу проходит ту же проверку. Радиус воронки любого оружия —
от 0 до 128 вокселей, есть у взрыва энергия или нет. Хеш набора
материалов и хеш набора типов берут каждое поле, влияющее на симуляцию,
а хеш материалов — ещё и границы проверки (ADR-429).

Числа симуляции в файлах настроек обязательны: пропущенное поле — ошибка
загрузки, а не значение по умолчанию в коде. Необязательны только
переключатели доставки снаряда (способ, ход, рикошет, накачка), свидетель
полигона и размер кубика газа на экране (ADR-429).

Семантика слияния данных двух модов. Сейчас порядок детерминирован («по графу
зависимостей, при равных — по имени»), но **исход не определён**: два мода,

одного поля.

## Безопасность

Моды из интернета — это чужой код. Luau даёт песочницу и запрет на загрузку
байткода; у Factorio была реальная RCE именно через Lua-байткод, так что это
не теоретическая угроза. WASM-уровень изолирован по построению.

Правило: **никакой мод не получает файловую систему, сеть и процессы.**
Хранение данных мода — через API хоста, в отведённом месте.

## Структура мода

```
my-mod/
├─ mod.ron              имя, версия, зависимости, требуемая версия API
├─ data/                RON: юниты, материалы, оружие — сливается с ванильными
├─ bodies/              составные тела: части, трансформы, соединения, ядро,
│                       масштабный множитель, вместимость контейнера
├─ scripts/
│  ├─ synced/           детерминированная логика
│  └─ unsynced/         UI, оверлеи
└─ assets/              .vox-модели (по одной на часть), текстуры, звуки
```

Описание юнита после ADR-019, ADR-020 и ADR-021 — это не одна `.vox`-модель, а
**набор частей**: корпус, башня, гусеницы; у каждой свой том и трансформ, у
сборки — соединения, позиция ядра, масштабный множитель и вместимость
контейнера, если юнит что-то возит.

Загрузка: ванильный контент из `data/` грузится тем же кодом, что моды.
Порядок применения — по графу зависимостей, детерминированно; при равных
условиях — по имени, чтобы порядок не зависел от файловой системы.

## Правило, которое делает API живым

**Своя игра пишется через тот же API.** Ванильные юниты, материалы и
способности определяются теми же RON-файлами и теми же скриптами, что
доступны модам. Привилегированного пути нет.

Без этого правила получается второсортный API для чужаков и удобный для себя —
и мод-сообщество не появляется. С ним API проверяется на каждой строчке
собственного контента.

## Версионирование

`mod.ron` объявляет требуемую версию API. Ломающее изменение API — минорная
версия проекта и новый ADR (`12-decisions.md`). Моды с несовместимой версией не
грузятся с внятным сообщением, а не падают.

До первого публичного релиза API не стабилен и ломается свободно. После —
ломается только с миграционной запиской.

## Что решается позже

**Хот-релоад synced-скриптов запрещён.** Не «вероятно, только для unsynced» —
именно запрещён: подмена детерминированной логики на живом состоянии ломает
и реплей, и lockstep. Хот-релоад unsynced-скриптов желателен и безопасен.
