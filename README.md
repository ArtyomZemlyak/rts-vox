# rts-vox

RTS, где **всё состоит из вокселей материалов** — мир, постройки и юниты.
Ресурсы добываются копкой и реклеймом обломков. Процедурная генерация карт,
бои на 5000+ юнитов.
Стадия: **работающее ядро симуляции, GPU-рендер и проверяемые демосцены.**

Для сборки требуется Rust 1.95 или новее (минимальная версия закреплённого
Bevy 0.19.1). Все проверки и тесты выполняются в профиле `release`.

Разрабатывается соло с Claude Code, поэтому вся архитектура подчинена одному
требованию: **агент должен уметь проверить себя сам — без человека, без GPU,
из терминала.** Всё остальное вторично.

## Основная карта — полигон

Один танк стреляет по разрушаемой бетонной цели. Снаряд, ударная волна и кратер
рассчитываются на CPU; огонь и дым — в локальном GPU-поле скорости, давления,
температуры, топлива, кислорода и сажи. Газ учитывает оставшуюся геометрию.
Сцена включает лесистый рельеф, PBR-материалы танка, тени, свет взрыва,
плотные клубы дыма, пыль и осколки. Глубина и нормали воксельного мира
включены в общий рендер с контактным затенением, bloom и цветокоррекцией.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\cargo-local.ps1 build --release -p render --bin blast
.\scripts\play-range.cmd
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\capture-range.ps1 -Seconds 14
```

Первый скрипт собирает программу с локальным MSVC, второй открывает карту,
третий записывает итоговый GPU-рендер в MP4 со скоростью 1×.
Для MP4 используется ffmpeg из PATH или `cache/video-tools`.

Для записи ходовых мишеней используйте `capture-range.ps1 -DriveDemo -View target -Seconds 24`.
`-Patrol` выбирает, за какой ходовой мишенью следить, считая с единицы.
`-View` выбирает камеру: `auto`, `overview`, `exposed`, `sheltered`, `gun` или `target`;
`gun` — своя машина, `target` — ходовая мишень раскладки. Ключ имеет приоритет
над `-Close` и над камерой режима; без ключа ракурс выбирает режим, а `auto` —
это отдельная сценарная камера, а не «как было». `sheltered`, `gun` и `target`
требуют раскладки и без неё отклоняются.
`-Move 96,540` отдаёт управляемому танку приказ ехать в точку при старте
(например, в лес — с валкой деревьев); без `-DriveDemo`, иначе демо
перепишет приказ.
Параметры `-Weapon shell -Power 4000` включают фугас мощности 4×;
скорость записи остаётся реальной 1× для любого оружия и ракурса.

Уже собранный полигон открывается двойным щелчком по `scripts/play-range.cmd`.
Из PowerShell в папке `scripts` запустите `.\play-range.cmd`.
Обёртка задаёт `ExecutionPolicy Bypass` только для своего процесса PowerShell;
настройки пользователя и системы остаются прежними.

Для итераций по шейдерам можно перед запуском установить
`$env:RTS_VOX_SHADER_DIR = "$PWD/crates/render/src"`: файлы читаются при старте.
Без этой переменной используются шейдеры, встроенные при сборке.

`--weapon energy` включает энергопушку: заряд излучателя, прямой полёт сгустка,
электрический след и синий разряд с разрушением. Параметры находятся в
`data/energy-cannon.ron`. Общая раскладка полигона сохраняется при смене оружия.

Кнопка «Фугас» включает материальное разрушение: выбитый грунт, бетон и
броня переходят в физические обломки. Их скорость ограничена энергией
выстрела, масса сохраняется после оседания. Энергопушка использует отдельный
режим аннигиляции. Уже выпавшие обломки остаются при смене оружия.

Основная карта для дальнейшей работы — **тот же лесной полигон с танком**:
`.\scripts\play-range.cmd`.
Старый `play-energy.ps1` открывает его же. Начальная расстановка из
`data/range-cover.ron`: прочная слоистая стена, открытый танк, танк за ней
и две ходовые мишени — танк и шагоход на замкнутых маршрутах с подъёмами.
Свою расстановку можно открыть через `.\scripts\play-range.cmd -LayoutPath out/range-layout.ron`.

Карта открывается в живом режиме управления своим танком. **ПКМ по земле —
ехать, ПКМ по юниту — атаковать его до уничтожения или нового приказа**.
Танк, посланный в лес, валит деревья: ствол в пятне корпуса срезается,
крона рассыпается обломками и остаётся материей; шагоход деревья обходит.
ЛКМ выбирает мишень для осмотра. В левой панели есть кнопки оружия, мощности,
паузы, восстановления, остановки танка и мишеней, обзора и перемещения камеры.
«Огонь по точке» включает выбор места попадания мышью. Выбор нового заряда
сохраняет разрушения; занятый выстрел сначала завершается.

«Расстановка» открывает инструменты добавления танков, шагоходов, блоков
и щитов: купол ловит снаряд и луч на своей границе, тратит заряд, падает
от перегрузки и восстанавливается (`data/shield.ron`, ADR-276). Взрыв
оставляет тепло на поверхностях; листва и стволы загораются по порогу
материала и выгорают (`data/heat.ron`, `range-materials.ron`, ADR-277).
Сегменты тел — плиты, звенья ног — бьются в своих кадрах и отваливаются
целиком, когда снят корень под креплением (ADR-278).
«Маршрут / стоянка» переключает выделенную мишень между стоянкой и маршрутом
её типа. Размещать препятствия можно и на ходовой площадке. Сохранение,
загрузка, отмена и поворот блока доступны кнопками. Клавиатура не обязательна.

Дополнительные горячие клавиши: **Enter/R** восстанавливают выбранную
расстановку. **E** возвращает
редактор, **R** восстанавливает/повторяет опыт, **Space** ставит паузу при просмотре.
**F** заряжает следующий выстрел по текущим повреждениям, когда предыдущая волна завершилась.
Старые **W/P** переключают оружие/мощность с восстановлением опыта;
кнопки панели сохраняют повреждения. Башня наводится независимо от движения
корпуса; горизонтальная скорость снаряда не растёт от угла.
`.\scripts\play-range.cmd -AutoFire` сохраняет режим автоматического первого выстрела.

В редакторе: **1** выделение, **2** танк, **3** шагоход, **4** бетонная стена,
**5** стальная стена, **6** земляной блок, **7** точка прицеливания.
**ЛКМ** ставит/выделяет, **ПКМ** переносит выделенное (или отменяет инструмент),
**Delete** удаляет, **Q** поворачивает новый блок на 90°.
Слои исходной стены переносятся/удаляются вместе. Пересечения реальных тел
отклоняются, **Ctrl+Z/Y** отменяет/возвращает изменение (32 шага).
**F6** сохраняет расстановку, **F5** перечитывает её. Выбор точки попадания
включает контактный взрыватель; исходный опыт укрытия использует взрыватель
на плоскости цели для сравнения с убранной стеной.

Колесо приближает, средняя кнопка мыши перемещает камеру, **Home** возвращает
общий план. При просмотре **1/2/3** — общий/открытый/защищённый танк,
**C** — автоматическая камера, **B** — убрать/вернуть укрытие,
**T** — заменить мишени танками/шагоходами. Эти временные сравнения не меняют
сохранённую расстановку. Счётчик в заголовке показывает потерю геометрии, не HP.

Прямая запись итогового рендера без computer use:
`scripts/capture-range.ps1 -OutputDir out/my-range-capture -Seconds 14`.
PNG получают реальные временные метки; пропуски сохраняются удержанием кадра.
Результат — `realtime-1x.mp4`, журнал и CSV. Старый `capture-blast.ps1` оставлен
для покадровой офлайн записи, она не измеряет производительность реального времени.

## Диагностическое поле боя (1 км)

`scripts/play-battlefield.ps1` открывает карту 1×1 км с двумя разнесёнными
базами и небольшими отрядами. Расстановка — `data/battlefield.ron`.
Сборка: `scripts/cargo-local.ps1 build --release -p render --bin play`.
Прямой запуск: `target/release/play.exe --scenario data/battlefield.ron`.

ЛКМ/рамка — выделение, ПКМ — движение или атака, Ctrl+ПКМ — копка.
WASD — камера, Q/E — поворот, R/F — масштаб, Home — вернуться к своим,
Space — пауза. B/N/T и Ctrl+ПКМ — склад/завод/турель; 1/2/3 на заводе —
танк/краулер/шагоход. Esc отменяет выбранную постройку, затем закрывает окно.
Скорость 1×, позы между тиками интерполируются. Земля подгружается около камеры.
Объёмные эффекты энергопушки пока проверяются в основном полигоне выше.

## Как это читать

Документы делятся на два слоя, и путать их не надо.

**Канон — `docs/*.md`.** Что система есть. Всё в изъявительном наклонении,
без вариантов и без истории вопроса. По нему можно начинать писать код.
Минимальный путь: `01` → `02` → `03` → `10` → `11` → `12`. Без `10` не видно
порогов, без `12` — принятых решений, а этап 0 требует и того и другого.

**Анализ — `docs/analysis/*.md`.** Почему именно так: рассмотренные варианты,
замеры, источники, отвергнутые пути, поправки к обоснованиям. Ненормативно.
Читается по надобности, когда нужно понять цену решения или оспорить его.

Нерешённое живёт **в тексте канона**, а не отдельным списком:

```bash
grep -rn '\[QUESTION' docs/
```

Формат пометки и что значат поля — [CLAUDE.md](CLAUDE.md).

## Ключевые решения

| Ось | Решение |
|---|---|
| Язык | Rust |
| Каркас рендера | Bevy 0.19, пин `=0.19.1` |
| Ядро симуляции | отдельный крейт, **не зависит от Bevy**, SoA, fixed-point Q32.32 |
| Детерминизм | обязателен с первого дня; lockstep заложен, сеть — в конце |
| Масштаб боя | цель 5000; сходится ли — решают два замера этапа 0 (мешинг рваного забоя и секторный FIM) |
| Разрушаемость | весь мир; копка и реклейм — экономика; каждый выстрел деформирует геометрию |
| Отделение кусков | каскад из трёх фильтров поверх графа компонент чанков |
| Вода | не воксели: водоём — контейнер с объёмом, уровень производный |
| Освещение | по пикселю маршем луча по битовому объёму; в вершины ничего не пекётся |
| Туман | скрывает и рельеф; навигация и рендер видят мир глазами группы зрения |
| Юниты | воксельные тома с ядром, позиционный урон, copy-on-write шаблоны |
| Масштаб | дискретные масштабы по классам; математика в мировых единицах, не в вокселях |
| Сложные формы | составные тела из томов + косметика в unsynced; мешей в симуляции нет |
| Навигация | граф проходимых вокселей, объёмный (туннели); три слоя — земля, воздух, вода |
| Рендер | гибрид: меши для статического мира, марш луча по томам для юнитов и обломков |
| GPU | только рендер-слой; симуляция остаётся на CPU (ADR-025), бэкенд пинится на Vulkan |
| Экономика | материя сохраняется как величина: контейнеры физичны, содержимое количественно |
| Энергия | не материя и не воксели: поток от разрушения блоков, гладкий визуал |
| Фракции | различаются решением логистической задачи: возит / телепортирует / прорастает |
| Моддинг | данные (RON) + Luau; API определён **на ядре**, не на движке |
| Дистрибуция | open source, десктоп (Windows/Linux) |

Реестр решений — [docs/12-decisions.md](docs/12-decisions.md);
обоснования — [docs/analysis/10-decisions-full.md](docs/analysis/10-decisions-full.md).

## Главный риск, названный явно

Сочетание «Teardown-класс разрушаемость × 5000 юнитов × детерминированный
lockstep» не реализовано ни в одной шипнутой игре. Teardown — камера вблизи,
маленькая сцена, недетерминированная физика. Supreme Commander — сотни юнитов
на армию, heightmap, без разрушаемости геометрии. Здесь всё это одновременно.

Это не значит «нельзя». Это значит, что готовых рецептов на стыке нет и каждый
бюджет производительности надо мерить, а не брать из статей.

И есть два риска серьёзнее производительности. Первый: единственная шипнутая
RTS нашего масштаба, всерьёз рассматривавшая мелкую деформацию рельефа, от неё
**сознательно отказалась** — воронки делают карту непроходимой. Направленная
копка от этого спасает (она увеличивает связность), непреднамеренный шум от
боя — нет, и после ADR-035 он теперь есть. Второй: навигация в копаемом
3D-мире — то, на чём умирает жанр; Dwarf Fortress тому канонический пример,
и ADR-039 выбрал именно дорогой вариант.

См. [docs/01-concept.md](docs/01-concept.md), раздел «Риски»,
[docs/analysis/02-research-notes.md](docs/analysis/02-research-notes.md), раздел 1,
и [docs/analysis/05-mining-and-terrain.md](docs/analysis/05-mining-and-terrain.md).

Материальные попадания работают и в общей игре: танк использует
кинетический снаряд 6 кг / 600 м/с, шагоход — направленное оружие.
Пробоина и частичное повреждение привязаны к месту удара; потеря
двигателя, орудия или сенсора отключает соответствующую возможность.
Отдельная дуэль для проверки: `scripts/play-material-duel.ps1`.
Состояние интеграции и оставшиеся части физики описаны в
[журнале работы по цели](docs/analysis/28-goal-progress.md).
Замеченные в живых проверках проблемы и их судьба — в
[бэклоге проблем](docs/analysis/31-problem-backlog.md).


Обычная игра: заряд танкового снаряда теперь строит волну по прочности
грунта и сохраняет выбитую породу в физических обломках. Осевшие кучи
собираются краулером; учёт материи не зависит от картинки. Режим проверки:
`scripts/play-material-duel.ps1`, общая карта: `scripts/play-battlefield.ps1`.
Волна учитывает корпуса и укрытия; выбитая броня сохраняет цвет, массу
и реклеймимую материю в общем пуле обломков.
Формат сохранения общей партии — 10; загрузчик также читает версии 8 и 9.
Подробности: `docs/15-explosions-and-fields.md`.


`Shift+ПКМ` — двигаться с боем: юнит тормозит на дистанции своего оружия
и продолжает маршрут после потери цели. Красная группа общей карты использует
этот приказ; обычный `ПКМ` сохраняет прямое движение в указанную точку.


Отделение цельной башни: `scripts/play-sections.ps1`. Движущийся танк
получает диагностический разрыв крепления; башня сохраняет форму,
отделку и материю, падает отдельно от корпуса. Рядом стоит целый танк
для сравнения. Испытание работает на 1× через обычный World.tick.
`play --load файл.bin` открывает сохранённую общую партию.

Погибший корпус: `scripts/play-corpses.ps1`. Диагностическое пробитие ядра
оставляет настоящий повреждённый танк с пробоинами, исходной отделкой и
отключённым свечением. Корпус наследует скорость, оседает и остаётся до
реклейма; рядом стоит целая машина. Повтор идёт на 1×.

Проверка повреждённой ходовой: `scripts/play-drive.ps1`. Три параллельных
маршрута сравнивают целый танк, корпус без башни и танк с частично повреждённым
двигателем. Потеря массы меняет разгон и поворот; повреждение двигателя
уменьшает тягу, отказ оставляет выбег с торможением.


Разворот шагоходов: `scripts/play-turn.ps1`. Два бота разворачиваются
в разные стороны и идут к целям. Ноги переставляются и при повороте
на месте; опорные стопы сохраняют мировую точку и направление.


Прямая запись видео без управления рабочим столом:
`scripts/capture-play.ps1 -SavePath out/walker-turn/fixture.bin -Seconds 10`.
Для общей карты — `-ScenarioPath data/battlefield.ron`. MP4 сохраняет реальный
темп 1×, включая пропущенные кадры; рядом лежит CSV с временем и тиками.


Шагающий полигон с ровной дорожкой и выемкой со ступенями:
`scripts/play-terrain.ps1`. Подошва наклоняется по рельефу, перенос
заранее учитывает уступы между точками постановки стопы.

Серия разрушенных рельефов для машин полигона — воронки, вал, поле
воронок, рвы, щебень, террасы, холмы — в восьми направлениях захода для
танка и шагохода, с замером рывка корпуса за тик:

```bash
cargo test --release -p sim-core --test terrains -- --nocapture
```
