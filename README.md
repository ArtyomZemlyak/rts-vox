# rts-vox

RTS, где **всё состоит из вокселей материалов** — мир, постройки и юниты.
Ресурсы добываются копкой и реклеймом обломков. Процедурная генерация карт,
бои на 5000+ юнитов.
Стадия: **технический концепт, кода ещё нет.**

Разрабатывается соло с Claude Code, поэтому вся архитектура подчинена одному
требованию: **агент должен уметь проверить себя сам — без человека, без GPU,
из терминала.** Всё остальное вторично.

## Как это читать

Документы делятся на два слоя, и путать их не надо.

**Канон — `docs/*.md`.** Что система есть. Всё в изъявительном наклонении,
без вариантов и без истории вопроса. По нему можно начинать писать код.
Минимальный путь: `01` → `02` → `03` → `10` → `11` → `12`. Без `10` не видно
порогов, без `12` — принятых решений, а этап 0 требует и того и другого.

**Анализ — `docs/analysis/*.md`.** Почему именно так: рассмотренные варианты,
замеры, источники, отвергнутые пути, поправки к обоснованиям. Ненормативно.
Читается по надобности, когда нужно понять цену решения или оспорить его.

Нерешённое живёт **в тексте канона**, а не отдельным списком:

```bash
grep -rn '\[QUESTION' docs/
```

Формат пометки и что значат поля — [CLAUDE.md](CLAUDE.md).

## Ключевые решения

| Ось | Решение |
|---|---|
| Язык | Rust |
| Каркас рендера | Bevy 0.19, пин `=0.19.1` |
| Ядро симуляции | отдельный крейт, **не зависит от Bevy**, SoA, fixed-point Q32.32 |
| Детерминизм | обязателен с первого дня; lockstep заложен, сеть — в конце |
| Масштаб боя | цель 5000; сходится ли — решают два замера этапа 0 (мешинг рваного забоя и секторный FIM) |
| Разрушаемость | весь мир; копка и реклейм — экономика; каждый выстрел деформирует геометрию |
| Отделение кусков | каскад из трёх фильтров поверх графа компонент чанков |
| Вода | не воксели: водоём — контейнер с объёмом, уровень производный |
| Освещение | по пикселю маршем луча по битовому объёму; в вершины ничего не пекётся |
| Туман | скрывает и рельеф; навигация и рендер видят мир глазами группы зрения |
| Юниты | воксельные тома с ядром, позиционный урон, copy-on-write шаблоны |
| Масштаб | дискретные масштабы по классам; математика в мировых единицах, не в вокселях |
| Сложные формы | составные тела из томов + косметика в unsynced; мешей в симуляции нет |
| Навигация | граф проходимых вокселей, объёмный (туннели); три слоя — земля, воздух, вода |
| Рендер | гибрид: меши для статического мира, марш луча по томам для юнитов и обломков |
| GPU | только рендер-слой; симуляция остаётся на CPU (ADR-025), бэкенд пинится на Vulkan |
| Экономика | материя сохраняется как величина: контейнеры физичны, содержимое количественно |
| Энергия | не материя и не воксели: поток от разрушения блоков, гладкий визуал |
| Фракции | различаются решением логистической задачи: возит / телепортирует / прорастает |
| Моддинг | данные (RON) + Luau; API определён **на ядре**, не на движке |
| Дистрибуция | open source, десктоп (Windows/Linux) |

Реестр решений — [docs/12-decisions.md](docs/12-decisions.md);
обоснования — [docs/analysis/10-decisions-full.md](docs/analysis/10-decisions-full.md).

## Главный риск, названный явно

Сочетание «Teardown-класс разрушаемость × 5000 юнитов × детерминированный
lockstep» не реализовано ни в одной шипнутой игре. Teardown — камера вблизи,
маленькая сцена, недетерминированная физика. Supreme Commander — сотни юнитов
на армию, heightmap, без разрушаемости геометрии. Здесь всё это одновременно.

Это не значит «нельзя». Это значит, что готовых рецептов на стыке нет и каждый
бюджет производительности надо мерить, а не брать из статей.

И есть два риска серьёзнее производительности. Первый: единственная шипнутая
RTS нашего масштаба, всерьёз рассматривавшая мелкую деформацию рельефа, от неё
**сознательно отказалась** — воронки делают карту непроходимой. Направленная
копка от этого спасает (она увеличивает связность), непреднамеренный шум от
боя — нет, и после ADR-035 он теперь есть. Второй: навигация в копаемом
3D-мире — то, на чём умирает жанр; Dwarf Fortress тому канонический пример,
и ADR-039 выбрал именно дорогой вариант.

и [docs/analysis/05-mining-and-terrain.md](docs/analysis/05-mining-and-terrain.md).
